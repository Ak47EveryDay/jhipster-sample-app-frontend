# テスト規約

> **位置づけ**: 単体テスト（Vitest）と E2E テスト（Cypress）の置き場所と書き方を、既存のテストコードと設定から取り出したものである。
> 実行コマンドと前提環境は `開発手順.md` §4、テストに関わる設定は `ビルドと環境設定.md` §2.4、§2.5、§8.5、§8.6 を参照。
> 数値はコミット `bf6b0ad` の実測である（単体テスト 81 ファイル、E2E テスト 13 ファイル）。行数は `wc -l` による。表の「N ファイル」は、特に断りがない限り、「書き方」欄に示した文字列（`provideTranslateService()`、`[NgbActiveModal]` など）を含む `*.spec.ts` の数である。E2E テストの `it` の件数は、監査を除く `cypress/e2e/**/*.cy.ts`（12 ファイル）にある `it(` の数である。

### 3.2 HTTP を `HttpTestingController` で置き換えるテスト（22 ファイル）

実サービスをそのまま使い、HTTP だけを `HttpTestingController` で置き換える。この書き方をするのはサービスの spec 17 本（`*.service.spec.ts`）と、エンティティの一覧画面の spec 5 本である。フォームサービスとリゾルバーの spec は HTTP を使わない。登録・編集画面の spec は HTTP を置き換えず、`vi.spyOn(userService, 'query').mockReturnValue(…)` の形でサービスのメソッドを置き換える。

```ts
// src/app/entities/bank-account/service/bank-account.service.spec.ts（抜粋）
beforeEach(() => {
  TestBed.configureTestingModule({ providers: [provideHttpClientTesting()] });
  service = TestBed.inject(BankAccountService);
  httpMock = TestBed.inject(HttpTestingController);
});

it('should find an element', () => {
  const returnedFromService = { ...requireRestSample };
  const expected = { ...sampleWithRequiredData };

  service.find(123).subscribe(resp => (expectedResult = resp));

  const req = httpMock.expectOne({ method: 'GET' });
  req.flush(returnedFromService);
  expect(expectedResult).toMatchObject(expected);
});

afterEach(() => {
  httpMock.verify();
});
```

- 基本の形は「呼ぶ → `httpMock.expectOne(…)` でリクエストを取り出す → `req.flush(レスポンス)` でレスポンスを返す → 結果を `expect` する」である。
- `afterEach` で `httpMock.verify()` を呼び、未応答のリクエストが残っていないことを確認する（22 ファイル）。
- 日付を持つエンティティは、サンプルの `date` を `toJSON()` で文字列にしたものをレスポンスとして返し、結果を dayjs の日付を持つサンプルと比較することで変換を検証する（`src/app/entities/operation/service/operation.service.spec.ts`）。

### 4.5 監査（`lighthouse.audits.ts`）

- `cy.visit('/')` の後、`cy.lighthouse(customThresholds, desktopConfig)` を実行する。
- しきい値は `performance: 80`、`accessibility: 90`、`seo: 90`、`'best-practices': 90`、`pwa: 0` である。
- 結果の HTML レポートは `cypress/lhreport.html` に出る（`cypress/plugins/index.ts` の `lighthouse` タスク。`.gitignore` の対象）。
- 監査は専用の設定 `cypress-audits.config.ts`（`specPattern: 'cypress/e2e/**/*.audits.ts'`）からだけ実行する。

## 5. E2E テスト向けの lint

`cypress/**/*.ts` には `eslint.config.ts` の専用ブロックが適用される。

- `tseslint.configs.recommendedTypeChecked` と `cypress.configs.recommended` を適用する。
- 型情報は `cypress/tsconfig.json` から取る。
- `no-explicit-any` と `no-unsafe-*`、`unbound-method` は off にしている。

## 6. 注意点

1. **`data-cy` は E2E テストとの契約である**。値を変えたり削除したりするときは `cypress/support/commands.ts`、`cypress/support/entity.ts` と `cypress/e2e/**/*.cy.ts` を合わせて修正する。
2. **一覧画面の spec では `TestBed.tick()` が要る**。呼ばないと `effect` が走らず、HTTP リクエストも発生しない。
3. **`httpMock.verify()` を `afterEach` に置く**。未応答のリクエストが残ったままテストが通るのを防ぐ。
4. **`<fa-icon>` を含む画面の spec ではアイコンの登録が要る**。アプリの起動時に行っている `FaIconLibrary.addIcons` はテストでは実行されないため、spec 内で使うアイコンを登録する。
5. **E2E テストは CI では動かない**。`.github/workflows/github-actions.yml` は `npm test`（lint と単体テスト）と `npm run build` だけを実行し、`CYPRESS_INSTALL_BINARY: '0'` で Cypress 本体のダウンロードも省く。
6. **カバレッジのしきい値は設定されていない**。`coverage/lcov.info` と `coverage/TESTS-results-sonar-vitest.xml` が出力されるだけである（`angular.json` の `architect.test`、`sonar-project.properties`）。
7. **E2E の `cy.login` は sessionStorage を使う**。ログイン画面を経由しないため、「ログイン画面の操作」は `cypress/e2e/account/login-page.cy.ts` だけが検証している。
