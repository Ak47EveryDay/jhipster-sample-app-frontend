## B. 実装中（コードの書き方）

| No | 確認項目 | 判定基準 | 依拠 |
|---|---|---|---|
| B-1 | ファイル名 | kebab-case。種別の接尾辞（`.service.ts`、`.model.ts`、`.routes.ts` / `.route.ts`、`-form.service.ts`、`-routing-resolve.service.ts`）を正しく付ける | 規則 F-01 〜 F-19 |
| B-2 | クラス名とセレクター | クラス名は PascalCase で `Component` を付けない。セレクターは要素型、接頭辞 `jhi-`、kebab-case | 規則 C-01、C-03 |
| B-3 | サービス | `@Service()` を付ける。`@Injectable()` は使わない。エンティティは `<Entity>sService`（一覧）と `<Entity>Service`（CRUD）の 2 段構え | 規則 C-12 〜 C-17 |
| B-4 | 依存の注入 | `private readonly <名前> = inject(<型>);`（エンティティ配下は `protected`。既存コードは `protected readonly` と `readonly` を付けない `protected` が混在しており、新規には `protected readonly` を推奨）。コンストラクター注入は使わない | 規則 T-01、`プロジェクト構成とレイヤー別開発ガイド.md` §5.6 |
| B-5 | メンバーの並び | static フィールド → インスタンス フィールド → `constructor` → static メソッド → インスタンス メソッド。やむを得ない箇所だけ抑制コメントを付ける | 規則 T-02、T-03 |
| B-6 | API URL | 必ず `${serverApiUrl}` から始める。オリジンをハードコードしない。識別子は `encodeURIComponent(…)` で囲む | `プロジェクト構成とレイヤー別開発ガイド.md` §5.2 |
| B-7 | 認証状態と保存 | ログイン状態は `AccountService.account` と `identity()`、トークン・遷移先 URL・言語の保存は `StateStorageService` を使う。画面から `localStorage` / `sessionStorage` を直接操作しない。`GET api/account` を画面から直接呼ばない | `共通部品利用ガイド.md` §1、§8 |
| B-8 | エラー表示 | 画面に `<jhi-alert-error />` を置き、`error` コールバックに表示処理を書かない | `主要処理フロー.md` §4.2 |
| B-9 | 成功通知 | バックエンドがレスポンスヘッダーで返す翻訳キーを表示する場合は `<jhi-alert />` を置く。画面で文言を組み立てない | `主要処理フロー.md` §4.1 |
| B-10 | 文言 | テンプレートの固定文言は `jhiTranslate` で置く。キーが `src/i18n/en/*.json` に存在する。属性値は `{{ 'キー' \| translate }}` | 規則 M-06 〜 M-08 |
| B-11 | テンプレートの構文 | `@if` / `@for` / `@let` を使う。`*ngIf`、`*ngFor`、`[(ngModel)]`、`ngClass` を使わない（管理画面の絞り込み欄にある `[ngModel]` と `(ngModelChange)` の併記は既存の例外。`ネーミングルールとコーディング規約.md` §9）。`@for` には `track` を付ける | 規則 M-01 〜 M-05 |
| B-12 | フォーム | Reactive Forms。`FormGroup` の生成はフォームサービスに置く。主キーのコントロールは `disabled: true` | `プロジェクト構成とレイヤー別開発ガイド.md` §5.3 |
| B-13 | 日付 | モデルは `dayjs.Dayjs \| null`。REST で受け取る値は文字列。フォームでは `DATE_TIME_FORMAT`（`YYYY-MM-DDTHH:mm`）の文字列で持つ | `プロジェクト構成とレイヤー別開発ガイド.md` §5.1、§5.2 |
| B-14 | 状態 | シグナルで持つ。真偽値は `is…`、コレクションは複数形。書き換えを許さないものは `asReadonly()` か `computed()` | 規則 T-16 〜 T-21 |
| B-15 | 購読の後始末 | 一時的な購読は `finalize` か `takeUntilDestroyed`。コンポーネントが持つ `Subscription` は `ngOnDestroy` で解除する | 規則 T-26 〜 T-29 |
| B-16 | `data-cy` | 操作や参照の対象に camelCase で付ける。エンティティ画面は共通名（`entityCreateButton` など）と `<Entity>Heading` 系を使う | 規則 M-09 〜 M-11 |
| B-17 | ルート | 遅延読み込みは `loadComponent` / `loadChildren`。ログイン必須は `canActivate: [userRouteAccessService]`。権限は `data.authorities`。`resolve` のキーは画面の `input` 名と同じ。`title` は翻訳キー | 規則 R-02 〜 R-06 |
| B-18 | import の書き分け | エイリアスのあるモジュールはエイリアス。同一の機能単位の中は相対パス。別の機能単位は `app/` で始まる絶対パス | `プロジェクト構成とレイヤー別開発ガイド.md` §3 |
| B-19 | 比較と null 系 | `===` / `!==`、`??`、`?.` を使う。型から見て常に真（偽）の条件を書かない | 規則 T-06 〜 T-08 |
| B-20 | `console` と禁止構文 | `console.log`、`eval`、bitwise 演算を書かない。`parseInt` には基数を付ける | 規則 T-10、T-14 |
| B-21 | スタイル | Bootstrap のクラスを優先する。独自クラスは `jh-` で始める。コンポーネントの SCSS は 4kb 以内 | 規則 M-18、`ビルドと環境設定.md` §2.2 |
| B-22 | アイコン | `<fa-icon icon="…">` の名前が `fontAwesomeIcons` に登録されている | 規則 M-15 |
| B-23 | テンプレートの参照 | `templateUrl` と `styleUrl` は `./` で始める。テンプレートと同じ基本名にする | 規則 F-02、F-04 |

## C. 実装後（テストと品質）

| No | 確認項目 | 判定基準 | 依拠 |
|---|---|---|---|
| C-1 | 単体テストの有無 | エンティティは 7 本。単独画面は `<名前>.spec.ts` と、サービスを作ったなら `<名前>.service.spec.ts` を同じディレクトリに置く（既存コードにテストがないファイルの区分は `テスト規約.md` §2.3） | `テスト規約.md` §2 |
| C-2 | 単体テストの書き方 | `vitest` から明示的に import。`it` は `should …`。`// GIVEN` / `// WHEN` / `// THEN`。モックは `vi.fn` / `vi.spyOn`。HTTP は `HttpTestingController` と `afterEach` の `httpMock.verify()` | `テスト規約.md` §3.1 〜 §3.2 |
| C-3 | 一覧画面のテスト | `TestBed.tick()` を呼び、`req.flush(…)` でレスポンスを返し、`await vi.runAllTimersAsync()` でタイマーを進める。`afterEach` で `TestBed.resetTestingModule()` | `テスト規約.md` §3.3 |
| C-4 | リゾルバーのテスト | `TestBed.runInInjectionContext` の中で呼ぶ。ID 無し、404、その他のエラーの 3 通りを検証 | `テスト規約.md` §3.4 |
| C-5 | スキップと抑制 | `it.skip`、`describe.skip` を残さない。spec に `eslint-disable` を書かない | `テスト規約.md` §3.1 |
| C-6 | lint | `npm run lint` がエラー 0 で通る | `ビルドと環境設定.md` §8.1 |
| C-7 | 整形 | `npm run prettier:check` が通る | `ビルドと環境設定.md` §8.2 |
| C-8 | 単体テスト | `npm test` が通る（lint を含む） | `開発手順.md` §4.2 |
| C-9 | ビルド | `npm run build` が通り、ビルド予算のエラーが出ない | `開発手順.md` §3.3 |
| C-10 | E2E テスト | 画面や `data-cy` を変えた場合は `npm run e2e:headless` が通る | `テスト規約.md` §4 |
| C-11 | 手動確認 | `npm start` で `admin/admin` と `user/user` の両方でログインし、対象画面の表示・登録・編集・削除を確認する。未ログインで `/login` へ、権限不足で `/accessdenied` へ遷移することを確認する | `主要処理フロー.md` §2.5 |
| C-12 | lint の抑制コメント | 本体の `eslint-disable` は既存の 14 件（`member-ordering` 12 件、`no-console` 1 件、`ban-ts-comment` 1 件）である。新たに `member-ordering` の抑制を置く場合は、規則 T-03 の形（注入より後のフィールド宣言）に当てはまるかを確認する | `ネーミングルールとコーディング規約.md` §8 |
