## 2. 全体構成

### 2.1 外部結合（ブラウザー・開発サーバー・バックエンド）

```
┌─ ブラウザー ─────────────────────────────────────────────────────────┐
│  http://localhost:9060                                               │
│    SPA ルーティング（/login、/bank-account、/admin/metrics など）     │
└──────────────┬──────────────────────────────┬────────────────────────┘
               │ /api/**  /management/**      │ 上記以外の全パス
               │ /v3/api-docs  /h2-console    │
               ▼                              ▼
┌─ 開発サーバー（ng serve）──────────────┐   ┌─ Angular アプリ ───────────┐
│  proxy.config.mjs                      │   │  index.html を返す        │
│  → http://127.0.0.1:8080 へ転送        │   └───────────────────────────┘
└──────────────┬─────────────────────────┘
               ▼
┌─ バックエンド http://localhost:8080（別リポジトリ）──────────────────┐
│  /api/**         業務 API・認証                                     │
│  /management/**  運用 API（health、info、loggers、metrics など）     │
│  /v3/api-docs    OpenAPI 定義（Swagger UI が参照）                   │
│  /h2-console     H2 コンソール（開発環境のみ、navbar からリンク）     │
└──────────────────────────────────────────────────────────────────────┘
```

- 開発時、ブラウザーが見るのは `http://localhost:9060` のみである。`/api`、`/management`、`/v3/api-docs`、`/h2-console` で始まるリクエストは開発サーバーが `http://127.0.0.1:8080` へ転送する（`proxy.config.mjs`、`angular.json` の `architect.serve.options.port`）。
- 本番ビルドは静的ファイルの集合である。配置先サーバーは `/api/**`、`/management/**`、`/v3/api-docs/**` をバックエンドへ到達させ、拡張子のないパス（例: `/bank-account/edit/1`）には `index.html` を返す必要がある（`README.md` の「Building」）。
- バックエンドを別オリジンに置く場合は、ビルド時の環境変数 `SERVER_API_URL` で起点を指定する。末尾の `/` は自動で補われる（`build-plugins/define-esbuild.ts` の `withTrailingSlash`）。この場合バックエンド側で CORS の許可が要る（`README.md`）。

### 2.2 フロントエンド内部の骨格

```
src/index.html
  └ src/main.ts → src/bootstrap.ts           bootstrapApplication(App, appConfig)
      └ src/app/app.ts            <jhi-app>   ルートコンポーネント（アイコン・ロケール・日付ピッカーの初期設定）
          └ src/app/layouts/main/main.ts  <jhi-main>
              ├ <jhi-page-ribbon>            開発環境リボン（src/app/layouts/profiles/page-ribbon.ts）
              ├ <router-outlet name="navbar"> → src/app/layouts/navbar/navbar.ts
              └ <router-outlet>              以下の画面本体
                    ├ src/app/home/        /（ホーム）
                    ├ src/app/login/       /login
                    ├ src/app/account/     /account/**（登録・有効化・パスワード・設定）
                    ├ src/app/admin/       /admin/**（運用管理）
                    ├ src/app/entities/    /bank-account /label /operation /user-management /authority
                    └ src/app/layouts/error/  /error /accessdenied /404
```

- アプリ全体のプロバイダー（ルーター、`HttpClient` とインターセプター、翻訳、タイトル戦略など）は `src/app/app.config.ts` の `appConfig` に集約されている。
- `NgModule` は存在せず、全コンポーネント・ディレクティブ・パイプが standalone である（`src/app` 配下に `@NgModule` の定義はない）。
- `zone.js` は依存に含まれておらず、`appConfig` に変更検知方式の指定（`provideZoneChangeDetection` など）もない。変更検知はシグナル駆動で行われる（`package.json`、`src/app/app.config.ts`）。

ルートの仕組みに関する補足:

- **ログインと権限** はガード `userRouteAccessService`（`src/app/core/auth/user-route-access.service.ts`）が判定する。ログインが必要なルートは `canActivate: [userRouteAccessService]` を持ち、権限が必要なルートはさらに `data.authorities` を持つ。`/admin/**` は親ルート（`src/app/app.routes.ts` の `path: 'admin'`）で `data: { authorities: [Authority.ADMIN] }` を指定し、子ルート（`src/app/admin/admin.routes.ts`）には個別の指定がない。
- **ユーザー管理と権限管理は `/admin` 配下ではない**。URL は `/user-management`、`/authority` であり、ルートは `src/app/entities/entity.routes.ts` で定義される。一方で navbar のメニューは管理メニュー（Administration）側に置かれている（`src/app/layouts/navbar/navbar.html`）。
- **タイトル** は各ルートの `title` に翻訳キーを指定する。`AppPageTitleStrategy`（`src/app/app-page-title-strategy.ts`）が翻訳してブラウザータイトルへ設定し、未指定の場合は `global.title` を使う。
- **削除はルートを持たない**。一覧画面から `NgbModal` で削除ダイアログ（`src/app/entities/**/delete/*-delete-dialog.ts`）を開く。
- **ナビゲーションエラー** は `appConfig` の `withNavigationErrorHandler` で受け、HTTP ステータスに応じて `/accessdenied`（403）、`/404`（404）、`/login`（401）、`/error`（その他）へ遷移させる（`src/app/app.config.ts`）。

| `api/activate?key=` | GET | `ActivateService.get`（`src/app/account/activate/activate.service.ts`） | 有効化 |

読み取り方の注意:

- 一覧取得（複数形クラス `~sService`）は `httpResource` で、単票の CRUD（単数形クラス）は `Observable` で扱う。二段構えの書式と各メンバーの役割は `プロジェクト構成とレイヤー別開発ガイド.md` §5.2 を参照。
- パスの識別子はエンティティごとに異なる。`bank-accounts`、`labels`、`operations`、`users` は数値 `id`、`admin/users` は文字列 `login`、`authorities` は文字列 `name` である。
- 認証トークンは `Authorization: Bearer {token}` ヘッダーで送る（`src/app/core/interceptor/auth.interceptor.ts`）。Swagger UI の静的ページだけはインターセプターを通らないため、ページ内のスクリプトがストレージキー `jhi-authenticationToken` を直接読んで同じヘッダーを組み立てている（`src/swagger-ui/index.html`）。

## 6. 動作環境の要点

1. **起動順序**: バックエンドを先に起動する（`http://localhost:8080`）。その後 `npm install`、`npm start` で開発サーバーが `http://localhost:9060` で立つ（`README.md` の「Development」）。
2. **ログインアカウント**: `admin/admin`（管理者）、`user/user`（一般ユーザー）（`README.md`）。E2E テストも同じ値を `cypress.config.ts` の `expose` に持つ。
3. **API の起点**: 開発時は `SERVER_API_URL` が空文字であり、同一オリジンへの相対パスになる（`angular.json` の `define`、`build-plugins/define-esbuild.ts`）。
4. **プロキシの転送先**: `proxy.config.mjs` の `backendHost`（`127.0.0.1`）と `backendPort`（`8080`）は固定値である。`package.json` の `config.backend_port`（`8080`）は `ci:server:await` スクリプトの待ち合わせにだけ使われ、プロキシとは別設定である。
5. **CI**: GitHub Actions（`.github/workflows/github-actions.yml`）は push と pull request で `npm ci`、`npm test`（lint を含む）、`npm run build` を実行する。E2E テストは CI では動かない（`CYPRESS_INSTALL_BINARY: '0'`）。
6. **Service Worker**: 設定ファイル `ngsw-config.json` は存在するが、`appConfig` で `provideServiceWorker('ngsw-worker.js', { enabled: false })` と無効化されている。
7. **言語**: `LANGUAGES` は `'en'` のみであるため、navbar の言語メニュー（`@if (languages.length > 1)`）は表示されない（`src/app/layouts/navbar/navbar.html`）。
8. **devcontainer**: `.devcontainer/` は Java イメージを前提とした内容であり、`forwardPorts` は `[4200, 3001, 9000, 8080]` である。開発サーバーのポート `9060` は含まれていない（`.devcontainer/devcontainer.json`）。

## 7. JHipster 生成物であることに起因する特性

- **再生成はできない**。`generator-jhipster` は依存から外れており、JHipster による再生成は不可能である（`README.md` の「What changed in the split」）。既存コードの修正は手作業で行う。
- **`jhipster-needle-*` コメント** はジェネレーターの挿入位置を示すマーカーであり、`src/app` 配下の 7 ファイル 10 箇所に残っている（`src/app/entities/entity.routes.ts`、`src/app/admin/admin.routes.ts`、`src/app/layouts/navbar/navbar.html`、`src/app/config/language.constants.ts`、`src/app/config/dayjs.ts`、`src/app/config/font-awesome-icons.ts`、`src/app/shared/language/find-language-from-key.pipe.ts`）。既存の項目はいずれもマーカーより前に並んでいる。
- **使われていない共通部品が残っている**。`shared/filter`、`DataUtils`、`DurationPipe` などは本体から参照がない（`共通部品利用ガイド.md` の「未使用部品」を参照）。
- **対応する画面がない翻訳キーが残っている**。例えば `src/i18n/en/sessions.json` のキー、および `src/i18n/en/global.json` の `global.menu.admin.tracker` は、該当するルート・画面が存在しない。
- **権限の指定方法が混在している**。`src/app/app.routes.ts` は列挙型 `Authority.ADMIN` を使い、`src/app/entities/admin/**/*.routes.ts` と `src/app/layouts/navbar/navbar.html` は文字列リテラル `'ROLE_ADMIN'` を直接書く（`src/app/shared/jhipster/constants.ts`）。
