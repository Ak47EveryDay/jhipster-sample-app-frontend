## 4. ビルド時定数と esbuild プラグイン（`build-plugins/`）

### 4.1 `define-esbuild.ts`

esbuild の `define` で、コード中の識別子をビルド時の文字列へ置き換える。

| 定数 | 由来 | 既定値 | 使われ方 |
|---|---|---|---|
| `SERVER_API_URL` | 環境変数 `SERVER_API_URL` | `''`（空文字 → 同一オリジンへの相対パス） | `src/app/config/endpoint.constants.ts` の `serverApiUrl` を通じて、すべての API URL の先頭に付く |
| `__VERSION__` | 環境変数 `APP_VERSION` | `'unknown'` | `src/environments/environment.ts` の `VERSION`。navbar に `v…` の形で表示される |

- `SERVER_API_URL` は空文字でないとき、末尾が `/` でなければ補われる（`withTrailingSlash`）。サービスが `${serverApiUrl}api/…` と組み立てるためである。
- `angular.json` の `define` より後に `build.initialOptions.define` へ代入するため、プラグインの値が優先される。
- バックエンドを別オリジンにする場合は `README.md` の「Building」のとおりビルド時に `SERVER_API_URL` を指定し、バックエンド側で CORS を許可する。
- このプラグインはビルドの終了時（`onEnd`）に、`swagger-ui-dist` と `axios` の配布物（`swagger-ui-bundle.js`、`swagger-ui-standalone-preset.js`、`axios.min.js`、CSS と PNG）を出力先の `swagger-ui/` へコピーする。`src/swagger-ui/index.html` はアセットとしてコピーされ、これらのファイルを参照する。

### 4.2 `i18n-esbuild.ts`

翻訳ファイルを 1 つの仮想モジュールにまとめる。

- `prepareLanguage(language)` は `src/i18n/<language>/*.json` をすべて読み、`deepmerge` で 1 つのオブジェクトに結合する。
- `import('i18n/en.json')` のような `i18n/` で始まる import をこのプラグインが受け（`onResolve` の `filter: /^i18n\//`）、結合結果の JSON を返す。
- 呼び出し元は `src/i18n/index.ts` の `loadLocale` である。流れは `主要処理フロー.md` §6.1 を参照。
- `I18N_HASH`（`src/i18n` 配下のディレクトリのハッシュ、md5）も `define` に登録される。ただし `src/app` からは参照されていない（宣言は `src/declarations.d.ts` のみ）。

### 4.3 単体テストでの翻訳の解決（`vitest-base.config.ts`）

Vitest は esbuild プラグインを通らないため、`jhipster:i18n` という Vitest プラグインが同じ役割を担う。`i18n/<lang>.json` を仮想 ID（`\0i18n/<lang>`）へ解決し、`prepareLanguage(language)` の結果を `export default {…}` として返す。

## 6. 開発サーバーとプロキシ

`proxy.config.mjs`:

```js
const backendHost = '127.0.0.1';
const backendPort = 8080;

export default {
  '^/(api|management|v3/api-docs|h2-console)': {
    target: `http://${backendHost}:${backendPort}`,
    xfwd: true,
  },
};
```

- `angular.json` の `architect.serve.options.proxyConfig` がこのファイルを指定する。パスの先頭が `api`、`management`、`v3/api-docs`、`h2-console` のいずれかのリクエストだけを転送する。
- `xfwd: true` により、転送時に `X-Forwarded-*` ヘッダーを付ける。
- 転送先の変更は `backendHost` と `backendPort` の 2 つの固定値を直すことになる。バックエンドのポートを変えた場合は、`package.json` の `config.backend_port`（E2E の待ち合わせ用）も同じ値にする。

改行は LF、文字コードは UTF-8、行末の空白を除く、ファイル末尾に改行を置く、インデントは半角空白 2 つ。Markdown は行末の空白を保持する。

### 8.4 Git フック（`.husky/pre-commit`、`.lintstagedrc.cjs`）

- `npm install` 時の `prepare` スクリプト（`husky`）がフックを有効化する。git 管理下にあるフックのファイルは `.husky/pre-commit` の 1 つである。
- `pre-commit` は `lint-staged` を実行する。`lint-staged` が見つからなければ `npm install` を実行してから再試行する。
- `lint-staged` の対象はステージ済みのファイルのうち、§1 の Prettier と同じ glob に一致するもので、実行内容は `prettier --write` である。
- コミット時に ESLint や単体テストは走らない。ESLint は `npm test` の `pretest` で、または `npm run lint` で実行する。

| `ngsw-config.json` | Service Worker の設定。`appConfig` で Service Worker は無効化されているため現状は使われない |

- コンポーネント固有のスタイルは各コンポーネントの `styleUrl` で読み込む SCSS に書く。Bootstrap の変数を使う場合は、既存の `navbar.scss` と `docs.scss` が `@import 'bootstrap/scss/functions';` と `@import 'bootstrap/scss/variables';` を先に読み込んでいる形に合わせる。
- コンポーネントのスタイルはビルド予算 `anyComponentStyle`（警告 2kb、エラー 4kb、§2.2）の対象になる。

## 10. 既知の注意点

1. **`.devcontainer/` はモノリス時代の設定のまま残っている**。Java のイメージを前提とし、`forwardPorts` は `[4200, 3001, 9000, 8080]` である。開発サーバーのポート `9060` は含まれていない（`.devcontainer/devcontainer.json`）。
2. **プロキシの転送先はハードコード** である（`proxy.config.mjs`）。バックエンドの接続先を変えるときは §6 の説明に従う。
3. **`I18N_HASH` は定義だけ** であり、アプリのコードからは使われていない（§4.2）。
4. **`docs/` は Prettier と lint-staged の対象外** である（§1、§8.4）。
5. **`ng e2e` は使われていない**。E2E は npm スクリプトから `cypress` コマンドを直接呼ぶ（§2.5）。
6. **`vitest-base.config.ts` にはカバレッジのしきい値がない**。`coverage.reportsDirectory: 'coverage'` だけが指定されている。
