# 開発手順

> **位置づけ**: 環境の準備から日常的な操作、新規に画面やサービスを足すときの手順までを順に並べたものである。
> 各手順で「見本」として挙げる既存コードはすべて実在し、同じ形で書けばよいようになっている。
> コードの書き方の規則は `プロジェクト構成とレイヤー別開発ガイド.md` と `ネーミングルールとコーディング規約.md`、設定の意味は `ビルドと環境設定.md`、テストの書き方は `テスト規約.md` を参照。
> コマンドは `package.json`、`README.md`、`.github/workflows/github-actions.yml` に基づく（コミット `bf6b0ad`）。

---

## 1. 全体の流れ

```
環境準備（§2）
   └ 開発サーバーを起動（§3.1）
        └ 開発
             ├ こまめに: npm run lint ／ npm run prettier:format ／ npm test（§4）
             ├ 新規開発: 画面とルート（§5）／ サービスとモデル（§5.3）／ 定数・翻訳・アイコン（§5.4）
             └ E2E テスト（§4.3）
   ┗ 提出前: npm test → npm run build（§4、§3.3）→ 開発チェックリスト.md
```

| 目的 | コマンド | 出典 |
|---|---|---|
| 開発サーバーの起動 | `npm start` | `package.json` の `scripts.start` |
| lint | `npm run lint` | 同 `scripts.lint` |
| 整形の確認と適用 | `npm run prettier:check`、`npm run prettier:format` | 同 `scripts.prettier:*` |
| 単体テスト | `npm test` | 同 `scripts.test` |
| E2E テスト | `npm run e2e:headless` | 同 `scripts.e2e:headless` |
| 本番ビルド | `npm run build` | 同 `scripts.build` |

## 2. 環境準備

1. **Node.js を確認する**。24.21.0 以上が必要である（`README.md` の「Requirements」、`package.json` の `engines.node`）。
2. **バックエンドを先に起動する**。バックエンドは `http://localhost:8080` で待ち受ける（`README.md` の「Development」）。フロントエンド単体ではログインもデータ取得もできない。
3. **依存をインストールする**。

   ```bash
   npm install
   ```

   このとき `prepare` スクリプト（`husky`）が走り、コミット時のフック（`prettier --write`）が有効になる（`package.json`、`.husky/pre-commit`）。

4. **devcontainer を使う場合の注意**。`.devcontainer/devcontainer.json` の `forwardPorts` は `[4200, 3001, 9000, 8080]` であり、開発サーバーのポート `9060` は含まれていない。手動で転送を追加する必要がある。

## 3. 起動とビルド

### 3.1 開発サーバー

```bash
npm start
```

- `http://localhost:9060` でアプリが立ち上がり、ブラウザーが自動で開く（`angular.json` の `architect.serve.options`）。
- ホットリロード（HMR）が有効である（`ng serve --hmr`）。
- `/api`、`/management`、`/v3/api-docs`、`/h2-console` へのリクエストは `http://127.0.0.1:8080` へ転送される（`proxy.config.mjs`）。
- ログインは `admin/admin`（管理者）または `user/user`（一般ユーザー）（`README.md`）。

ページを開くと「An error has occurred」が出る場合は、`src/index.html` に書かれている 3 つの原因（開発サーバー未起動、`npm install` のネットワークエラー、Node.js のバージョン不足）を順に確認する。

### 3.2 ファイル監視ビルド

開発サーバーを使わずにビルドだけを繰り返すときは `npm run watch` を使う（`ng build --watch --configuration development`）。

### 3.3 本番ビルド

```bash
npm run build
```

- 成果物は `dist/jhipster-sample-app-frontend/` に出る。任意の静的ファイルサーバーで配置できる（`README.md` の「Building」）。
- 配置先のサーバーには 2 つの要件がある（同所）。
  1. `/api/**`、`/management/**`、`/v3/api-docs/**` をバックエンドへ到達させる。リバースプロキシで転送するか、ビルド時に `SERVER_API_URL=https://<バックエンドのホスト>/` を指定してブラウザーから直接呼ぶ（この場合はバックエンド側で CORS を許可する）。
  2. 拡張子のないパス（例: `/bank-account/edit/1`）には `index.html` を返す。これがないと、直接 URL を開いたときや再読み込みで 404 になる。
- 本番構成にはビルド予算がある。初期バンドルは警告 500kb・エラー 1mb、コンポーネント 1 つあたりのスタイルは警告 2kb・エラー 4kb である（`angular.json` の `budgets`）。

## 4. テスト・lint・整形

### 4.1 lint と整形

```bash
npm run lint            # ESLint
npm run lint:fix        # 自動修正付き
npm run prettier:check  # 整形の確認
npm run prettier:format # 整形を適用
```

- 整形の対象はルート直下と `build-plugins/`、`src/`、`cypress/` である（`package.json` の `prettier:*` スクリプトの glob）。`docs/` は対象外である。
- コミット時にはステージ済みファイルへ `prettier --write` だけが走る。ESLint は走らない（`.lintstagedrc.cjs`）。

### 4.2 単体テスト

```bash
npm test            # まず lint（pretest）、続けて単体テストとカバレッジ
npm run test:watch  # 監視モード
```

- `npm test` は lint でエラーがあると単体テストを実行しない（`pretest` の仕組み）。
- カバレッジは `coverage/lcov.info` と `coverage/TESTS-results-sonar-vitest.xml` に出る。しきい値の設定はない。

### 4.3 E2E テストと監査

E2E テストには、Chrome、開発サーバー、バックエンドの 3 つが必要である（`README.md` の「Testing」）。

```bash
# 端末 1
npm start
# 端末 2（npm start の完了後）
npm run e2e:headless
```

- `e2e:headless` は `ci:server:await` でバックエンドの `/management/health` が応答するのを待ってから、`cypress run --e2e --browser chrome` を実行する。
- 対話的に確認するときは `npm run cypress`（`cypress open --e2e`）を使う。
- Lighthouse による監査だけを実行するときは `npm run e2e:audits`、対話的には `npm run cypress:audits` を使う（`cypress-audits.config.ts`）。
- CI は単体テストとビルドだけを実行し、E2E テストは実行しない（`.github/workflows/github-actions.yml`）。

## 5. 新規に開発する

### 5.1 エンティティの一式を追加する

バックエンドに `/api/<複数形>` の REST API（一覧取得、1 件取得、登録、更新、削除）があることを前提とする。エンティティ名を `foo` とするとき、作るファイルと進め方は次のとおりである。各ファイルの全文の形は `プロジェクト構成とレイヤー別開発ガイド.md` §5 にある。

`ng generate component` が作る `<名前>.component.ts` という命名は、本リポジトリの規約（接尾辞を付けない）と合わない。既存のエンティティのディレクトリを複製して作るのが確実である。

| 手順 | 作成するファイル | 見本 | 要点 |
|---|---|---|---|
| 1 | `src/app/entities/foo/foo.model.ts` | `src/app/entities/bank-account/bank-account.model.ts` | `interface IFoo` と `type NewFoo = Omit<IFoo, 'id'> & { id: null }` |
| 2 | `src/app/entities/foo/foo.test-samples.ts` | `src/app/entities/bank-account/bank-account.test-samples.ts` | `sampleWithRequiredData`、`sampleWithPartialData`、`sampleWithFullData`、`sampleWithNewData` の 4 定数を `Object.freeze` して export |
| 3 | `src/app/entities/foo/service/foo.service.ts` | `src/app/entities/bank-account/service/bank-account.service.ts` | `@Service()` の `FoosService`（`fooParams`、`fooResource`、`foos`、`resourceUrl`）と、それを継承する `FooService`（CRUD） |
| 4 | `src/app/entities/foo/route/foo-routing-resolve.service.ts` | `src/app/entities/bank-account/route/bank-account-routing-resolve.service.ts` | default export のリゾルバー関数 |
| 5 | `src/app/entities/foo/list/foo.ts`、`foo.html` | `src/app/entities/bank-account/list/` | 一覧画面。件数が多い場合は `src/app/entities/operation/list/`（無限スクロール）か `src/app/entities/admin/user-management/list/`（ページング）を参考にする |
| 6 | `src/app/entities/foo/detail/foo-detail.ts`、`foo-detail.html` | `src/app/entities/bank-account/detail/` | `readonly foo = input<IFoo \| null>(null);` |
| 7 | `src/app/entities/foo/update/foo-update.ts`、`foo-update.html`、`foo-form.service.ts` | `src/app/entities/bank-account/update/` | 登録と編集を兼ねる画面と、`FormGroup` を作る `FooFormService` |
| 8 | `src/app/entities/foo/delete/foo-delete-dialog.ts`、`foo-delete-dialog.html` | `src/app/entities/bank-account/delete/` | セレクターを持たない削除ダイアログ |
| 9 | `src/app/entities/foo/foo.routes.ts` | `src/app/entities/bank-account/bank-account.routes.ts` | `''`、`:id/view`、`new`、`:id/edit` の 4 ルート |
| 10 | `src/i18n/en/foo.json` | `src/i18n/en/bankAccount.json` | 名前空間は `jhipsterSampleApplicationApp.foo` |

続けて、既存ファイルへの登録を行う。

| 登録先 | 修正内容 | 見本となる記述 |
|---|---|---|
| `src/app/entities/entity.routes.ts` | `{ path: 'foo', title: '<翻訳キー>', loadChildren: () => import('./foo/foo.routes') }` を配列の末尾（`jhipster-needle-add-entity-route` のコメントの前）に追加 | `path: 'bank-account'` の項目 |
| `src/app/layouts/navbar/navbar.html` | エンティティメニューに `<li>` を追加 | `global.menu.entities.bankAccount` の項目 |
| `src/i18n/en/global.json` | `global.menu.entities.foo` を追加 | `global.menu.entities.bankAccount` |
| `src/app/config/font-awesome-icons.ts` | 新しいアイコンを使う場合だけ、import と `fontAwesomeIcons` 配列へ追加 | 既存のアイコン定義 |

最後に単体テストを作る。エンティティ 1 つにつき 7 本である（`テスト規約.md` §2.2）。E2E テストを足す場合は `cypress/e2e/entity/bank-account.cy.ts` を複製して、URL と `data-cy` の値を揃える。

### 5.2 単独の画面を追加する

配置場所によって登録の仕方が変わる。

| 配置場所 | 作成するファイル | ルートの登録 | 見本 |
|---|---|---|---|
| `src/app/account/<名前>/` | `<名前>.ts`（`export default class`）、`<名前>.html`、必要に応じて `<名前>.service.ts`、`<名前>.model.ts`、`<名前>.route.ts` | `<名前>.route.ts` を作り、`src/app/account/account.route.ts` の配列へ追加 | `src/app/account/settings/`（`settings.ts`、`settings.html`、`settings.route.ts`） |
| `src/app/admin/<名前>/` | `<名前>.ts`（`export default class`）、`<名前>.html`、必要に応じて `<名前>.service.ts`、`<名前>.model.ts` | `src/app/admin/admin.routes.ts` に `{ path: '<名前>', loadComponent: () => import('./<名前>/<名前>'), title: '<翻訳キー>' }` を追加 | `src/app/admin/health/`（`health.ts`、`health.service.ts`、`health.model.ts`） |
| 最上位（`src/app/<名前>/`） | 同上 | `src/app/app.routes.ts` に `loadComponent` の項目を追加 | `src/app/login/` |

手順:

1. 見本のディレクトリを複製し、クラス名・セレクター（`jhi-<名前>`）・ファイル名を置き換える。
2. バックエンドを呼ぶ場合は `<名前>.service.ts` に `@Service()` クラスを書く（§5.3）。
3. ルートを登録する。ログインを必要とする画面は `canActivate: [userRouteAccessService]` を付ける（`src/app/account/settings/settings.route.ts`）。`admin` 配下は親ルートが `ROLE_ADMIN` を要求するため、子ルートには指定が要らない。
4. メニューに項目を追加する（`src/app/layouts/navbar/navbar.html`）。`routerLink` は `/` 始まりの絶対パスで書く。E2E テストの `cy.clickOnAdminMenuItem` は `href` で項目を探すためである。
5. 翻訳を `src/i18n/en/<名前>.json` に追加する（見本: `src/i18n/en/health.json`）。
6. `<名前>.spec.ts` と、サービスを作ったなら `<名前>.service.spec.ts` を作る（見本: `src/app/admin/health/health.spec.ts`、`health.service.spec.ts`）。

### 5.3 既存の画面に API 呼び出しを追加する

| 手順 | 内容 | 見本 |
|---|---|---|
| 1 | リクエスト・レスポンスの型が画面固有なら `<名前>.model.ts` に書く。単純な引数ならモデルは要らない | `src/app/account/register/register.model.ts`（`Registration`） |
| 2 | `<名前>.service.ts` に `@Service()` クラスを書く。`private readonly http = inject(HttpClient);`、URL は `${serverApiUrl}api/…` | `src/app/account/password/password.service.ts`（`PasswordService.save`） |
| 3 | 画面で `private readonly <名前>Service = inject(<名前>Service);` を宣言して呼ぶ | `src/app/account/password/password.ts` の `changePassword()` |
| 4 | テンプレートに `<jhi-alert-error />` を置く。エラーの表示は共通の処理に任せる | `src/app/account/settings/settings.html` |
| 5 | `<名前>.service.spec.ts` を書く。`provideHttpClientTesting()` と `httpMock.expectOne({ method, url })` でメソッド・URL・リクエスト本文を検証する | `src/app/account/register/register.service.spec.ts` |

サービスの書き方の見本（`src/app/account/password/password.service.ts`）:

```ts
@Service()
export class PasswordService {
  private readonly http = inject(HttpClient);

  save(newPassword: string, currentPassword: string): Observable<{}> {
    return this.http.post(`${serverApiUrl}api/account/change-password`, { currentPassword, newPassword });
  }
}
```

URL の組み立て方の使い分け:

| 状況 | 書き方 | 実例 |
|---|---|---|
| 画面固有の単発の API | メソッド内に `${serverApiUrl}api/…` と直接書く | `RegisterService.save`（`src/app/account/register/register.service.ts`） |
| 1 つのリソースへ複数のメソッド | フィールド `resourceUrl`（または `infoUrl`）に基底 URL を置く | `src/app/entities/label/service/label.service.ts`、`src/app/layouts/profiles/profile.service.ts` |
| 一覧を `httpResource` で取得 | エンティティ型の 2 段構え（`<Entity>sService` と `<Entity>Service`） | `src/app/entities/bank-account/service/bank-account.service.ts` |

### 5.4 定数・翻訳キー・アイコン・共通部品を追加する

| 対象 | 手順 | 見本 |
|---|---|---|
| 定数 | `src/app/config/<名前>.constants.ts` に `export const` で定義し、`src/app/config/index.ts` に `export * from './<名前>.constants';` を追加する。使う側は `app/config` から import する | `src/app/config/pagination.constants.ts` |
| 翻訳キー | `src/i18n/en/<画面>.json` にキーを追加し、テンプレートで `jhiTranslate="<キー>"` として使う | `src/i18n/en/bankAccount.json` |
| アイコン | `src/app/config/font-awesome-icons.ts` で `@fortawesome/free-solid-svg-icons` から import し、`fontAwesomeIcons` 配列に加える | 同ファイルの既存のアイコン |
| 共通部品（UI） | `src/app/shared/<分類>/` に `<名前>.ts` と `<名前>.html` を置き、`index.ts` で export する。`app/shared/<分類>` の形で import できるようにするには `tsconfig.json` の `paths` にエイリアスを追加する | `src/app/shared/pagination/`（`item-count.ts`、`index.ts`） |
| 純関数 | `src/app/shared/jhipster/` に置く。Angular に依存させない | `src/app/shared/jhipster/headers.ts` |

`src/app/shared/` の分類のうち、`tsconfig.json` の `paths` にエイリアスが設定されているのは `alert`、`auth`、`date`、`language`、`pagination`、`sort` の 6 つである。`filter` と `jhipster` はエイリアスがなく、フルパスで import する。

## 6. 提出前の確認

1. `npm test` で lint と単体テストが通ることを確認する。
2. `npm run prettier:check` で整形の漏れがないことを確認する。
3. `npm run build` で本番構成のビルドが通り、ビルド予算のエラーが出ないことを確認する。
4. 画面や `data-cy` を変えた場合は E2E テスト（`npm run e2e:headless`）を実行する。
5. `開発チェックリスト.md` の該当する表を確認する。

## 7. つまずきやすい箇所と対処

| 症状 | 原因 | 対処 |
|---|---|---|
| ページを開くと「An error has occurred」 | 開発サーバー未起動、`npm install` 失敗、Node.js のバージョン不足 | `src/index.html` の案内に従う。Node.js は 24.21.0 以上 |
| API が 404 になる | バックエンドが起動していない、または起動が完了していない | バックエンドを `http://localhost:8080` で起動する。E2E なら `npm run e2e:headless` を使う（待ち合わせ付き） |
| 利用中に突然ログイン画面へ遷移する | 何らかの API が HTTP 401 を返した（トークンの失効） | 仕様どおりの動きである（`主要処理フロー.md` §2.4）。再ログインすれば元の URL へ戻る |
| URL を直接開くと 404 になる（本番） | 配置先サーバーが `index.html` を返していない | `README.md` の「Building」の 2 つ目の要件を満たす |
| 本番で API 呼び出しが CORS エラーになる | `SERVER_API_URL` で別オリジンを指定したが、バックエンドが CORS を許可していない | バックエンド側でフロントエンドのオリジンを許可する（`README.md`） |
| 登録・編集画面を開いても値が入らない | `resolve` のキー名と画面の `input` のプロパティ名が一致していない | 両者を同じ名前にする（例: `bankAccount`） |
| 一覧画面の単体テストで HTTP リクエストが発生しない | `effect` が進んでいない | spec 内で `TestBed.tick()` を呼ぶ（`テスト規約.md` §3.3） |
| 画面にアイコンが表示されない | アイコンが `fontAwesomeIcons` に登録されていない | `src/app/config/font-awesome-icons.ts` に追加する。単体テストでは spec 内でも登録する |
| E2E テストが要素を見つけられない | `data-cy` の値を変えたか削除した | `cypress/support/commands.ts`、`cypress/support/entity.ts` と spec を合わせて修正する |
| 本番ビルドがスタイル容量のエラーで失敗する | コンポーネントの SCSS が 4kb を超えた | スタイルを `src/content/scss/global.scss`（ビルド予算の対象外）へ移す。既存のコンポーネント用 SCSS 5 ファイルはいずれも 36 行以内である |
| コミット時にファイルが書き換わる | lint-staged の `prettier --write` | 仕様どおりの動きである。差分を確認して add し直す |
| 新しい翻訳キーが `translation-not-found[…]` と出る | キーがないか、JSON の階層が違う | `src/i18n/en/*.json` を確認する |
