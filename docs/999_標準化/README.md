> 画面・コンポーネント単位の設計説明は本ディレクトリの範囲外である（別途 `docs/050_設計/` に作成される）。

## 3. 用語集

本ディレクトリの文書で統一して使う言葉である。

| 用語 | 意味 |
|---|---|
| 画面 | ルートに対応するページ単位のコンポーネント（一覧、詳細、登録・編集など） |
| 機能単位 | 画面・ルート・サービスをまとめた 1 つのディレクトリ（例: `src/app/entities/bank-account/`） |
| 機能層 | `home`、`login`、`account`、`admin`、`entities`、`layouts` の各ディレクトリ |
| 共通部品層 | `core` と `shared` |
| 共通部品 | 複数の画面から使うサービス・部品・定数（`src/app/core/` と `src/app/shared/`、`src/app/config/`）。一覧は [共通部品利用ガイド.md](./共通部品利用ガイド.md) |
| パスエイリアス | `tsconfig.json` の `paths` に定義した import 先の短縮名（`app/config` など） |
| 単票 | レコード 1 件分のデータ、または 1 件を対象とする操作（一覧の対比） |
| 設定層 | `config` |
| エンティティ | 一覧・詳細・登録・編集・削除の一式を持つ業務データ（`bank-account`、`label`、`operation`、`user-management`、`authority`） |
| サービス | `@Service()` を付けたクラス（`*.service.ts`） |
| モデル | `*.model.ts` に定義した型 |
| フォームサービス | `FormGroup` の生成と値の変換を担うサービス（`*-form.service.ts`） |
| リゾルバー | ルートの `resolve` に指定する関数（`*-routing-resolve.service.ts`） |
| ガード | ルートの遷移可否を判定する `userRouteAccessService` |
| インターセプター | HTTP の共通処理を行う関数（`src/app/core/interceptor/`） |
| シグナル | Angular の `signal`、`computed`、`effect` |
| 翻訳キー | `src/i18n/en/*.json` のキー |
| ビルド時定数 | ビルド時にコードへ差し込まれる定数（`SERVER_API_URL`、`__VERSION__`、`I18N_HASH`） |
| 単体テスト | Vitest で実行する `*.spec.ts` |
| E2E テスト | Cypress で実行する `cypress/e2e/**/*.cy.ts` |
| 実測 | 対象コミットのコードを機械的に数えた値 |
| 規則番号 | [ネーミングルールとコーディング規約.md](./ネーミングルールとコーディング規約.md) の規則の番号。F（ファイル名）、C（クラスとシンボル）、T（TypeScript）、M（テンプレートとスタイル）、R（ルートと翻訳キー） |

## 4. 記法の約束

- ファイルのパスはリポジトリルート基準で書く。文書名だけの参照は本ディレクトリ内の文書を指す。
- コードの識別子、ファイル名、コマンドはバッククォートで囲む。
- 「実測」「import 数」などの数値は、その文書の冒頭に対象コミットと集計範囲を記してある。
- 設定値は `ファイル名` と JSON のキーの位置（例: `angular.json` の `architect.serve.options.port`）で示す。
- 記述の根拠となるファイルを「出典」「依拠」「根拠」の欄に示す。
- 置き換える部分を示すプレースホルダーは山括弧で書く。ファイル名とパスの部分は `<entity>`、`<名前>`（kebab-case）、クラス名の部分は `<Entity>`（PascalCase）、その他の語は `<キー>`、`<項目名>` のように日本語で書く。

## 5. 対象外とした事項

| 事項 | 理由 |
|---|---|
| 画面・コンポーネント単位の設計説明 | 別途 `docs/050_設計/` に作成される設計書の範囲である。本ディレクトリは画面をまたぐ共通の規約と知識だけを扱う |
| ログ出力の規約（出力項目、マスク） | フロントエンドにはログを出力する仕組みがない。`console.log` は lint で禁止されており、あるのはバックエンドのログを閲覧する画面（`/admin/logs`）だけである |
| JHipster による再生成の手順 | `generator-jhipster` は依存から外れており、再生成はできない（`README.md`） |
| バックエンドの内部構造 | 別リポジトリである。本ディレクトリはフロントエンドが呼ぶ API の一覧（[システム知識整理.md](./システム知識整理.md) §4）までを扱う |

## 7. 更新するときの約束

- コードや設定を変えたときは、対応する文書の記述を更新する。文書の冒頭と末尾に対象コミットを記す。
- 実測値（件数、import 数）は、コードが変わると古くなる。数え直したときは集計範囲とコミットをそろえて更新する。
- 既存コードと規則が食い違うときは、規則の側を現状に合わせて直すか、[ネーミングルールとコーディング規約.md](./ネーミングルールとコーディング規約.md) §9 の「既存コードの揺れ」に加える。根拠のない規則を追加しない。
