# 共通部品利用ガイド

> **位置づけ**: 画面やサービスを書くときに「どの共通部品を、いつ、どう使うか」を引くための一覧である。
> 層の構造は `プロジェクト構成とレイヤー別開発ガイド.md`、処理の流れは `主要処理フロー.md`、名前の付け方は `ネーミングルールとコーディング規約.md` を参照。
> 「import 数」は、コミット `bf6b0ad` の `src/**/*.ts` のうち、そのシンボルを import しているファイルの数である（単体テスト、定義ファイル、バレル `index.ts` を除く）。テンプレートからだけ使う部品については、その部品を import するコンポーネントの数が import 数になる。

## 1. 認証・セッション（`src/app/core/auth`）

import はエイリアス `app/core/auth` から行う。

| 部品 | 用途 | 使い分け | import 数 | 定義 |
|---|---|---|---|---|
| `AccountService` | ログイン中アカウントの保持と取得 | 画面は読み取り専用シグナル `account` を読む。再取得は `identity(force?)` | 10 | `account.service.ts` |
| `StateStorageService` | 認証トークン、遷移前 URL、選択言語の保存 | 保存先はブラウザーのストレージ。画面が直接 `localStorage` / `sessionStorage` を操作しない | 7 | `state-storage.service.ts` |
| `userRouteAccessService` | ルートガード（ログインと権限の判定） | ルート定義の `canActivate` に置く | 8 | `user-route-access.service.ts` |
| `AuthServerProvider` | トークンの発行要求と破棄 | `LoginService` だけが使う | 1 | `auth-jwt.service.ts` |
| `Account`、`Login` | アカウントとログイン情報のモデル | — | 各 3 | `account.model.ts`、`login.model.ts` |

`AccountService` の要点（`src/app/core/auth/account.service.ts`）:

| メンバー | 動作 |
|---|---|
| `account`（読み取り専用シグナル） | ログイン中なら `Account`、未ログインなら `null` |
| `identity(force?: boolean)` | キャッシュ（`accountCache$`）がないか `force` が true なら `GET api/account` を呼ぶ。失敗時は `null` を流す |
| `authenticate(identity)` | シグナルを設定する。`null` を渡すとキャッシュも消える |
| `hasAnyAuthority(authorities)` | 所持権限と照合する。引数は文字列 1 つでも配列でもよい |
| `save(account)` | `POST api/account`（設定画面） |

`identity()` は取得に成功すると、次の 2 つを副次的に行う。

- `account.langKey` があり、かつセッションに言語の選択が保存されていない場合、`account.langKey` に言語を切り替える。
- `StateStorageService` に遷移前 URL が保存されていれば、そこへ遷移して保存値を消す。

`StateStorageService` の保存内容（`src/app/core/auth/state-storage.service.ts`）:

| メソッド | キー | 保存先 | 値 |
|---|---|---|---|
| `storeUrl` / `getUrl` / `clearUrl` | `previousUrl` | `sessionStorage` | URL を JSON 文字列化したもの |
| `storeAuthenticationToken` / `getAuthenticationToken` / `clearAuthenticationToken` | `jhi-authenticationToken`（`AUTHENTICATION_TOKEN_KEY`） | `rememberMe` が true なら `localStorage`、それ以外は `sessionStorage` | トークンを JSON 文字列化したもの |
| `storeLocale` / `getLocale` / `clearLocale` | `locale` | `sessionStorage` | 言語コード |

読み取り（`getAuthenticationToken`）は `localStorage` を先に調べ、無ければ `sessionStorage` を見る。

## 2. HTTP インターセプター（`src/app/core/interceptor`）

4 本とも `HttpInterceptorFn` であり、`src/app/app.config.ts` の `provideHttpClient(withInterceptors([…]))` に次の順で登録されている。画面やサービスは個別に import しない。

| 順 | 部品 | 処理 | 対象外 | 定義 |
|---|---|---|---|---|
| 1 | `authInterceptor` | トークンがあれば `Authorization: Bearer {token}` を付ける | URL が空、または `http` で始まり `serverApiUrl` で始まらないリクエスト | `auth.interceptor.ts` |
| 2 | `authExpiredInterceptor` | 401 を受けたら、現在の URL を保存し、ログアウトして `/login` へ遷移する | URL に `api/account` を含むリクエスト | `auth-expired.interceptor.ts` |
| 3 | `errorHandlerInterceptor` | エラーをイベント `jhipsterSampleApplicationApp.httpError` として配信する | 401 かつ、`message` が空または URL に `api/account` を含む | `error-handler.interceptor.ts` |
| 4 | `notificationInterceptor` | 成功レスポンスのヘッダー `x-jhipstersampleapplicationapp-alert`（と `-params`）を成功アラートにする | 成功レスポンス以外 | `notification.interceptor.ts` |

- `api/account` を除外しているため、未ログイン状態での `GET api/account` の 401 は、ログアウト処理にもエラー表示にもならない。
- `authExpiredInterceptor` だけは `app/login/login.service` を import している（`LoginService.logout()` を呼ぶため）。これは共通部品層から機能層への依存として、本リポジトリで唯一の例外である。

`createRequestOption` の変換規則（`src/app/core/request/request-util.ts`）:

- 値が `undefined` と `null` の項目は落とす。

エンティティのサービスは `query(req?)` の中で使う（`this.http.get<…>(this.resourceUrl, { params: createRequestOption(req), observe: 'response' })`）。

## 4. 通知・イベント（`src/app/core/util`、`src/app/shared/alert`）

### 4.1 アラート

| 部品 | 種別 | 用途 | import 数 | 定義 |
|---|---|---|---|---|
| `AlertService` | サービス | アラートの追加と既定値の管理 | 3 | `src/app/core/util/alert.service.ts` |
| `AlertError` | コンポーネント `<jhi-alert-error />` | HTTP エラーを危険アラートとして表示する | 22 | `src/app/shared/alert/alert-error.ts` |
| `Alert` | コンポーネント `<jhi-alert />` | `AlertService` 本体のアラート（成功通知など）を表示する | 10 | `src/app/shared/alert/alert.ts` |
| `AlertModel`、`AlertErrorModel` | モデル | アラートの型 | 2、1 | `alert.service.ts`、`alert-error.model.ts` |

`AlertService.addAlert(alertToAdd, extAlerts?)` の動作（`src/app/core/util/alert.service.ts`）:

- `translationKey` があれば `TranslateService.instant(key, translationParams)` で翻訳し、結果を `message` に設定する。未訳（`translation-not-found[…]` の形）で `message` の指定もない場合は、`translationKey` 自体を `message` にする。
- `message` は `DomSanitizer.sanitize(SecurityContext.HTML, …)` を通す。テンプレートは `<pre [innerHTML]="alert.message">` で表示する。
- 未指定なら既定値を補う。`timeout` は 5000 ミリ秒、`toast` は `false`、`position` は `'top right'`。
- `timeout` が 0 より大きければ、時間経過で自動的に閉じる。
- 第 2 引数 `extAlerts`（`WritableSignal<AlertModel[]>`）を渡すと、`AlertService` 本体ではなくそのシグナルに追加する。`AlertError` は自分のシグナルを渡している。

`AlertError` は `EventManager` の `jhipsterSampleApplicationApp.httpError` を購読し、ステータスに応じて次のとおり表示を切り替える（`alert-error.ts` の `handleHttpError`）。

| ステータス | 表示内容 |
|---|---|
| 0（サーバーに到達できない） | 翻訳キー `error.server.not.reachable` |
| 400 | レスポンスヘッダーの `x-jhipstersampleapplicationapp-error` が翻訳キーなら、それを表示（`-params` は `entityName` として渡す）。ヘッダーがメッセージなら原文を表示。本文に `fieldErrors` があれば項目ごとに `error.{メッセージ}` を表示。本文に `message` があれば、それを翻訳キーとして表示。いずれも無ければ本文を原文として表示 |
| 404 | 翻訳キー `error.url.not.found` |
| 上記以外 | 本文に `message` があれば、それを翻訳キー（`detail` を既定文言、`params` を埋め込み値）として表示。無ければ原文を表示 |

## 8. 使用規約速記

1. 認証状態は `AccountService.account` を読む。`GET api/account` を画面から直接呼ばない。
2. トークン・遷移前 URL・言語の保存は `StateStorageService` を使う。画面が直接ブラウザーのストレージを操作しない。
3. クエリパラメーターは `createRequestOption` で組む。
4. 成功通知はバックエンドがレスポンスヘッダー `x-jhipstersampleapplicationapp-alert` で返す翻訳キーを `notificationInterceptor` が表示する。画面は `<jhi-alert />` を置くだけでよい。
5. エラー表示は `<jhi-alert-error />` が担う。画面で `error` コールバックに表示処理を書かない（登録・編集画面の `onSaveError()` は空である）。
6. 文言は `jhiTranslate` で置く。要素の内容に残す英語は、翻訳が読み込まれるまでの既定文言である。
7. 権限による表示制御は `*jhiHasAnyAuthority`、ルート単位の制御は `canActivate: [userRouteAccessService]` と `data.authorities` を使う。
8. 並び替えは `jhiSort` / `jhiSortBy` / `SortService` / `sortStateSignal` の組を使い、状態はクエリパラメーター `sort` に反映する。
