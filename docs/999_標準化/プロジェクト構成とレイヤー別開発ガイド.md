# プロジェクト構成とレイヤー別開発ガイド

> **位置づけ**: ディレクトリの意味、レイヤー間の依存の向き、各層のコードの書き方（モデル・サービス・フォームサービス・リゾルバー・ルート・画面）を規定するものである。
> 依存の向きと import の数はコミット `bf6b0ad` の `src/**/*.ts`（単体テストを除く 181 ファイル、import 文 737 件）を実測した結果である。
> 数え方は、行頭が `import` である静的な文を 1 件とし、動的 `import()`（41 件）と `export … from` は含めないものである。動的 `import()` は §3.2 の相対パスの集計にだけ含める。
> 命名の規則は `ネーミングルールとコーディング規約.md`、共通部品の選び方は `共通部品利用ガイド.md`、手順は `開発手順.md` を参照。
> 画面ごとの設計説明は本書の範囲外である（別途 `docs/050_設計/` 配下に作成される）。

## 1. 全体像（レイヤーと依存の向き）

```
                     ┌──────────────────────────────────────────────────────┐
  機能層（画面）       │ home   login   account   admin   entities   layouts │ ← src/app/app.routes.ts
                     └───────────────────────────┬──────────────────────────┘   src/app/app.config.ts
                                                 │ 下方向だけを参照する
                     ┌───────────────────────────▼──────────────────────────┐
  共通部品層           │ core    auth / interceptor / request / util          │
                     │ shared  alert / auth / date / filter / jhipster      │
                     │         language / pagination / sort                  │
                     └───────────────────────────┬──────────────────────────┘
                                                 │ 下方向だけを参照する
                     ┌───────────────────────────▼──────────────────────────┐
  設定層              │ config  定数 / 翻訳ローダー / dayjs / 日付ピッカー / アイコン │
                     └──────────────────────────────────────────────────────┘
```

実測で確認した事実:

| レイヤー | 参照している相手 | 参照していない相手 | 備考 |
|---|---|---|---|
| `config` | Angular、ngx-translate、dayjs、Font Awesome、`i18n`（仮想モジュール） | `app/` 配下のすべて | `src/app/config/translation.config.ts` だけが `i18n` を import する |
| `shared` | `config`、`core/auth`、`core/util` | 機能層のすべて | `shared/auth` は `app/core/auth`、`shared/alert` は `app/core/util` を使う |
| `core` | `config`、`app/shared/jhipster/*` | `admin`、`account`、`entities`、`home`、`layouts` | **例外 1 件**: `src/app/core/interceptor/auth-expired.interceptor.ts` が `app/login/login.service` を使う |
| 機能層 | `config`、`core`、`shared`、`environments/environment` | — | 機能層どうしの参照は §6 のとおり限定的 |

- `core` と `shared` は相互に参照し合う。`core` が使うのは `src/app/shared/jhipster/` 配下の定数・純関数（`constants.ts`、`headers.ts`、`data-utils.ts`、`link-header.ts`）に限られる。
- 上方向の参照（共通部品層から機能層への依存）は `auth-expired.interceptor.ts` の 1 件のみである。HTTP 401 を受けたときに `LoginService.logout()` を呼ぶために生じている。共通部品を新設する場合も、機能層を import しないのが本リポジトリの構造である。

### 3.2 import の書き分け

実測では、相対パスによる import 187 件（静的な文 148 件と動的 `import()` 39 件。バレル `index.ts` の `export … from` は含まない）のうち、import 元と import 先が同じ `src/app/<層>/<単位>/` 配下にあるもの（層の直下のファイルはどの単位にも属さないものとした）は 151 件である。残りの 36 件は、`src/` 直下、`src/app/` 直下、および層の直下のファイル（`src/app/app.routes.ts`、`src/app/app.config.ts`、`src/app/account/account.route.ts`、`src/app/admin/admin.routes.ts`、`src/app/entities/entity.routes.ts` など）が配下または同じディレクトリの画面や部品を参照する 32 件と、`src/app/layouts/main/main.ts` などが隣接する部品を参照する 4 件である。この結果から、書き分けは次のとおりである。

| 状況 | 書式 | 実例 |
|---|---|---|
| エイリアスのあるモジュール | エイリアスで import | `import { AccountService } from 'app/core/auth';`（`src/app/login/login.service.ts`） |
| 同一の機能単位の中 | 相対パス | `import { IBankAccount, NewBankAccount } from '../bank-account.model';`（`src/app/entities/bank-account/service/bank-account.service.ts`） |
| 別の機能単位 | `app/` で始まる絶対パス | `import { UserService } from 'app/entities/user/service/user.service';`（`src/app/entities/bank-account/update/bank-account-update.ts`） |
| エイリアスのない共通部品 | `app/shared/jhipster/…` の絶対パス | `import { getMessageFromHeaders } from 'app/shared/jhipster/headers';`（`src/app/core/interceptor/notification.interceptor.ts`） |

- 絶対パスの先頭は `src/` ではなく `app/`（または `environments/`）である。`"*": ["./src/*"]` により `src/` 直下がルートとして解決される。
- 既存コードには、別の機能単位を相対パスで参照している箇所が 4 か所ある。`src/app/shared/pagination/item-count.ts` の `../language/translate.directive`、`src/app/layouts/main/main.ts` の `../footer/footer` と `../profiles/page-ribbon`、`src/app/account/register/register.ts` の `../password/password-strength-bar/password-strength-bar` である。このうち最後の参照先は、`src/app/account/password-reset/finish/password-reset-finish.ts` が `app/account/password/password-strength-bar/password-strength-bar` と絶対パスでも参照しており、同じものの書き方が分かれている。新規に書く場合は表のとおり絶対パスに合わせる。

## 5. 各層の書き方

以下、コードは現存するものからの抜粋である。新規コードは同じ形で書く。

### 5.1 モデル（`*.model.ts`）

エンティティは「`I` 付きの interface」と「新規登録用の型」の 2 つを export する。

```ts
// src/app/entities/bank-account/bank-account.model.ts
export interface IBankAccount {
  id: number;
  name?: string | null;
  balance?: number | null;
  user?: Pick<IUser, 'id' | 'login'> | null;
}

export type NewBankAccount = Omit<IBankAccount, 'id'> & { id: null };
```

- 主キー以外の項目は `?` と `| null` を併記する。
- 日付項目は `dayjs.Dayjs | null` で持つ（`src/app/entities/operation/operation.model.ts` の `date`）。
- 関連は、選択肢として使う項目だけを持つ形（上記 `user`）か、相手の interface をそのまま使う形（`operation.model.ts` の `bankAccount?: IBankAccount | null`、`labels?: ILabel[] | null`）である。
- 主キーが `id` でないエンティティでは `New…` の除外項目が変わる。`user-management.model.ts` は `login` を主キーとし、`NewUserManagement = Omit<IUserManagement, 'login'> & { login: null }` としている。`authority.model.ts` は `name` である。
- REST で受け取る生の形（日付が文字列）は、サービスファイル内に `RestOf<T>` と `Rest…` 型として定義する（§5.2）。
- 単独画面のモデルは class（`Account`、`Login`、`Registration`）、interface / type（`HealthModel`、`MetricsModel`、`Bean`）、enum（`ThreadState`、`HttpMethod`）が混在する。画面ごとに既存の形に合わせる。

### 5.2 サービス（`*.service.ts`）

**デコレーターは `@Service()` である。** `@Injectable()` は使われていない（`src/app` 配下で定義 0 件）。依存は `inject()` 関数で受け取る。

エンティティのサービスは、一覧取得を担う複数形クラスと、単票の CRUD を担う単数形クラスの 2 段構えである。

```ts
// src/app/entities/bank-account/service/bank-account.service.ts（抜粋）
@Service()
export class BankAccountsService {
  readonly bankAccountsParams = signal<Record<string, string | number | boolean | readonly (string | number | boolean)[]> | undefined>(
    undefined,
  );
  readonly bankAccountsResource = httpResource<IBankAccount[]>(() => {
    const params = this.bankAccountsParams();
    if (!params) {
      return undefined;
    }
    return { url: this.resourceUrl, params };
  });
  readonly bankAccounts = computed(() => (this.bankAccountsResource.hasValue() ? this.bankAccountsResource.value() : []));
  protected readonly resourceUrl = `${serverApiUrl}api/bank-accounts`;
}

@Service()
export class BankAccountService extends BankAccountsService {
  protected readonly http = inject(HttpClient);

  create(bankAccount: NewBankAccount): Observable<IBankAccount> { … }
  update(bankAccount: IBankAccount): Observable<IBankAccount> { … }
  partialUpdate(bankAccount: PartialUpdateBankAccount): Observable<IBankAccount> { … }
  find(id: number): Observable<IBankAccount> { … }
  query(req?: any): Observable<HttpResponse<IBankAccount[]>> { … }
  delete(id: number): Observable<undefined> { … }
  getBankAccountIdentifier(bankAccount: Pick<IBankAccount, 'id'>): number { … }
  compareBankAccount(o1, o2): boolean { … }
  addBankAccountToCollectionIfMissing<Type extends Pick<IBankAccount, 'id'>>(…): Type[] { … }
}
```

| 部品 | 役割 | 使う場面 |
|---|---|---|
| `<entity>sParams`（`signal`） | 一覧取得のクエリパラメーター。画面の `queryBackend()` が `set()` する | 一覧画面 |
| `<entity>sResource`（`httpResource`） | パラメーターが `undefined` の間はリクエストしない。レスポンスヘッダーも読める | 一覧画面 |
| `<entity>s`（`computed`） | 取得結果。未取得または失敗時は空配列 | 一覧画面 |
| `create` / `update` / `partialUpdate` / `find` / `delete` | 単票の CRUD。`Observable` を返す | 登録・編集画面、削除ダイアログ、リゾルバー |
| `query(req?)` | `createRequestOption(req)` をパラメーターにして全件取得し、`observe: 'response'` で返す | 関連エンティティの選択肢の読み込み |
| `get<Entity>Identifier` / `compare<Entity>` | 主キーの取得と比較。`track` 式と `[compareWith]` に使う | 画面 |
| `add<Entity>ToCollectionIfMissing` | 既存の選択肢一覧に、現在の値が含まれていなければそれを先頭に補う | 登録・編集画面の関連選択肢 |

- 一覧の URL パラメーターは `undefined` のとき空配列ではなくリクエスト自体を抑止する（`if (!params) { return undefined; }`）。一覧画面はこの仕組みにより、パラメーターを設定するまではリクエストを送らない。
- `resourceUrl` は `${serverApiUrl}api/<複数形-kebab>` とし、個別の URL は `${this.resourceUrl}/${encodeURIComponent(id)}` の形で組み立てる。
- 日付を持つエンティティは、REST 用の型と変換メソッドを備える。実例は `src/app/entities/operation/service/operation.service.ts`。

```ts
// src/app/entities/operation/service/operation.service.ts（抜粋）
type RestOf<T extends IOperation | NewOperation> = Omit<T, 'date'> & { date?: string | null };
export type RestOperation = RestOf<IOperation>;
export type NewRestOperation = RestOf<NewOperation>;
export type PartialUpdateRestOperation = RestOf<PartialUpdateOperation>;

protected convertValueFromServer(restOperation: RestOperation): IOperation {
  return { ...restOperation, date: restOperation.date ? dayjs(restOperation.date) : undefined };
}
protected convertValueFromClient<T extends IOperation | NewOperation | PartialUpdateOperation>(operation: T): RestOf<T> {
  return { ...operation, date: operation.date?.toJSON() ?? null };
}
```

- バックエンドを呼ばない単独画面は、シグナルを持たない `Observable` だけのサービスになる（例: `src/app/admin/health/health.service.ts` の `HealthService`）。

### 5.3 フォームサービス（`update/<entity>-form.service.ts`）

`FormGroup` の生成、フォーム値とモデル値の相互変換を画面から分離したサービスである。

```ts
// src/app/entities/bank-account/update/bank-account-form.service.ts（抜粋）
type PartialWithRequiredKeyOf<T extends { id: unknown }> = Partial<Omit<T, 'id'>> & { id: T['id'] };
type BankAccountFormGroupInput = IBankAccount | PartialWithRequiredKeyOf<NewBankAccount>;
type BankAccountFormDefaults = Pick<NewBankAccount, 'id'>;
type BankAccountFormGroupContent = {
  id: FormControl<IBankAccount['id'] | NewBankAccount['id']>;
  name: FormControl<IBankAccount['name']>;
  …
};
export type BankAccountFormGroup = FormGroup<BankAccountFormGroupContent>;

@Service()
export class BankAccountFormService {
  createBankAccountFormGroup(bankAccount?: BankAccountFormGroupInput): BankAccountFormGroup {
    const bankAccountRawValue = { ...this.getFormDefaults(), ...(bankAccount ?? { id: null }) };
    return new FormGroup<BankAccountFormGroupContent>({
      id: new FormControl({ value: bankAccountRawValue.id, disabled: true }, { nonNullable: true, validators: [Validators.required] }),
      name: new FormControl(bankAccountRawValue.name, { validators: [Validators.required] }),
      …
    });
  }
  getBankAccount(form: BankAccountFormGroup): IBankAccount | NewBankAccount { return form.getRawValue(); }
  resetForm(form: BankAccountFormGroup, bankAccount: BankAccountFormGroupInput): void { … }
  private getFormDefaults(): BankAccountFormDefaults { return { id: null }; }
}
```

- 主キーの `FormControl` は `disabled: true` にする。値は `getRawValue()` で取り出す。
- 必須項目には `validators: [Validators.required]` を付ける。画面テンプレートのエラー表示（`entity.validation.required`）と対応する。
- 日付を扱うフォームは、フォーム内では `DATE_TIME_FORMAT`（`src/app/config/input.constants.ts`）の文字列で持ち、`convert…RawValue…` 系の private メソッドで `dayjs` と相互変換する（`src/app/entities/operation/update/operation-form.service.ts`）。

### 5.4 リゾルバー（`route/<entity>-routing-resolve.service.ts`）

詳細・編集画面を開く前に 1 件を取得する。5 エンティティで同一の形である。

```ts
// src/app/entities/bank-account/route/bank-account-routing-resolve.service.ts
const bankAccountResolve = (route: ActivatedRouteSnapshot): Observable<null | IBankAccount> => {
  const { id } = route.params;
  if (id) {
    const router = inject(Router);
    const service = inject(BankAccountService);
    return service.find(id).pipe(
      catchError((error: HttpErrorResponse) => {
        if (error.status === 404) {
          router.navigate(['404']);
        } else {
          router.navigate(['error']);
        }
        return EMPTY;
      }),
    );
  }
  return of(null);
};
export default bankAccountResolve;
```

- パスパラメーターが無ければ `of(null)` を返す。これが「新規登録」の初期値になる。
- 404 は `/404`、それ以外の失敗は `/error` へ遷移し、`EMPTY` を返してナビゲーションを中断する。

### 5.5 ルート（`*.routes.ts` / `*.route.ts`）

エンティティのルートは 4 画面分を 1 ファイルにまとめる。

```ts
// src/app/entities/bank-account/bank-account.routes.ts（抜粋）
const bankAccountRoute: Routes = [
  { path: '', loadComponent: () => import('./list/bank-account').then(m => m.BankAccount),
    data: { defaultSort: `id,${ASC}` }, canActivate: [userRouteAccessService] },
  { path: ':id/view', loadComponent: () => import('./detail/bank-account-detail').then(m => m.BankAccountDetail),
    resolve: { bankAccount: BankAccountResolve }, canActivate: [userRouteAccessService] },
  { path: 'new', loadComponent: () => import('./update/bank-account-update').then(m => m.BankAccountUpdate),
    resolve: { bankAccount: BankAccountResolve }, canActivate: [userRouteAccessService] },
  { path: ':id/edit', …（編集。同上） },
];
export default bankAccountRoute;
```

- 遅延読み込みは `loadComponent: () => import('./x').then(m => m.Xxx)` で書く。エンティティの画面は名前付き export なので `.then(m => m.Xxx)` が必要である。`export default class` の画面（`home`、`login`、`account/*`、`admin/*`、`layouts/*`）は `loadComponent: () => import('./home/home')` のみでよい。
- `resolve` のキー名は、詳細画面の `input` プロパティ名と一致させる（§5.6）。`appConfig` の `withComponentInputBinding()` がこの対応で解決データを画面へ束縛する。
- ログイン必須のルートには `canActivate: [userRouteAccessService]` を付ける。権限が必要な場合は `data: { authorities: ['ROLE_ADMIN'] }` を併記する（`src/app/entities/admin/user-management/user-management.routes.ts`）。
- 既定の並びを持つ一覧（`bank-account`、`label`、`operation`）は `data: { defaultSort: `id,${ASC}` }` を指定する（`ASC` は `app/config`）。画面はクエリパラメーター `sort` がないときにこの値を使う。`user-management` と `authority` のルートにはこの指定がない。
- エンティティのルートは `src/app/entities/entity.routes.ts` に `{ path: '<entity>', title: '<翻訳キー>', loadChildren: () => import('./<entity>/<entity>.routes') }` として登録する。ここでの `path` が URL の先頭セグメントになる。

### 5.6 画面コンポーネント

共通の書式:

- メタデータは `selector`、`templateUrl`、（必要なら）`styleUrl`、`imports` だけを書く。`standalone: true` と `ChangeDetectionStrategy` の指定はない。
- 依存は `inject()` で受ける。既存コードでは、エンティティの画面はアクセス修飾子に `protected` を付けるが `readonly` には揺れがあり、`protected readonly xxxService = inject(XxxService);` が多い一方で、登録・編集画面と一覧画面の一部は `protected xxxService = inject(XxxService);` と `readonly` を付けない。それ以外の画面は `private readonly xxxService = inject(XxxService);` が多い。新規コードには、エンティティ配下は `protected readonly`、それ以外は `private readonly` を使うことを推奨する（規則 T-01。件数は §8）。
- 画面内の状態はシグナルで持つ（`readonly isSaving = signal(false);` など）。保存中は `isSaving` を `true` にしてボタンを無効化する。
- 「戻る」は `previousState()` メソッドで `globalThis.history.back()` を呼ぶ。

**一覧画面**（`list/<entity>.ts`）は 3 つの形がある。どれも「ルートのクエリパラメーター → サービスの `…Params` シグナル → `httpResource` → 画面のシグナル」という流れは同じである。

| 形 | 実例 | クエリパラメーター（`queryBackend()`） | テンプレート上の要素 |
|---|---|---|---|
| 全件取得・画面内並び替え | `BankAccount`、`Label`、`Authority` | `sort`（関係を持つ `BankAccount` のみ `eagerload: true` も指定） | 並び替えヘッダーのみ |
| 無限スクロール | `Operation` | `size`（`ITEMS_PER_PAGE`）と `eagerload: true`。2 ページ目以降は `link` ヘッダーの `next` の内容を引き継ぐ | `<tbody infinite-scroll (scrolled)="loadNextPage()" …>`（`ngx-infinite-scroll`） |
| ページング | `UserManagement` | `page`（0 始まり）、`size`、`sort`。総件数は `X-Total-Count` ヘッダーから取る | `<jhi-item-count>` と `<ngb-pagination (pageChange)="navigateToPage($event)">` |

共通するメソッド名は次のとおりである。

| メソッド | 役割 |
|---|---|
| `trackId`（`trackLogin`、`trackName`） | `@for` の `track` 式。サービスの `get…Identifier` に委譲 |
| `load()` | `queryBackend()` を呼ぶ |
| `delete(item)` | 削除ダイアログを `modalService.open(XxxDeleteDialog, { size: 'lg', backdrop: 'static' })` で開き、`ITEM_DELETED_EVENT` で閉じられたら `load()` する |
| `navigateToWithComponentValues(sortState)` | 並び替えの変更をクエリパラメーターへ反映（`router.navigate(['./'], { relativeTo, queryParams })`） |
| `fillComponentAttributeFromRoute` | クエリパラメーター（`sort`、`page`）をシグナルへ反映 |
| `fillComponentAttributesFromResponseBody` / `…FromResponseHeader` | レスポンス本文・ヘッダーをシグナルへ反映 |

**詳細画面**（`detail/<entity>-detail.ts`）はリゾルバーの結果を `input` で受ける。API を呼ばない。

```ts
// src/app/entities/bank-account/detail/bank-account-detail.ts
export class BankAccountDetail {
  readonly bankAccount = input<IBankAccount | null>(null);
  previousState(): void { globalThis.history.back(); }
}
```

**登録・編集画面**（`update/<entity>-update.ts`）は、リゾルバーの結果を `ActivatedRoute.data` で受けてフォームへ反映する。

```ts
// src/app/entities/bank-account/update/bank-account-update.ts（抜粋）
editForm: BankAccountFormGroup = this.bankAccountFormService.createBankAccountFormGroup();

ngOnInit(): void {
  this.activatedRoute.data.subscribe(({ bankAccount }) => {
    this.bankAccount = bankAccount;
    if (bankAccount) { this.updateForm(bankAccount); }
    this.loadRelationshipsOptions();
  });
}

save(): void {
  this.isSaving.set(true);
  const bankAccount = this.bankAccountFormService.getBankAccount(this.editForm);
  if (bankAccount.id === null) {
    this.subscribeToSaveResponse(this.bankAccountService.create(bankAccount));
  } else {
    this.subscribeToSaveResponse(this.bankAccountService.update(bankAccount));
  }
}

protected subscribeToSaveResponse(result: Observable<IBankAccount | null>): void {
  result.pipe(finalize(() => this.onSaveFinalize())).subscribe({ next: () => this.onSaveSuccess(), error: () => this.onSaveError() });
}
protected onSaveSuccess(): void { this.previousState(); }
protected onSaveError(): void { /* Api for inheritance. */ }
protected onSaveFinalize(): void { this.isSaving.set(false); }
```

- 新規か更新かは `id === null` で判定する。
- 保存エラー時の処理は空である。エラー表示はインターセプターと `<jhi-alert-error />` が担う（`主要処理フロー.md` §4）。
- 関連を持つエンティティは `loadRelationshipsOptions()` で関連先を `query()` し、`add…ToCollectionIfMissing` で現在の値を補って `…SharedCollection` シグナルへ入れる（`src/app/entities/operation/update/operation-update.ts` は `bankAccountsSharedCollection` と `labelsSharedCollection` の 2 つ）。

**削除ダイアログ**（`delete/<entity>-delete-dialog.ts`）は `selector` を持たない。

```ts
// src/app/entities/bank-account/delete/bank-account-delete-dialog.ts
@Component({ templateUrl: './bank-account-delete-dialog.html', imports: [TranslateDirective, FormsModule, FontAwesomeModule, AlertError] })
export class BankAccountDeleteDialog {
  bankAccount?: IBankAccount;
  protected readonly bankAccountService = inject(BankAccountService);
  protected readonly activeModal = inject(NgbActiveModal);
  cancel(): void { this.activeModal.dismiss(); }
  confirmDelete(id: number): void {
    this.bankAccountService.delete(id).subscribe(() => { this.activeModal.close(ITEM_DELETED_EVENT); });
  }
}
```

呼び出す側は `modalRef.componentInstance.bankAccount = bankAccount;` で値を渡す。

### 5.7 テンプレート

- 制御構文は `@if` / `@for` / `@let` を使う。`*ngIf`、`*ngFor`、`[(ngModel)]`、`ngClass` は使われていない（テンプレート中 0 件）。
- 文言は `jhiTranslate="<翻訳キー>"` ディレクティブで置く。要素の内容には英語の既定文言を残す。属性値は `{{ 'key' | translate }}` とする。
- E2E テストや単体テストから要素を特定するため、操作対象には `data-cy="<camelCase 名>"` を付ける。
- 詳細は `ネーミングルールとコーディング規約.md` §5 を参照。

## 8. 既存コードの揺れ（知っておくべき例外）

- **`export default` と名前付き export の使い分け**: `loadComponent` で直接読む画面（`home`、`login`、`account/*`、`admin/*` 直下、`layouts/*`）と一部の共通部品（`src/app/shared/alert/alert.ts`、`src/app/shared/filter/filter.ts`、`src/app/shared/pagination/item-count.ts`）は `export default class` である。エンティティの画面、`admin/metrics/blocks/*`、`AlertError` は名前付き export である。
- **アクセス修飾子**: `inject()` で初期化するクラスのフィールド（単体テストを除く 145 件）のうち、エンティティ配下の 63 件は `protected readonly` 32 件、`readonly` を付けない `protected` 25 件（登録・編集画面 19 件、一覧画面の `modalService` など 6 件）、アクセス修飾子なしの `readonly` 6 件（一覧画面の `readonly router = inject(Router);` など）である。それ以外の 82 件は `private readonly` 78 件、アクセス修飾子なしの `readonly` 3 件、`public readonly` 1 件（`src/app/home/home.ts`）である。数え方は、`*.spec.ts` を除く `src/**/*.ts` の行のうち、アクセス修飾子（`public`、`protected`、`private` のいずれか、または省略）と `readonly`（あり、または省略）に続けて `<名前> = inject(` と書かれたクラスのフィールドを数えるものであり、リゾルバーやインターセプターなど関数内の `const x = inject(…)` 23 件は含めない。`protected readonly` と `private readonly` は、lint 上の違いはない。
- **`member-ordering` の抑制コメント**: 依存の注入より後に別のフィールドを宣言する箇所には `// eslint-disable-next-line @typescript-eslint/member-ordering` が付いている（非テストコードで 12 件）。該当するのは `readonly isLoading = this.xxxService.xxxResource.isLoading;`、`editForm = this.xxxFormService.create…FormGroup();`、`readonly authorities = computed(…)` などの形である（`src/app/entities/**` の一覧・登録・編集画面と `src/app/core/auth/account.service.ts`）。
- **`shared/filter` は未使用**: フィルター表示部品 `<jhi-filter>` と `FilterOptions` は、本体から参照されていない（`共通部品利用ガイド.md` §7）。
