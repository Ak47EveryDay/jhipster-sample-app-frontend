# ドキュメント（jhipster-sample-app-frontend）

このディレクトリには、リポジトリ `jhipster-sample-app-frontend` の日本語の文書を置く。
いずれもこのリポジトリの現在のコード（コミット `bf6b0ad` 時点）を根拠に作成している。文書とコードが食い違う場合はコードを正とし、文書を修正すること。

## 構成

| ディレクトリ | 扱う内容 | 読む場面 |
| --- | --- | --- |
| [999_標準化](./999_標準化/README.md) | 規約とシステム知識。プロジェクトの構成とレイヤー、共通部品、主要な処理フロー、命名ルールとコーディング規約、テスト規約、ビルドと環境設定、開発手順、開発チェックリスト | 開発に着手するとき、書き方や手順を確認するとき、既存の動きを調べるとき |

## 読み方

1. まず [システム知識整理](./999_標準化/システム知識整理.md) で全体像をつかむ。
2. 開発に着手するときは [プロジェクト構成とレイヤー別開発ガイド](./999_標準化/プロジェクト構成とレイヤー別開発ガイド.md) と [ネーミングルールとコーディング規約](./999_標準化/ネーミングルールとコーディング規約.md) を読んでからコードを書く。
3. 環境を立てて動かすときは [開発手順](./999_標準化/開発手順.md) に沿って進める。テストは [テスト規約](./999_標準化/テスト規約.md) に従って書く。
4. 提出前に [開発チェックリスト](./999_標準化/開発チェックリスト.md) を確認する。

## 記載の約束

- 文書は日本語（常体）で書く。コードの識別子（クラス名、ファイル名、ルート、設定キー）は原文のままバッククォートで囲む。
- 規則としては、このリポジトリのコード、テスト、lint とビルドの設定から読み取れた事実だけを記載する。「実測」と書いた数値は対象コミットのコードを機械的に数えた値であり、コードが変わると更新が必要である。
- 各文書の冒頭に対象とするコミットを記す。コードや設定を変えたときは、対応する文書を更新する。
- バックエンドの内部構造は別リポジトリ `jhipster-sample-app-backend` にあり、このディレクトリには含めない。フロントエンドが呼ぶ API の一覧は [システム知識整理](./999_標準化/システム知識整理.md) に記載がある。
- リポジトリルートの `README.md` は英語の概要（起動、ビルド、テスト）である。日本語での詳しい説明はこのディレクトリを参照すること。
