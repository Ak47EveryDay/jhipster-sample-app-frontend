### 3.8 銀行口座で確認した注意点

銀行口座（`bank-account`）で確認した事実である。ほかのエンティティや画面で同じかどうかは、各自がコードで確認すること。

### アプリ・DTO

- `filter.model.ts` は、共通部品 `Filter`（`jhi-filter`、`src/app/shared/filter/filter.ts`）から `IFilterOptions` として import されている（`_進捗.md` の「本体からの import はなし」とは異なる）。`Filter` を使っている画面（テンプレートの `<jhi-filter>`、`imports`）はない。
- `alert-error.model.ts` の `AlertErrorModel` は、イベント `jhipsterSampleApplicationApp.error` の内容の型として使われる。このイベントを配信する箇所は本体にない（配信しているのは `jhipsterSampleApplicationApp.httpError` だけである）。
- ユーザ管理の登録・編集（`src/app/entities/admin/user-management/update/user-management-update.ts`）: `save()` は `getUserManagement()` の戻り値の `id` が `null` のとき `create()` を呼ぶ。フォームの既定値に `id` はなく、`new` のルートでは `resetForm()` も呼ばれないため、コードからは新規のとき `id` は `undefined` になり `update()`（`PUT api/admin/users/{login}`）が呼ばれると読める。単体テストは `getUserManagement()` を `{ id: null, login: null }` に置き換えている。実行では確かめていない。ユーザ管理登録・編集の画面設計書を書く執筆者への共有が必要である。（【訂正】この読みは誤りである。`FormControl` のコンストラクターの第 1 引数の既定値は `null` であり、登録時の `id` は `null` になって `create()` が呼ばれる。ユーザ管理登録・編集_画面設計書の 5.6 参照）
- バックエンドに `PATCH /api/admin/users/{login}` と `PUT /api/authorities/{id}` はない。フロントエンドの `UserManagementService.partialUpdate()` に対応するバックエンドのエンドポイントはなく、本体からも呼ばれていない。
- バックエンドの `UserResource.createUser()` は `User`（エンティティ）を返す。フロントエンドは `IUserManagement` として受け取る。
- バックエンドの `LabelResource.getAllLabels()` と `getLabel()` は関連を一緒に読み込まない（`findAll()`、`findById()`）。`operations` が JSON に出るかどうかはコードからは確認できない。
- 管理系のモデル（configuration、health、log、metrics、profile-info）の対応先は Spring Boot Actuator と JHipster のライブラリーである。バックエンドの `src/main/java/` 配下に対応するクラスはなく、ライブラリーのクラス名とフィールド名はローカルの Maven リポジトリーの JAR（spring-boot-actuator 4.1.1、spring-boot-health 4.1.1、spring-boot 4.1.1、jhipster-framework 9.4.0）を `javap` で確認した。文書ではライブラリーのクラス名と、フロントエンドに宣言のないライブラリーのフィールド名（inputs、defaultProfiles、originParents、groups、FATAL）はバッククォートで囲まずに出典を添えた。
- 使われていない定義: `UsersService` の `usersParams`、`usersResource`、`users`（`src/app/entities/user/service/user.service.ts`）、`I18N_HASH`（`build-plugins/i18n-esbuild.ts` が定義し `src/declarations.d.ts` に型があるだけで参照なし）、`NewRestOperation`、`PartialUpdateRestOperation`、`NewRestUserManagement`、`PartialUpdateRestUserManagement`、`clearLocale()`。
- エラーアラートの経路: `AlertError` はエラー応答の本文を `problem-details.ts` の型を使わずに読む。本文の `params`（`ProblemWithMessage` では `string`）を `AlertModel` の `translationParams` に渡している。

### ラベル・取引

- ラベル一覧が送るクエリパラメーターは `sort` だけである（`eagerload` はない）。バックエンドの `LabelResource.getAllLabels()` は引数がない。
- ラベルの Operation 列（一覧・詳細）は `label.operations` の要素を取引詳細へのリンクとして描く。並び替えの対象は `id` と `label` の 2 列だけである。
- ラベルの `label` は `Validators.required` と `Validators.minLength(3)`（バックエンドは `@NotNull` と `@Size(min = 3)`）。
- ラベルの Operation は複数選択（`<select multiple>`）。選択肢は `GET api/operations` を引数なしで呼び、1 ページ分だけである。
- 取引一覧はページング（`size=20`）と無限スクロールがある。並び替えはバックエンド（`Pageable`）で、画面に `refineData()` はない。
- 取引一覧の Refresh list と削除後の `load()` は `reset()` を呼ばず、表示済みの行を置き換えない。
- 取引の関連は 2 つ（`bankAccount` は単一選択で空欄あり、`labels` は複数選択で空欄なし）。選択肢は `GET api/bank-accounts` と `GET api/labels` を引数なしで呼ぶ（どちらもページングなし）。
- 取引の `date` は `type="datetime-local"`。フォームの値は `YYYY-MM-DDTHH:mm` の文字列で、送信時に `toJSON()` で ISO 8601 にする。登録の初期値は現在時刻である。

### ユーザ管理・権限

- 2 つのエンティティは管理者用である。各ルートは `data: { authorities: ['ROLE_ADMIN'] }` と `canActivate: [userRouteAccessService]` を持つ。ログインしていても `ROLE_ADMIN` を持たなければ `router.navigate(['accessdenied'])` で `/accessdenied` へ遷移する。
- ナビゲーションバーでは「Administration」メニュー（`*jhiHasAnyAuthority="'ROLE_ADMIN'"`）の中に「User Management」（翻訳キー `userManagement.home.title`、英語は「Users」）と「Authority」（`global.menu.entities.adminAuthority`）がある。「Entities」メニューにはない。
- ユーザ管理の API は `api/admin/users`（バックエンドの `UserResource`。`/api/admin/**` は `ROLE_ADMIN` を要求）。`GET api/users`（`PublicUserResource`）はこの 2 つのエンティティからは呼ばない。
- ユーザ管理一覧はページング（20 件）と `X-Total-Count` がある。並び替えはバックエンド（`Pageable`）で、画面に `refineData()` はない。ルートの `data` に `defaultSort` はない。
- ユーザ管理一覧の行には有効・無効の切り替え（`setActive()`、`PUT api/admin/users/{login}`）がある。ログイン中のユーザー自身の行では「Activated」と「Delete」が無効。
- ユーザ管理登録・編集にパスワードの入力欄とバリデーショングループはない。グループ単位のバリデーターもない。
- 登録と編集の判定は `save()` の `userManagement.id === null` である。フォームサービスの既定値に `id` はないが、Angular の `FormControl` のコンストラクターの既定値（`formState = null`）により、登録では `id` は `null` になる（`node_modules/@angular/forms/fesm2022/forms.mjs` で確認）。
- 権限には編集のルートがない（`''`、`:name/view`、`new`）。`AuthorityUpdate.save()` は `create()` だけを呼ぶ。一覧に Edit ボタンはなく、Delete ボタンがある。詳細に Edit ボタンはない。
- ユーザ管理削除ダイアログの翻訳文のプレースホルダーは `{{ login }}` だが、テンプレートが渡す値は `id` である。
