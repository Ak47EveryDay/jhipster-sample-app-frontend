## 1. 概要

本文書は、画面に表示されるメッセージ（エラーメッセージ、入力チェックのメッセージ、成功・失敗の通知、確認のメッセージ）を一覧にしたものである。すべての記述は現在のコード（フロントエンドのコミット `570a360`、バックエンドのコミット `423e462`）に基づく。

- メッセージの文言は翻訳ファイル `src/i18n/en/*.json` に定義されている。アプリケーションが対応している言語は英語（`en`）だけである（`src/app/config/language.constants.ts` の `LANGUAGES`）。本書には英語の文言をそのまま載せる。
- 「メッセージID」は翻訳キーである。「PL / BL 区分」は、フロントエンドが判定するものを PL、バックエンドの応答によって表示されるものを BL とする。
- 文言の中の `<strong>` と `</strong>`（太字の指定）は省いて載せる。`<br/>` は `〈改行〉` と書き換える。
- 翻訳ファイルの文言の前後に空白があるとき、表ではそれが分からない。`activate.messages.success` と `reset.finish.messages.success` の文言は末尾に空白があり、画面ではその直後に「sign in」のリンクが続く（`src/app/account/activate/activate.html`、`src/app/account/password-reset/finish/password-reset-finish.html`）。

## 2. メッセージの出どころ

メッセージは次の 3 つの場所から出る。どの場所にも当てはまらない文言（ボタンのラベル、見出し、項目名など）はメッセージではないため、本文書では扱わない。それらは各画面設計書の「画面表示項目一覧」に載っている。

| 出どころ | 仕組み | 表示先 | 根拠 |
| --- | --- | --- | --- |
| 共通のエラーアラート | `errorHandlerInterceptor` が HTTP エラーをイベント `jhipsterSampleApplicationApp.httpError` として配信し、`AlertError` がステータスに応じた文言をアラートに追加する | 画面に置かれた `<jhi-alert-error />` | `src/app/core/interceptor/error-handler.interceptor.ts`、`src/app/shared/alert/alert-error.ts`（`handleHttpError()`） |
| 共通の成功通知 | `notificationInterceptor` がレスポンスヘッダーのアラートのキーを読み、成功のアラートを追加する | 画面に置かれた `<jhi-alert />` | `src/app/core/interceptor/notification.interceptor.ts` |
| 画面固有のメッセージ | 画面のコンポーネントがシグナル（`success`、`error` など）を `true` にし、テンプレートの `@if` で表示する | その画面の中 | 各画面の `.ts` と `.html` |

アラートの表示のされ方（種類、自動的に消えるまでの時間、閉じる操作）は [アラート_画面設計書](../02_画面設計/共通/アラート/アラート_画面設計書.md) を参照する。

## 3. 共通のエラーメッセージ（HTTP エラー）

`AlertError.handleHttpError()` が HTTP ステータスに応じて出すメッセージである。`<jhi-alert-error />` が置かれた画面で表示される。

| 番号 | エラー種別 | 発生事由 | メッセージID | メッセージ内容（英語） | クライアント側での処理 | PL / BL 区分 | 根拠 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 通信エラー | HTTP ステータス 0。サーバーに到達できない | `error.server.not.reachable` | Server not reachable | エラーアラートとして表示する | PL | `src/app/shared/alert/alert-error.ts`（`case 0`） |
| 2 | 404 エラー | HTTP ステータス 404 | `error.url.not.found` | Not found | エラーアラートとして表示する | PL | 同上（`case 404`） |
| 3 | バリデーションエラー（サーバー） | 400。レスポンスヘッダーにエラーのキーがあるか、本文に `fieldErrors` がある | `error.validation` | Validation error on the server. | 本文の `message` を翻訳キーとして表示する | BL | 同上（`handleBadRequest()`）、バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/errors/ExceptionTranslator.java` |
| 4 | 同時更新の競合 | 409 | `error.concurrencyFailure` | Another user modified this data at the same time as you. Your changes were rejected. | 本文の `message` を翻訳キーとして表示する（`handleDefaultError()`） | BL | 同上 |
| 5 | ログイン名が既に使われている | 400。ヘッダーのエラーキーが `userexists` | `error.userexists` | Login name already used! | エラーアラートとして表示する | BL | 同上（`handleBadRequest()`）、バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/errors/LoginAlreadyUsedException.java` |
| 6 | メールアドレスが既に使われている | 400。ヘッダーのエラーキーが `emailexists` | `error.emailexists` | Email is already in use! | エラーアラートとして表示する | BL | 同上、`EmailAlreadyUsedException.java` |
| 7 | 新規登録で ID が指定されていた | 400。ヘッダーのエラーキーが `idexists` | `error.idexists` | A new {{ entityName }} cannot already have an ID | エラーアラートとして表示する。`entityName` はヘッダー `params` の値を `global.menu.entities.<params>` で翻訳したもの | BL | 同上、バックエンドの各リソースの `create*()` |
| 8 | 更新で本文の ID がない | 400。ヘッダーのエラーキーが `idnull` | `error.idnull` | Invalid ID | エラーアラートとして表示する | BL | 同上、各リソースの `update*()` |
| 9 | 更新でパスと本文の ID が違う | 400。ヘッダーのエラーキーが `idinvalid` | `error.idinvalid` | Invalid ID | エラーアラートとして表示する | BL | 同上 |
| 10 | 更新で対象が存在しない | 400。ヘッダーのエラーキーが `idnotfound` | `error.idnotfound` | ID cannot be found | エラーアラートとして表示する | BL | 同上 |

- 400 のときは、レスポンスヘッダーの `X-jhipsterSampleApplicationApp-error` にエラーのキーがあればそれを、なければ本文の `message` を翻訳キーとして使う（`src/app/shared/alert/alert-error.ts` の `handleBadRequest()`）。
- ヘッダーのキーも本文の `message` も `error.<キー>` の形であり、上の表のメッセージID に対応する。
- 401 で URL に `api/account` を含むときは、`errorHandlerInterceptor` がイベントを配信しないため、何も表示されない（`src/app/core/interceptor/error-handler.interceptor.ts`）。
- 401 で URL に `api/account` を含まないときは、`authExpiredInterceptor` が `/login` へ遷移させる。このときエラーアラートは表示されない（遷移先の画面に `<jhi-alert-error />` がないため）。

- ログイン画面には入力チェックのメッセージはない。Username と Password に `Validators.required` があるが、エラーを表示するテンプレートの分岐はなく、未入力のままでも要求を送る（`src/app/login/login.html`、`src/app/login/login.ts`）。

- 現在のパスワード（Current password）が未入力のときは、新パスワード用の文言「Your password is required.」が表示される（`src/app/account/password/password.html` は `global.messages.validate.newpassword.required` を使う）。
