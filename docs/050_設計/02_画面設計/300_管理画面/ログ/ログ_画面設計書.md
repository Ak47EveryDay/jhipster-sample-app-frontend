## 2. 機能概要

- バックエンドのロガーの一覧を、ロガー名と有効なログレベルの組でテーブル形式で表示する。
- 表示するデータは `GET management/loggers` で取得する。応答の `loggers`（キーはロガー名）を、名前（`name`）と有効なレベル（`level`）を持つ `Log` の配列に変換して、シグナル `loggers` に持つ。
- 「Filter」のテキストボックスに文字を入力すると、ロガー名がその文字を含むロガーだけに絞り込む。大文字と小文字は区別しない。絞り込みは画面の中で行い、API は呼び直さない。
- Name 列と Level 列の見出しをクリックして並び替えられる。初期状態は Name の昇順である。並び替えの状態は URL に反映しない。
- 各行に TRACE、DEBUG、INFO、WARN、ERROR、OFF の 6 つのボタンがある。押すと `POST management/loggers/{name}` でそのロガーのレベルを変え、成功したら一覧を再取得する。現在の有効なレベルのボタンは色が付き、それ以外は `btn-light` になる。
- 「There are {{ total }} loggers.」にロガーの総数を表示する。総数は絞り込み前の件数である。
- 一覧を再取得するボタンはない。再取得するのはレベルの変更に成功したときだけである。
- HTTP エラーを表示する `<jhi-alert-error />` と、通知を表示する `<jhi-alert />` はない。
- 入力項目は絞り込みのテキストボックスだけである。チェックは [ログ_入力チェック一覧](./ログ_入力チェック一覧.md) に書く。

## 5. イベント処理

### 5.1 イベント一覧

| No. | イベント発生源 | イベント | 遷移先 | イベント物理名 |
| --- | --- | --- | --- | --- |
| 1 | 画面 | 初期化（画面を開いたとき。ロガーの一覧の取得） | なし | `ngOnInit()`（`findAndExtractLoggers()`） |
| 2 | Filter 入力欄 | 入力 | なし（一覧を絞り込む） | `(ngModelChange)="filter.set($event)"`、`filteredAndOrderedLoggers`（`computed`） |
| 3 | Name 見出し | クリック | なし（Name 列を並び替える） | `jhiSortBy="name"` |
| 4 | Level 見出し | クリック | なし（Level 列を並び替える） | `jhiSortBy="level"` |
| 5 | TRACE、DEBUG、INFO、WARN、ERROR、OFF のボタン | クリック | なし（レベルを変えて、一覧を再取得する） | `(click)="changeLevel(logger.name, 'TRACE')"` など |

### 5.2 イベント詳細

#### 5.2.1 画面初期化

- トリガー: `/admin/logs` への遷移。
- 処理手順:
  1. ルートガード `userRouteAccessService` が `AccountService.identity()` でアカウントを確認する。未ログインなら遷移前の URL を `StateStorageService.storeUrl()` で保存し、`/login` へ遷移してここで終わる。ログインしていても `data.authorities`（`Authority.ADMIN`）を持たなければ `router.navigate(['accessdenied'])` を実行し、この画面への遷移は完了しない。
  2. `ngOnInit()` が `findAndExtractLoggers()` を呼ぶ。
  3. `findAndExtractLoggers()` は `isLoading` を `true` にして、`logsService.findAll()` を購読する。`LogsService.findAll()` は `GET management/loggers` を送る。
  4. 成功（`next`）: `Object.entries(response.loggers)` でロガー名と設定の組を取り出し、`new Log(key, logger.effectiveLevel)` の配列にしてシグナル `loggers` に入れる。表示に使うのは有効なレベル（`effectiveLevel`）だけである。明示的に設定されたレベル（`configuredLevel`）と、設定できるレベルの一覧（`levels`）は使わない。
  5. 失敗（`error`）: `this.loggers.set([])` で空配列にする。
  6. 成功・失敗とも（`finalize`）: `isLoading` を `false` に戻す。
- 表示の切り替え: テンプレートの内容は `@defer (when loggers() && !isLoading())` の中にある。初回の応答が届くまでは `loggers()` が `undefined` であるためトリガーは偽で、初期表示のブロック（@placeholder）の指定がないので何も表示しない。応答が届いて `loggers()` に値が入り、`isLoading()` が `false` になると、トリガーが真になる。`@loading` のスピナーは、トリガーが真になったあとに `@defer` が依存を読み込む間に表示するブロックである。以上はコードから読める Angular の動きであり、実機では確認していない。
- 絞り込みと並び替えの実体: `filteredAndOrderedLoggers`（`computed`）が表示する行を決める。`loggers()`（`undefined` なら空配列）を `filter()` で絞り込み、`sortState()` に `order` と `predicate` があれば `sortService.startSort({ order, predicate }, { predicate: 'name', order: 'asc' })` で並び替える。テンプレートはこの値を行の繰り返しに使う。
- 状態変化: `loggers`、`isLoading`。
- 遷移: なし。

#### 5.2.2 Filter 入力欄への入力

- トリガー: `(ngModelChange)="filter.set($event)"`。
- 処理手順:
  1. 入力のたびに、シグナル `filter` が新しい文字列になる。
  2. `filteredAndOrderedLoggers`（`computed`）が再計算され、`logger.name` が入力文字列を含むロガーだけになる。両方とも `toLowerCase()` で小文字にして比較するため、大文字と小文字は区別しない。
  3. API は呼ばない。URL も変わらない。
- 件数の文言: 「There are {{ total }} loggers.」の `total` は `loggers()?.length` であり、絞り込み後も絞り込み前の件数のままである。
- 状態変化: `filter`、`filteredAndOrderedLoggers`（`computed`）。
- 遷移: なし。

#### 5.2.3 並び替え（Name、Level 見出しのクリック）

- トリガー: `jhiSortBy` を持つ `<th>` のクリック。`SortByDirective` はホスト要素の `(click)` で `onClick()` を呼ぶ。
- 処理手順:
  1. `SortByDirective.onClick()` が、`<th>` の中に `<fa-icon>` があるときに親の `SortDirective` の `sort(this.jhiSortBy())` を呼ぶ。
  2. `SortDirective.sort(field)` は、今の `predicate` と同じ列なら `order` を `asc` と `desc` で反転させ、別の列なら `asc` にする。`sortState` を更新し、`sortChange` に新しい状態を出す。この画面は `(sortChange)` を購読していない。
  3. `[(sortState)]="sortState"` により画面の `sortState` が変わり、`filteredAndOrderedLoggers`（`computed`）が再計算される。
  4. `SortByDirective` の `effect` は、`<th>` の中の `<fa-icon>` のアイコンを `sortState` に応じて切り替える（`asc` なら `faSortUp`、`desc` なら `faSortDown`）。
- Level 列の並び順: `SortService.startSort()` は項目の `level` の文字列を `Intl.Collator`（`numeric: true`、`sensitivity: 'base'`）で比較する。そのため Level 列で並び替えたときの順は、レベルを表す文字列の文字列順になる（コードから読める動きであり、実機では確認していない）。
- 予備の並び順: 並び替えの比較で等しいロガー同士は、Name の昇順に並ぶ。
- 状態変化: `sortState`、`filteredAndOrderedLoggers`（`computed`）。
- 遷移: なし。並び替えの状態を URL のクエリパラメーターに書き出す処理はない。

#### 5.2.4 レベルボタンのクリック（レベルの変更）

- トリガー: 行の中の TRACE、DEBUG、INFO、WARN、ERROR、OFF のいずれかのボタンのクリック（`(click)="changeLevel(logger.name, 'TRACE')"` など）。
- 処理手順:
  1. `changeLevel(name, level)` が `this.logsService.changeLevel(name, level)` を購読する。`LogsService.changeLevel()` は `POST management/loggers/{name}` を、本文 `{ configuredLevel }` で送る。
  2. 成功（`next`）: `this.findAndExtractLoggers()` を呼び、一覧を再取得する（5.2.1 の手順 3 から 6）。応答の本文は使わない。
  3. 再取得が済むと、シグナル `loggers` が新しい有効なレベルで置き換わり、行のボタンの色が変わる。
  4. 失敗: `error` の処理はない。一覧は再取得せず、画面は変わらない。エラーごとの扱いは [ログ_入力チェック一覧](./ログ_入力チェック一覧.md) の 4 章に書く。
- 確認と二重押し: レベルを変える前に確認のダイアログは出ない。要求中にボタンを無効にする指定もない。
- 絞り込みと並び替えの状態: 再取得のあともシグナル `filter` と `sortState` はそのままである。
- 再取得中の表示: 再取得の間は `isLoading()` が真になる。コードからは、表示済みの一覧は消えず、応答が届くと内容が差し替わると読める（`@defer` のトリガーは一度真になれば内容を表示し続ける。Angular の動きであり、実機では確認していない）。
- 状態変化: `loggers`、`isLoading`。
- 遷移: なし。

### 5.3 API呼び出し一覧

| No. | 目的 | メソッド | パス | 要求パラメーター | 応答 | 成功時 | エラー時 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | ロガーの一覧の取得 | GET | `management/loggers` | なし | 200: `LoggersResponse`（`levels`、`loggers`。`loggers` はロガー名をキーにした、`configuredLevel`（`null` のこともある）と `effectiveLevel` のオブジェクト） | シグナル `loggers` に `Log` の配列が入る | `loggers` は空配列になる。「There are 0 loggers.」と、行のない表になる |
| 2 | ロガーのレベルの変更 | POST | `management/loggers/{name}` | パスパラメーター `name`（ロガー名）。本文: `configuredLevel`（`TRACE`、`DEBUG`、`INFO`、`WARN`、`ERROR`、`OFF` のいずれか） | 204（本文なし） | 一覧の再取得 | 処理なし（再取得も、エラーの表示もなし） |

補足:

- 呼び出し元は `LogsService.findAll()` と `LogsService.changeLevel()`（`src/app/admin/logs/logs.service.ts`）である。URL は `${serverApiUrl}management/loggers` と `${serverApiUrl}management/loggers/${name}` で、`serverApiUrl` はビルド時定数 `SERVER_API_URL` である（`src/app/config/endpoint.constants.ts`）。No. 1 にクエリパラメーターと本文はない。
- 型の定義は `src/app/admin/logs/log.model.ts` の `Level`、`Logger`、`LoggersResponse`、`Log` である。詳細は [log_DTO設計書](../../../03_IF設計/01_DTO設計書/log_DTO設計書.md) に書く。
- バックエンドの公開設定（バックエンドの `src/main/resources/config/application.yml`）: `management.endpoints.web.base-path` は `/management` で、`management.endpoints.web.exposure.include` に `loggers` が含まれる。
- バックエンドの認可（バックエンドの `src/main/java/io/github/jhipster/sample/config/SecurityConfiguration.java`）: `/management/**` は `AuthoritiesConstants.ADMIN`（`ROLE_ADMIN`）を持つことを要求する。
- サーバー側の実装: `management/loggers` は Spring Boot Actuator（ライブラリー）のエンドポイントであり、バックエンドのリポジトリにソースはない。読み取りは、設定できるレベルの一覧と、ロガーごとの設定済みのレベルと有効なレベルを返す。書き込みはロガー名とレベルを受け取り、実行中のアプリケーションのログシステムのレベルを設定する。書き込みの結果はなく、204 になる。以上はライブラリーの動きであり、本リポジトリのコードではない。
- レベルの変更の範囲: 変更は実行中のアプリケーションに対するものである。設定ファイル（バックエンドの `src/main/resources/logback-spring.xml`、バックエンドの `application-dev.yml` の `logging.level` など）を書き換える処理はコード上にない。
- ロガーの初期状態: どのロガーが一覧に現れ、どのレベルになるかはバックエンドのログ設定による（バックエンドの `src/main/resources/logback-spring.xml` の `logger` 要素と `root` 要素、バックエンドの `application-dev.yml` と `application-prod.yml` の `logging.level`）。この画面は初期値を持たない。
- ロガー名: `changeLevel()` はロガー名を URL エンコードせずにパスに入れる。URL に使えない文字を含むロガー名がある場合の動作は、コードからは確認できない。
- 要求ヘッダーは `authInterceptor` が `Authorization: Bearer <トークン>` を付ける（トークンがあるとき）。
- エラー時の共通の動きは次のとおりである。共通部品の詳細は [HTTP共通処理_画面設計書](../../共通/HTTP共通処理/HTTP共通処理_画面設計書.md) に書く。
  - 401 のときは `authExpiredInterceptor` が現在の URL を `StateStorageService.storeUrl()` で保存し、ログアウトして `/login` へ遷移する。
  - テンプレートに `<jhi-alert-error />` がないため、HTTP エラーを画面に表示する仕組みはない。`errorHandlerInterceptor` はイベント `jhipsterSampleApplicationApp.httpError` を配信するが、この画面にはそれを購読する部品がない。
