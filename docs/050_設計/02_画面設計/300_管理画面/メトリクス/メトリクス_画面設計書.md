## 2. 機能概要

- バックエンドのメトリクス（JVM のメモリー、スレッド、ガベージコレクション、HTTP リクエスト、キャッシュ、データソース、プロセスとシステム）を表示する画面である。
- 表示するデータは `GET management/jhimetrics` と `GET management/threaddump` で取得する。画面を開いたときと「Refresh」ボタンのクリックで、2 つを同時に送る。
- API を呼ぶのは画面のコンポーネント `Metrics` だけである。表示の各部分は 9 部品（画面に並べる 8 部品と、スレッドダンプのモーダルダイアログ 1 部品）に分かれており、どの部品も自分で API を呼ばない。画面が取得した値を `input` で受けて表示する。
- 取得の間は「Updating...」の情報アラートを出す。再取得の間は、部品ごとに表を隠すか、部品ごと消すかして、応答が届くと新しい値で表示し直す。
- スレッドブロックの「Expand」ボタンでスレッドダンプダイアログを開く。ダイアログではスレッドを状態で絞り込み、スレッドごとのスタックトレースを開ける。
- HTTP エラーを表示する `<jhi-alert-error />` と、通知を表示する `<jhi-alert />` はない。
- 入力項目はない。この画面に `入力チェック一覧` はない。

## 3. 画面レイアウト

画面は `Main` の `<router-outlet />` の中、`<div class="card jh-card">` の内側に表示される（`src/app/layouts/main/main.html`）。テンプレートのルートは `<div>` 1 つで、その中を上から順に次の領域が占める。

```
見出し領域（<h2>）
    Application Metrics
    [Refresh]
JVMメトリクス見出し領域（<h3 jhiTranslate="metrics.jvm.title">）
    JVM Metrics
上段領域（<div class="row">）              … metrics() があり、updatingMetrics() が偽のとき
    [メモリーブロック] [スレッドブロック] [システムブロック]
ガベージコレクションブロック領域            … metricsRef?.garbageCollector があるとき
    Garbage collections
更新中表示領域（<div class="alert alert-info" jhiTranslate="metrics.updating">）   … updatingMetrics() が真のとき
    Updating...
HTTPリクエストブロック領域                  … metricsRef?.['http.server.requests'] があるとき
    HTTP requests (time in milliseconds)
エンドポイントリクエストブロック領域         … metricsRef?.services があるとき
    Endpoints requests (time in milliseconds)
キャッシュブロック領域                      … metricsRef?.cache があるとき
    Cache statistics
データソースブロック領域                    … metricsRef.databases が空でないオブジェクトのとき
    DataSource statistics (time in milliseconds)
```

スレッドダンプダイアログ（`MetricsModalThreads`）はルートを持たず、画面の上に開く。ダイアログの中を上から順に次の領域が占める。

```
スレッドダンプダイアログ見出し領域（<div class="modal-header">）
    Threads dump   [×]
スレッドダンプダイアログ本文領域（<div class="modal-body">）
    [All <数>] [Runnable <数>] [Waiting <数>] [Timed Waiting <数>] [Blocked <数>]
    <状態のバッジ> <スレッド名> (ID <スレッド ID>)   Show Stacktrace / Hide Stacktrace
    <スタックトレース>                     … 開いたときだけ
    Threads dump: <スレッド名>
    Blocked Time | Blocked Count | Waited Time | Waited Count | Lock name
スレッドダンプダイアログボタン領域（<div class="modal-footer">）
    [Done]
```

### メモリーブロック領域

部品は `JvmMemory`（`src/app/admin/metrics/blocks/jvm-memory/jvm-memory.ts`、セレクター `jhi-jvm-memory`）である。

- 要求: なし。画面が `GET management/jhimetrics` で取得した値のうち `jvm` を、`input` の `jvmMemoryMetrics` で受け取る。

### スレッドブロック領域

部品は `JvmThreads`（`src/app/admin/metrics/blocks/jvm-threads/jvm-threads.ts`、セレクター `jhi-jvm-threads`）である。

- 要求: なし。画面が `GET management/threaddump` で取得したスレッドの配列（シグナル `threads`）を、`input` の `threads` で受け取る。

- 表示: 4 つの状態それぞれの数と合計に対する割合のプログレスバー、合計数、Expand ボタン。
- 更新: `updating` の `input` はない。部品は上段領域の中にあるため、再取得の間は部品ごと表示されない。応答が届くと新しい `threads()` で作り直される。

## 5. イベント処理

### 5.1 イベント一覧

| No. | イベント発生源 | イベント | 遷移先 | イベント物理名 |
| --- | --- | --- | --- | --- |
| 1 | 画面 | 初期化（画面を開いたとき。メトリクスとスレッドダンプの取得） | なし | `ngOnInit()`（`refresh()`） |
| 2 | Refresh ボタン | クリック | なし（メトリクスとスレッドダンプを再取得する） | `refresh()` |
| 3 | Expand ボタン（スレッドブロック） | クリック | なし（スレッドダンプダイアログを開く） | `open()`（`JvmThreads`） |
| 4 | スレッドダンプダイアログの All、Runnable、Waiting、Timed Waiting、Blocked のボタン | クリック | なし（スレッドを状態で絞り込む） | `(click)="threadStateFilter = undefined"` など、`getThreads()` |
| 5 | スレッドダンプダイアログの Show Stacktrace、Hide Stacktrace のリンク | クリック | なし（スタックトレースの表示を切り替える） | `(click)="thread.showThreadDump = !thread.showThreadDump"` |
| 6 | スレッドダンプダイアログの閉じるボタン、Done | クリック | なし（スレッドダンプダイアログを閉じる） | `dismiss()` |

### 5.2 イベント詳細

#### 5.2.1 画面初期化

- トリガー: `/admin/metrics` への遷移。
- 処理手順:
  1. ルートガード `userRouteAccessService` が `AccountService.identity()` でアカウントを確認する。未ログインなら遷移前の URL を `StateStorageService.storeUrl()` で保存し、`/login` へ遷移してここで終わる。ログインしていても `data.authorities`（`Authority.ADMIN`）を持たなければ `router.navigate(['accessdenied'])` を実行し、この画面への遷移は完了しない。
  2. `ngOnInit()` が `this.refresh()` を呼ぶ。
  3. `refresh()` は `updatingMetrics` を `true` にする（初期値も `true` である）。
  4. `combineLatest([this.metricsService.getMetrics(), this.metricsService.threadDump()])` を購読する。`MetricsService.getMetrics()` は `GET management/jhimetrics`、`MetricsService.threadDump()` は `GET management/threaddump` を送る。
  5. 2 つの要求がともに応答を返すと、`combineLatest` が両方の値を渡す。`next` でシグナル `metrics` にメトリクス、シグナル `threads` に `threadDump.threads` を入れ、`updatingMetrics` を `false` にする。
  6. 応答が届くまでは `metrics()` が `undefined` で `updatingMetrics()` が真であるため、画面には見出し、Refresh ボタン、「JVM Metrics」の小見出し、「Updating...」だけが表示される。応答が届くとブロック部品が表示される。
- ブロック部品への値の渡し方: 画面は `@let metricsRef = metrics();` で応答を取り出し、各ブロック部品の `input` に渡す（例: `[jvmMemoryMetrics]="metricsRef.jvm"`）。どの部品も自分で API を呼ばない（4 章の各部品の「要求」）。
- 失敗: `subscribe` に `error` の処理はない。`combineLatest` はどちらかの Observable が失敗すると値を出さなくなるため（RxJS の動きであり、本リポジトリのコードではない）、シグナル `metrics` と `threads` は前の値のまま、`updatingMetrics` は `true` のままである。初回に失敗した場合は、コードからは「Updating...」が消えず、ブロック部品は表示されないと読める。
- 状態変化: `metrics`、`threads`、`updatingMetrics`。
- 遷移: なし。

#### 5.2.2 Refresh ボタンクリック

- トリガー: `(click)="refresh()"`。ボタンを無効にする指定はなく、連続して押せる。
- 処理手順: 5.2.1 の手順 3 から 5 と同じである。
- 再取得中の表示（`updatingMetrics()` が真の間）:
  - 上段領域（メモリー、スレッド、システムの 3 部品）は表示しない。
  - 「Updating...」の情報アラートを表示する。
  - ガベージコレクションブロックは 3 つの列を表示し続け、`jvm.gc.pause` の統計表は表示しない。
  - HTTPリクエスト、エンドポイントリクエスト、キャッシュ、データソースの各ブロックは、見出しを表示し続け、表は表示しない。
  - 応答が届くと、各部品は新しい値で表示し直す。
- 状態変化: `metrics`、`threads`、`updatingMetrics`。
- 遷移: なし。

#### 5.2.3 Expand ボタンクリック（スレッドダンプダイアログを開く）

- トリガー: スレッドブロックの `(click)="open()"`。
- 処理手順:
  1. `JvmThreads.open()` が `this.modalService.open(MetricsModalThreads)` でスレッドダンプダイアログを開く。サイズと `backdrop` の指定はない（ng-bootstrap の既定になる）。
  2. `modalRef.componentInstance.threads = this.threads()` で、画面が持つスレッドの配列をダイアログのプロパティー `threads` に渡す。
  3. `MetricsModalThreads` の `ngOnInit()` が、スレッドブロックと同じ 4 つの状態の数を数え、`threadDumpAll` をその合計にする。
  4. ダイアログは API を呼ばない。開いた時点のスレッドの配列をそのまま表示する。
- 状態変化: ダイアログのプロパティー `threads` と、4 つの状態の件数。画面のシグナルは変わらない。
- 遷移: なし。

#### 5.2.4 スレッドダンプダイアログでの絞り込みとスタックトレースの表示

- トリガー: All、Runnable、Waiting、Timed Waiting、Blocked のボタン、または Show Stacktrace、Hide Stacktrace のリンクのクリック。
- 処理手順:
  1. 状態のボタンを押すと、`threadStateFilter` に `undefined`（All のとき）または `ThreadState` の値が入る。
  2. `getThreads()` が `threadStateFilter` に一致するスレッドだけを返す。`undefined` ならすべてのスレッドを返す。`@for (thread of getThreads(); track $index)` がこの値でスレッドごとのブロックを描く。
  3. 選択中のボタンには `<fa-icon icon="check" />` が付く。
  4. Show Stacktrace のリンクを押すと、`thread.showThreadDump` が反転する。真ならスタックトレース（`thread.stackTrace`）をカードに表示し、リンクの文言は「Hide Stacktrace」になる。偽ならスタックトレースを隠し、文言は「Show Stacktrace」になる。
- `showThreadDump`: モデルの `Thread` に、スタックトレースの表示の切り替えのための画面側の項目として定義している（コメント「custom field for showing-hiding thread dump」）。バックエンドの応答に入る項目ではない。
- 状態変化: ダイアログの `threadStateFilter`、各スレッドの `showThreadDump`。
- 遷移: なし。

#### 5.2.5 スレッドダンプダイアログを閉じる

- トリガー: 閉じるボタン（`(click)="dismiss()"`）または Done ボタン（`(click)="dismiss()"`）。
- 処理手順: `dismiss()` は `this.activeModal.dismiss()` を呼ぶ。`JvmThreads` は `modalRef.closed` を購読していないため、閉じたあとに再取得などはしない。
- 状態変化: ダイアログが閉じる。
- 遷移: なし。

### 5.3 API呼び出し一覧

| No. | 目的 | メソッド | パス | 要求パラメーター | 応答 | 成功時 | エラー時 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | メトリクスの取得 | GET | `management/jhimetrics` | なし | 200: `MetricsModel`（`jvm`、`databases`、`http.server.requests`、`cache`、`garbageCollector`、`services`、`processMetrics`） | シグナル `metrics` に応答が入る（No. 2 の応答が揃ったとき） | 処理なし。`updatingMetrics` は `true` のままで、「Updating...」が消えたまま |
| 2 | スレッドダンプの取得 | GET | `management/threaddump` | なし | 200: `ThreadDump`（`threads`。スレッドごとの名前、ID、状態、スタックトレースなど） | シグナル `threads` に `threads` の配列が入る（No. 1 の応答が揃ったとき） | No. 1 に同じ |

補足:

- 呼び出し元は `MetricsService.getMetrics()` と `MetricsService.threadDump()`（`src/app/admin/metrics/metrics.service.ts`）である。URL は `${serverApiUrl}management/jhimetrics` と `${serverApiUrl}management/threaddump` で、`serverApiUrl` はビルド時定数 `SERVER_API_URL` である（`src/app/config/endpoint.constants.ts`）。クエリパラメーターと本文はない。
- 2 つの要求の関係: 画面は 2 つの Observable を `combineLatest` に渡して購読する。2 つの値が揃って初めて、画面のシグナルが更新される。画面が開いたときと Refresh のたびに、2 つを同時に送る。自動的な再取得（一定時間ごとの更新）はない。
- 型の定義は `src/app/admin/metrics/metrics.model.ts` の `MetricsModel`、`JvmMetrics`、`Databases`、`HttpServerRequests`、`CacheMetrics`、`GarbageCollector`、`Services`、`ProcessMetrics`、`ThreadDump`、`Thread` などである。詳細は [metrics_DTO設計書](../../../03_IF設計/01_DTO設計書/metrics_DTO設計書.md) に書く。
- バックエンドの公開設定（バックエンドの `src/main/resources/config/application.yml`）: `management.endpoints.web.base-path` は `/management` で、`management.endpoints.web.exposure.include` に `jhimetrics` と `threaddump` が含まれる。`management.endpoint.jhimetrics.access` は `read-only` である。
- バックエンドの認可（バックエンドの `src/main/java/io/github/jhipster/sample/config/SecurityConfiguration.java`）: `/management/**` は `AuthoritiesConstants.ADMIN`（`ROLE_ADMIN`）を持つことを要求する。
- サーバー側の実装: `jhimetrics` は JHipster フレームワーク（ライブラリー）、`threaddump` は Spring Boot Actuator（ライブラリー）のエンドポイントである。バックエンドのリポジトリにソースはない。`jhimetrics` の応答の形は、本リポジトリのコードからはフロントエンドのモデル `MetricsModel` に依拠する。モデルの最上位の 7 つのキー（`jvm`、`processMetrics`、`garbageCollector`、`http.server.requests`、`services`、`cache`、`databases`）が、そのままブロック部品の `input` に渡る。
- 数値の書式: 小数を含む値は `DecimalPipe` で表示し、小数部の桁数は指定ごとに 0 〜 4 桁である（`number: '1.0-0'` から `number: '1.0-4'` まで）。件数などはそのまま表示する。メモリー量はバイトを 1048576 で割った値に「M」を付ける。時間は見出しの文言のとおりミリ秒である。`filterNaN()`（`src/app/core/util/operators.ts`）は `NaN` を 0 に置き換える。
- プログレスバー: `ngb-progressbar` は ng-bootstrap の部品である。すべてのバーに `[striped]="true"` と `[animated]="false"` を指定している。`[max]` を指定しないバーは ng-bootstrap の既定値を使う（本リポジトリのコードではない）。
- 翻訳キー: `src/i18n/en/metrics.json` には、テンプレートが使わない翻訳キーもある（例: `metrics.jvm.memory.heap`、`metrics.jvm.threads.all`、`metrics.servicesstats.title`）。この画面は 4 章に挙げたキーだけを使う。
- 要求ヘッダーは `authInterceptor` が `Authorization: Bearer <トークン>` を付ける（トークンがあるとき）。
- エラー時の共通の動きは次のとおりである。共通部品の詳細は [HTTP共通処理_画面設計書](../../共通/HTTP共通処理/HTTP共通処理_画面設計書.md) に書く。
  - 401 のときは `authExpiredInterceptor` が現在の URL を `StateStorageService.storeUrl()` で保存し、ログアウトして `/login` へ遷移する。
  - 購読に `error` の処理はなく、テンプレートに `<jhi-alert-error />` もないため、HTTP エラーを画面に表示する仕組みはない。`errorHandlerInterceptor` はイベント `jhipsterSampleApplicationApp.httpError` を配信するが、この画面にはそれを購読する部品がない。
