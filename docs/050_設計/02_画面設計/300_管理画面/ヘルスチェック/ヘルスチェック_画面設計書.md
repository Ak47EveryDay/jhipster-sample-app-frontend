## 2. 機能概要

- バックエンドのヘルスチェックの結果（コンポーネントごとの状態）をテーブル形式で表示する。
- 表示するデータは `GET management/health` で取得する。画面を開いたときと「Refresh」ボタンのクリックで取得する。
- 応答の `components`（キーはコンポーネント名、値は状態 `status` と詳細 `details`）を 1 行 1 コンポーネントで表示する。応答の最上位の `status`（全体の状態）は画面に出さない。
- 状態はバッジで示す。`UP` は緑（`bg-success`）、それ以外（`DOWN`、`UNKNOWN`、`OUT_OF_SERVICE`）は赤（`bg-danger`）である（Bootstrap のクラスによる）。
- バックエンドは全体の状態が `DOWN` または `OUT_OF_SERVICE` のときに 503 を返す（Spring Boot Actuator の既定の動き）。画面は 503 のときも応答の本文を表示する。
- 「Details」列の目のアイコンをクリックすると、そのコンポーネントの詳細（`details`）をモーダルダイアログに表示する。`details` を持たないコンポーネントには目のアイコンを出さない。
- HTTP エラーを表示する `<jhi-alert-error />` と、通知を表示する `<jhi-alert />` はない。
- 入力項目はない。この画面に `入力チェック一覧` はない。

## 3. 画面レイアウト

画面は `Main` の `<router-outlet />` の中、`<div class="card jh-card">` の内側に表示される（`src/app/layouts/main/main.html`）。テンプレートのルートは `<div>` 1 つで、その中を上から順に次の領域が占める。

```
見出し領域（<h2>）
    Health Checks
    [Refresh]
ヘルスチェックテーブル領域・ヘッダー行（`id="healthCheck"` の <table>）
    Service name | Status | Details
ヘルスチェックテーブル領域・データ行   … health() が null でないとき
    <コンポーネント名> | <状態のバッジ> | <目のアイコン>   … details があるときだけ
```

詳細のダイアログ（`HealthModal`）はルートを持たず、画面の上に開く。ダイアログの中を上から順に次の領域が占める。

```
詳細ダイアログ見出し領域（<div class="modal-header">）
    <コンポーネント名>   [×]
詳細ダイアログ本文領域（<div class="modal-body pad">）
    Properties
    テーブル: Name | Value
詳細ダイアログボタン領域（<div class="modal-footer">）
    [Done]
```

## 5. イベント処理

### 5.1 イベント一覧

| No. | イベント発生源 | イベント | 遷移先 | イベント物理名 |
| --- | --- | --- | --- | --- |
| 1 | 画面 | 初期化（画面を開いたとき。ヘルスチェックの取得） | なし | `ngOnInit()`（`refresh()`） |
| 2 | Refresh ボタン | クリック | なし（ヘルスチェックを再取得する） | `refresh()` |
| 3 | Details の目のアイコン | クリック | なし（詳細ダイアログを開く） | `(click)="showHealth({ key: componentHealth.key, value: componentHealth.value })"` |
| 4 | 詳細ダイアログの Close、Done | クリック | なし（詳細ダイアログを閉じる） | `dismiss()` |

### 5.2 イベント詳細

#### 5.2.1 画面初期化

- トリガー: `/admin/health` への遷移。
- 処理手順:
  1. ルートガード `userRouteAccessService` が `AccountService.identity()` でアカウントを確認する。未ログインなら遷移前の URL を `StateStorageService.storeUrl()` で保存し、`/login` へ遷移してここで終わる。ログインしていても `data.authorities`（`Authority.ADMIN`）を持たなければ `router.navigate(['accessdenied'])` を実行し、この画面への遷移は完了しない。
  2. `ngOnInit()` が `this.refresh()` を呼ぶ。
  3. `refresh()` は `this.healthService.checkHealth()` を購読する。`HealthService.checkHealth()` は `GET management/health` を送る。
  4. 成功（`next`）: `this.health.set(health)` で、応答の `HealthModel` をシグナル `health` に入れる。テンプレートの `@if (health(); as health)` が真になり、`<tbody>` が表示される。
  5. 失敗で `error.status` が 503: `this.health.set(error.error)` で、エラーの本文（バックエンドの応答の JSON）を同じくシグナル `health` に入れる。手順 4 と同じ形で表示する。
  6. 失敗で 503 以外: 何もしない。シグナル `health` は前の値のままである。
- 503 の扱い: バックエンドの Spring Boot Actuator（ライブラリー）は、状態 `DOWN` と `OUT_OF_SERVICE` を HTTP ステータス 503 に対応付ける。これはライブラリーの既定の対応であり、バックエンドの設定に対応を変える記述はない。Angular の `HttpClient` は 2xx 以外をエラーとして扱うため（Angular の動きであり、本リポジトリのコードではない）、この場合は `error` に入る。画面は 503 のときだけエラーの本文を表示に使う。以上はコードから読める動きであり、実機では確認していない。
- 初期表示: 応答が届くまでは `health()` は `null` であるため、`<tbody>` はなく、見出し、Refresh ボタン、ヘッダー行だけが表示される。読み込み中を示す表示はない。
- 行の内容: `health.components` を `KeyValuePipe` に通して、コンポーネントごとに 1 行を描く。並び順は `KeyValuePipe` の既定の動きである（Angular の動きであり、本リポジトリのコードではない）。この画面に並び替えの指定はない。
- コンポーネント名: 翻訳キーは `health.indicator.` にコンポーネントのキーを連ねたものである。`src/i18n/en/health.json` には `diskSpace`（「Disk space」）、`ssl`（「SSL」）、`mail`（「Email」）、`livenessState`（「Liveness state」）、`readinessState`（「Readiness state」）、`ping`（「Application」）、`db`（「Database」）の 7 つがある。テンプレートには同じ 7 キーの文言の対応が直接書いてあるが、`jhiTranslate` は要素の内容を翻訳結果で置き換える。そのため、7 つにないキーが現れたときは、`MissingTranslationHandlerImpl` が作る、翻訳キーがない旨の文言（`translationNotFoundMessage` の値 `translation-not-found` にキーを括弧で添えたもの）になるとコードからは読める（`src/app/shared/language/translate.directive.ts`、`src/app/config/translation.config.ts`）。翻訳の仕組みは [国際化_画面設計書](../../共通/国際化/国際化_画面設計書.md) に書く。
- 現れるコンポーネント: 実行時にどのコンポーネントが応答に含まれるかはバックエンドの設定と実行環境による。設定から読めるのは、メールのヘルスチェックが無効であることと、liveness と readiness のプローブが有効であることまでである（5.3 の補足）。
- 状態変化: `health`。
- 遷移: なし。

#### 5.2.2 Refresh ボタンクリック

- トリガー: `(click)="refresh()"`。ボタンを無効にする指定はなく、連続して押せる。
- 処理手順: 5.2.1 の手順 3 から 6 と同じである。
- 状態変化: `health`。
- 遷移: なし。

#### 5.2.3 Details の目のアイコンクリック（詳細ダイアログを開く）

- トリガー: `(click)="showHealth({ key: componentHealth.key, value: componentHealth.value })"`。
- 処理手順:
  1. `showHealth()` が `this.modalService.open(HealthModal)` で詳細ダイアログを開く。サイズと `backdrop` の指定はない（ng-bootstrap の既定になる）。
  2. `modalRef.componentInstance.health = health` で、コンポーネントのキーと状態・詳細（`HealthDetails`）をダイアログのプロパティー `health` に渡す。
  3. `HealthModal` のテンプレートは `@if (health)` の中身を表示する。`health.value.details` を `KeyValuePipe` に通した各要素を、Name と Value の 1 行にする。
  4. ダイアログは API を呼ばない。開いたときに画面が持っていた `details` をそのまま表示する。
- `HealthModal.readableValue(value)` の変換: コンポーネントが `diskSpace` のときは、値を 1073741824 で割った値が 1 より大きければ小数 2 桁に「GB」を付けて返す。そうでなければ 1048576 で割った値に小数 2 桁で「MB」を付ける。コンポーネントが `diskSpace` 以外のときは、オブジェクトなら `JSON.stringify()` の結果、それ以外なら `String()` の結果を返す。
- 表示される詳細: `details` の内容（名前と値）はコンポーネントごとに異なり、バックエンドの応答による。この画面は内容を固定していない。
- 状態変化: ダイアログのプロパティー `health` に値が入る。画面のシグナル `health` は変わらない。
- 遷移: なし。

#### 5.2.4 詳細ダイアログを閉じる

- トリガー: Close ボタン（`(click)="dismiss()"`）または Done ボタン（`(click)="dismiss()"`）。
- 処理手順: `dismiss()` は `this.activeModal.dismiss()` を呼ぶ。画面 `Health` は `modalRef.closed` を購読していないため、閉じたあとに再取得などはしない。
- 状態変化: ダイアログが閉じる。
- 遷移: なし。

### 5.3 API呼び出し一覧

| No. | 目的 | メソッド | パス | 要求パラメーター | 応答 | 成功時 | エラー時 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | ヘルスチェックの取得 | GET | `management/health` | なし | 200: `HealthModel`（`status`、`components`。各コンポーネントは `status` と `details`）。全体の状態が `DOWN`、`OUT_OF_SERVICE` のときは 503 で同じ形の本文 | シグナル `health` に応答本文が入る | 503 のときはエラーの本文を `health` に入れて表示。503 以外の失敗は処理なし |

補足:

- 呼び出し元は `HealthService.checkHealth()`（`src/app/admin/health/health.service.ts`）である。URL は `${serverApiUrl}management/health` で、`serverApiUrl` はビルド時定数 `SERVER_API_URL` である（`src/app/config/endpoint.constants.ts`）。クエリパラメーターと本文はない。
- 型の定義は `src/app/admin/health/health.model.ts` の `HealthStatus`、`HealthKey`、`HealthModel`、`HealthDetails` である。詳細は [health_DTO設計書](../../../03_IF設計/01_DTO設計書/health_DTO設計書.md) に書く。
- バックエンドの公開設定（バックエンドの `src/main/resources/config/application.yml`）は次のとおりである。
  - `management.endpoints.web.exposure.include` に `health` が含まれる。
  - `management.endpoint.health.show-details` は `when_authorized`、`management.endpoint.health.roles` は `ROLE_ADMIN` である。詳細（`details`）を表示できる権限を `ROLE_ADMIN` に限める設定である。
  - `management.endpoint.health.probes.enabled` は `true` である。グループ `liveness`（`livenessState`）と `readiness`（`readinessState`、`db`）が定義されている。
  - `management.health.mail.enabled` は `false` である。メールのヘルスチェックは無効である。
- バックエンドの認可（バックエンドの `src/main/java/io/github/jhipster/sample/config/SecurityConfiguration.java`）: `/management/health` と `/management/health/**` は `permitAll()` である。バックエンドはこのパスに認証を要求しない。画面を開けるかどうかは、フロントエンドのルートガード（`ROLE_ADMIN`）だけで決まる。
- 詳細の有無: 要求には `authInterceptor` がトークンを付けるため、コードからは `ROLE_ADMIN` のユーザーが開いたときは `details` を持つ応答になり、目のアイコンが表示されると読める。トークンを付けないで呼んだ場合に `details` が省かれるかどうかはライブラリーの動きであり、実機では確認していない。
- サーバー側の実装: `GET management/health` は Spring Boot Actuator（ライブラリー）のエンドポイントであり、バックエンドのリポジトリにソースはない。
- 要求ヘッダーは `authInterceptor` が `Authorization: Bearer <トークン>` を付ける（トークンがあるとき）。
- エラー時の共通の動きは次のとおりである。共通部品の詳細は [HTTP共通処理_画面設計書](../../共通/HTTP共通処理/HTTP共通処理_画面設計書.md) に書く。
  - 401 のときは `authExpiredInterceptor` が現在の URL を `StateStorageService.storeUrl()` で保存し、ログアウトして `/login` へ遷移する。
  - 購読の `error` の処理は 503 の場合だけである。テンプレートに `<jhi-alert-error />` がないため、HTTP エラーを画面に表示する仕組みはない。`errorHandlerInterceptor` はイベント `jhipsterSampleApplicationApp.httpError` を配信するが、この画面にはそれを購読する部品がない。

### 5.4 画面遷移

| 遷移先 | 条件 | トリガー |
| --- | --- | --- |
| 詳細ダイアログ（遷移しない） | `details` を持つコンポーネントの目のアイコンを押した | `showHealth()` |
| ログイン（`/login`） | 未ログインのままこの画面を開いた | `userRouteAccessService`（遷移前の URL を `StateStorageService.storeUrl()` で保存してから遷移する） |
| アクセス拒否画面（`/accessdenied`） | ログインしているが `ROLE_ADMIN` を持たないユーザー | `userRouteAccessService`（`router.navigate(['accessdenied'])`） |
| ログイン（`/login`） | `GET management/health` が 401 を返した | `authExpiredInterceptor` |
