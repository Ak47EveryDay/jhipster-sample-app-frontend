## 2. 機能概要

- バックエンドの設定値を 2 種類の表で表示する。1 つは Spring の構成プロパティー（接頭辞 `prefix` ごとのプロパティーのまとまり）で、もう 1 つはプロパティーソースごとのプロパティーと値である。
- 表示するデータは `GET management/configprops` と `GET management/env` で取得する。2 つは画面の初期化で別々に呼ぶ。
- `GET management/configprops` の応答が届くまでは、見出しを含めて何も表示しない。
- 「Filter (by prefix)」のテキストボックスに文字を入力すると、接頭辞（`prefix`）がその文字を含む構成プロパティーだけに絞り込む。大文字と小文字は区別しない。絞り込みは画面の中で行い、API は呼び直さない。
- Prefix 列の見出しをクリックすると、昇順と降順を切り替えられる。初期状態は Prefix の昇順である。Properties 列は並び替えできない。並び替えの状態は URL に反映しない。
- プロパティーソースの表は絞り込まない。`GET management/env` の応答の `propertySources` の並びのまま、すべて表示する。
- 再取得のボタンはない。値を更新するには画面を読み込み直すことになる。
- HTTP エラーを表示する `<jhi-alert-error />` と、通知を表示する `<jhi-alert />` はない。
- 入力項目は絞り込みのテキストボックスだけである。チェックは [アプリケーション設定_入力チェック一覧](./アプリケーション設定_入力チェック一覧.md) に書く。

## 3. 画面レイアウト

画面は `Main` の `<router-outlet />` の中、`<div class="card jh-card">` の内側に表示される（`src/app/layouts/main/main.html`）。テンプレートは `@if (allBeans())` の中の `<div>` 1 つで、その中を上から順に次の領域が占める。

```
見出し領域（<h2 id="configuration-page-heading" data-cy="configurationPageHeading" jhiTranslate="configuration.title">）
    Configuration
絞り込み入力領域
    Filter (by prefix)   [                    ]
Spring構成領域（<h3 id="spring-configuration">）
    Spring configuration
    テーブル: Prefix | Properties
プロパティーソース領域（<h4 [id]="'property-source-' + i">）   … ソースごとに繰り返す
    <プロパティーソース名>
    テーブル: Property | Value
```

| 領域 | テンプレート上の要素 | 表示条件 | 4 章の対応 |
| --- | --- | --- | --- |
| 見出し領域 | `<h2 id="configuration-page-heading" data-cy="configurationPageHeading" jhiTranslate="configuration.title">` | `allBeans()` が真のとき（外側の `@if (allBeans())`） | `### 見出し領域` |
| 絞り込み入力領域 | `<label for="configuration-filter" jhiTranslate="configuration.filter">`、`id="configuration-filter"` | 同上 | `### 絞り込み入力領域` |
| Spring構成領域 | `<h3 id="spring-configuration">`、`aria-describedby="spring-configuration"` の `<table>` | 同上 | `### Spring構成領域・ヘッダー行`、`### Spring構成領域・データ行` |
| プロパティーソース領域 | `@for (propertySource of propertySources(); track i; let i = $index)` の `<div>`（`<h4 [id]="'property-source-' + i">` と `<table>`） | 同上（`propertySources()` の要素ごと） | `### プロパティーソース領域` |

## 5. イベント処理

### 5.1 イベント一覧

| No. | イベント発生源 | イベント | 遷移先 | イベント物理名 |
| --- | --- | --- | --- | --- |
| 1 | 画面 | 初期化（画面を開いたとき。2 つの API でデータを取得する） | なし | `ngOnInit()` |
| 2 | Filter (by prefix) 入力欄 | 入力 | なし（構成プロパティーの表を絞り込む） | `(ngModelChange)="beansFilter.set($event)"`、`beans`（`computed`） |
| 3 | Prefix 見出し | クリック | なし（Prefix 列を並び替える） | `jhiSortBy="prefix"`、`[(sortState)]="sortState"` |

### 5.2 イベント詳細

#### 5.2.1 画面初期化

- トリガー: `/admin/configuration` への遷移。
- 処理手順:
  1. ルートガード `userRouteAccessService` が `AccountService.identity()` でアカウントを確認する。未ログインなら遷移前の URL を `StateStorageService.storeUrl()` で保存し、`/login` へ遷移してここで終わる。ログインしていても `data.authorities`（`Authority.ADMIN`）を持たなければ `router.navigate(['accessdenied'])` を実行し、この画面への遷移は完了しない。
  2. `ngOnInit()` が `this.configurationService.getBeans()` を購読する。`ConfigurationService.getBeans()` は `GET management/configprops` を送る。
  3. 成功（`next`）: `getBeans()` は応答の `contexts` の各コンテキストが持つ `beans` を 1 つのオブジェクトに統合し（同じ名前の Bean は後のコンテキストで上書きされる）、その値の一覧を `Bean[]` として返す。
  4. 画面は `this.allBeans.set(beans)` を実行する。`allBeans()` が真になるため、テンプレートの `@if (allBeans())` の中身が初めて表示される。応答が空の配列でも、表の行がない状態で表示される。
  5. `ngOnInit()` は続けて `this.configurationService.getPropertySources()` を購読する。`ConfigurationService.getPropertySources()` は `GET management/env` を送り、応答の `propertySources` を返す。
  6. 成功（`next`）: `this.propertySources.set(propertySources)` を実行し、プロパティーソースの表が表示される。
- 絞り込みと並び替えの実体: シグナル `beans`（`computed`）が表示する行を決める。`allBeans()`（`undefined` なら空配列）を取り出し、`beansFilter()` が空文字でなければ `bean.prefix.toLowerCase().includes(beansFilter.toLowerCase())` で絞り込む。続けて `sortState()` に `predicate` と `order` があれば `sortService.startSort({ predicate, order })` で並び替える。テンプレートはこの `beans()` を行の繰り返しに使う。
- 並び順: 並び替えの比較には `SortService` の `Intl.Collator`（`numeric: true`、`sensitivity: 'base'`）を使う。この画面は予備の並び順を指定していない。表の中のプロパティー（`properties`）とプロパティーソースの表の並びは `KeyValuePipe` の既定の動きである（Angular の動きであり、本リポジトリのコードではない）。
- 状態変化: `allBeans`、`propertySources`。
- 遷移: なし。

#### 5.2.2 Filter (by prefix) 入力欄への入力

- トリガー: `(ngModelChange)="beansFilter.set($event)"`。
- 処理手順:
  1. 入力のたびに、シグナル `beansFilter` が新しい文字列になる。
  2. `beans`（`computed`）が再計算され、`prefix` が入力文字列を含む Bean だけになる。両方とも `toLowerCase()` で小文字にして比較するため、大文字と小文字は区別しない。
  3. API は呼ばない。URL も変わらない。
- 状態変化: `beansFilter`、`beans`（`computed`）。
- 遷移: なし。

#### 5.2.3 Prefix 見出しのクリック（並び替え）

- トリガー: `jhiSortBy="prefix"` を持つ `<th>` のクリック。`SortByDirective` はホスト要素の `(click)` で `onClick()` を呼ぶ。
- 処理手順:
  1. `SortByDirective.onClick()` が、`<th>` の中に `<fa-icon>` があるときに親の `SortDirective` の `sort(this.jhiSortBy())` を呼ぶ。
  2. `SortDirective.sort(field)` は、今の `predicate` と同じ列なら `order` を `asc` と `desc` で反転させる。`sortState` を更新し、`sortChange` に新しい状態を出す。この画面は `(sortChange)` を購読していない。
  3. `[(sortState)]="sortState"` により画面の `sortState` が変わり、`beans`（`computed`）が再計算される。
  4. `SortByDirective` の `effect` は、`<th>` の中の `<fa-icon>` のアイコンを `sortState` に応じて切り替える（`asc` なら `faSortUp`、`desc` なら `faSortDown`）。
- 状態変化: `sortState`、`beans`（`computed`）。
- 遷移: なし。並び替えの状態を URL のクエリパラメーターに書き出す処理はない。

### 5.3 API呼び出し一覧

| No. | 目的 | メソッド | パス | 要求パラメーター | 応答 | 成功時 | エラー時 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 構成プロパティーの一覧の取得 | GET | `management/configprops` | なし | 200: `ConfigProps`（`contexts`。各コンテキストは `beans` を持つ。`beans` は Bean 名をキーにした、`prefix` と `properties` のオブジェクト） | `allBeans` に `Bean` の配列が入り、画面全体が表示される | `allBeans()` は `undefined` のままで、画面は非表示 |
| 2 | プロパティーソースの一覧の取得 | GET | `management/env` | なし | 200: `Env`（`activeProfiles`、`propertySources`。各ソースは `name` と `properties` を持つ。`properties` はプロパティー名をキーにした、`value` と `origin` のオブジェクト） | `propertySources` に入り、プロパティーソースの表が表示される | `propertySources` は空配列のままで、プロパティーソースの表は非表示 |

補足:

- 呼び出し元は `ConfigurationService.getBeans()` と `ConfigurationService.getPropertySources()`（`src/app/admin/configuration/configuration.service.ts`）である。URL は `${serverApiUrl}management/configprops` と `${serverApiUrl}management/env` で、`serverApiUrl` はビルド時定数 `SERVER_API_URL` である（`src/app/config/endpoint.constants.ts`）。クエリパラメーターと本文はない。
- 型の定義は `src/app/admin/configuration/configuration.model.ts` の `ConfigProps`、`Context`、`Bean`、`Env`、`PropertySource`、`Property` である。詳細は [configuration_DTO設計書](../../../03_IF設計/01_DTO設計書/configuration_DTO設計書.md) に書く。
- バックエンドの公開設定（バックエンドの `src/main/resources/config/application.yml`）: `management.endpoints.web.base-path` は `/management` で、`management.endpoints.web.exposure.include` に `configprops` と `env` が含まれる。
- サーバー側の実装: 2 つとも Spring Boot Actuator（ライブラリー）のエンドポイントであり、バックエンドのリポジトリにソースはない。これらのパスへ応答するアプリケーションのコードは、バックエンドの `src/main/java/` 配下にない。
- 表示される値: プロパティーの値のうち秘匿すべきものを置き換えるかどうかはライブラリーの動きである。バックエンドの設定（バックエンドの `src/main/resources/config/application.yml`、`application-dev.yml`、`application-prod.yml`）にプロパティーの値の表示を変える記述はない。実際の応答でどの値が置き換えられるかは、コードからは確認できない。
- バックエンドの認可（バックエンドの `src/main/java/io/github/jhipster/sample/config/SecurityConfiguration.java`）: `/management/**` は `AuthoritiesConstants.ADMIN`（`ROLE_ADMIN`）を持つことを要求する。
- 要求ヘッダーは `authInterceptor` が `Authorization: Bearer <トークン>` を付ける（トークンがあるとき）。
- エラー時の共通の動きは次のとおりである。共通部品の詳細は [HTTP共通処理_画面設計書](../../共通/HTTP共通処理/HTTP共通処理_画面設計書.md) に書く。
  - 401 のときは `authExpiredInterceptor` が現在の URL を `StateStorageService.storeUrl()` で保存し、ログアウトして `/login` へ遷移する。
  - 2 つの購読は `next` だけを持ち、`error` の処理はない。テンプレートに `<jhi-alert-error />` がないため、HTTP エラーを画面に表示する仕組みはない。`errorHandlerInterceptor` はイベント `jhipsterSampleApplicationApp.httpError` を配信するが、この画面にはそれを購読する部品がない。

### 5.4 画面遷移

| 遷移先 | 条件 | トリガー |
| --- | --- | --- |
| ログイン（`/login`） | 未ログインのままこの画面を開いた | `userRouteAccessService`（遷移前の URL を `StateStorageService.storeUrl()` で保存してから遷移する） |
| アクセス拒否画面（`/accessdenied`） | ログインしているが `ROLE_ADMIN` を持たないユーザー | `userRouteAccessService`（`router.navigate(['accessdenied'])`） |
| ログイン（`/login`） | データの取得が 401 を返した | `authExpiredInterceptor` |
