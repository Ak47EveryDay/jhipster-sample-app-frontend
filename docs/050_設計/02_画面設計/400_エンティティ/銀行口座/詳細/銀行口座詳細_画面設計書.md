## 2. 機能概要

- 銀行口座 1 件の ID、Name、Balance、User を読み取り専用で表示する。
- 表示するデータは、ルートのリゾルバー `bankAccountResolve` が `GET api/bank-accounts/{id}` で取得する。取得結果はコンポーネントの `input` である `bankAccount` に入る。画面のコンポーネント自身は API を呼ばない。
- 取得に失敗して 404 のときは `/404` へ、その他の失敗のときは `/error` へ遷移し、この画面は表示しない。
- 「Back」ボタンでブラウザーの履歴を 1 つ戻る。「Edit」ボタンで銀行口座編集画面へ遷移する。
- 入力項目はない。この画面に `入力チェック一覧` はない。
- `<jhi-alert-error />` と `<jhi-alert />` を置く。

## 3. 画面レイアウト

画面は `Main` の `<router-outlet />` の中に表示される（`src/app/layouts/main/main.html`）。テンプレートは中央寄せの `<div class="d-flex justify-content-center">` と `<div class="col-8">` で囲み、その中の `@if (bankAccount(); as bankAccountRef)` が真のときに次の領域を上から順に表示する。

```
見出し領域（<h2 data-cy="bankAccountDetailsHeading">）
    Bank Account
    <hr />
アラート領域
    <jhi-alert-error />   … エラー
    <jhi-alert />         … 成功通知
明細領域（<dl class="row-md jh-entity-details">）
    ID       … id
    Name     … name
    Balance  … balance
    User     … user.login
ボタン領域
    [Back] [Edit]
```

| 領域 | テンプレート上の要素 | 表示条件 | 4 章の対応 |
| --- | --- | --- | --- |
| 見出し領域 | `<h2 data-cy="bankAccountDetailsHeading">`、`<hr />` | `bankAccount()` が `null` でないとき | `### 見出し領域` |
| アラート領域 | `<jhi-alert-error />`、`<jhi-alert />` | 同上（アラートがあるときだけ内容が表示される） | `### アラート領域` |

## 5. イベント処理

### 5.1 イベント一覧

| No. | イベント発生源 | イベント | 遷移先 | イベント物理名 |
| --- | --- | --- | --- | --- |
| 1 | 画面 | 初期化（この画面への遷移。ルートの解決） | データがなければ `/404` または `/error` | `bankAccountResolve`（`BankAccountService.find()`） |
| 2 | Back ボタン | クリック | ブラウザーの履歴の前の画面 | `previousState()` |
| 3 | Edit ボタン | クリック | `/bank-account/:id/edit` | `[routerLink]="['/bank-account', bankAccountRef.id, 'edit']"` |

### 5.2 イベント詳細

#### 5.2.1 画面初期化

- トリガー: `/bank-account/:id/view` への遷移。画面が表示される前に、ルートガードとリゾルバーが順に動く。
- 処理手順:
  1. ルートガード `userRouteAccessService` が `AccountService.identity()` でアカウントを確認する。未ログインなら遷移前の URL を `StateStorageService.storeUrl()` で保存し、`/login` へ遷移してここで終わる。
  2. リゾルバー `bankAccountResolve(route)` が `route.params` から `id` を取り出す。`id` があれば `inject(Router)` と `inject(BankAccountService)` を取得し、`service.find(id)` を呼ぶ。`id` がなければ `of(null)` を返す。
  3. `BankAccountService.find(id)` は `GET api/bank-accounts/{id}` を送る（`id` は `encodeURIComponent` でエンコードする）。
  4. 成功なら `IBankAccount` がそのままリゾルバーの戻り値になる。失敗なら `catchError` が `HttpErrorResponse` を受け、`status` が 404 のときは `router.navigate(['404'])` を、それ以外のときは `router.navigate(['error'])` を実行して `EMPTY` を返す。`EMPTY` のためこの画面への遷移は完了しない。
  5. 解決結果は、ルート定義の `resolve` のキー `bankAccount` と同じ名前の `input`（`readonly bankAccount = input<IBankAccount | null>(null)`）に入る。これは `src/app/app.config.ts` の `provideRouter` に指定した `withComponentInputBinding()` によるものである。
  6. テンプレートは `@if (bankAccount(); as bankAccountRef)` の中身を表示する。
- 状態変化: `bankAccount`（`input`）に取得結果が入る。コンポーネントは他の状態を持たない。
- 遷移: 通常はなし。4. の失敗時のみ `/404` または `/error` へ遷移する。

#### 5.2.2 Back ボタンクリック

- トリガー: `(click)="previousState()"`。
- 処理手順: `previousState()` は `globalThis.history.back()` を呼ぶだけである。画面内に状態はない。
- 状態変化: なし。画面が破棄されるとき `<jhi-alert />`（`Alert`）の `ngOnDestroy()` が `alertService.clear()` を呼ぶ。
- 遷移: ブラウザーの履歴を 1 つ戻る。遷移先は履歴による（銀行口座一覧から来たなら銀行口座一覧に戻る）。この画面を直接開いて履歴がなければ、コードからは遷移先を確認できない。

#### 5.2.3 Edit ボタンクリック

- トリガー: `[routerLink]="['/bank-account', bankAccountRef.id, 'edit']"` のクリック。
- 処理手順: 銀行口座編集画面（`/bank-account/:id/edit`）へ遷移する。遷移先でも同じリゾルバー `bankAccountResolve` が `GET api/bank-accounts/{id}` を送る。
- 状態変化: なし（画面が破棄される）。
- 遷移: `/bank-account/:id/edit`。

### 5.3 API呼び出し一覧

この画面に関わる API 呼び出しは、ルートの解決のときにリゾルバーが送る 1 件だけである。画面のコンポーネントは API を呼ばない。

| No. | 目的 | メソッド | パス | 要求パラメーター | 応答 | 成功時 | エラー時 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 表示データの取得（ルートの解決） | GET | `api/bank-accounts/{id}` | パスパラメーター `id`（ルートの `:id`。`encodeURIComponent` でエンコードする） | 200: `IBankAccount` 1 件（`id`、`name`、`balance`、`user`） | リゾルバーが `IBankAccount` を返し、`bankAccount`（`input`）に入る | 404 のときリゾルバーが `/404` へ遷移する。その他の失敗のときは `/error` へ遷移する。どちらも `EMPTY` を返し、この画面は表示されない |

補足:

- 呼び出し元はリゾルバー `bankAccountResolve`（`src/app/entities/bank-account/route/bank-account-routing-resolve.service.ts`）で、メソッドは `BankAccountService.find(id)`（`src/app/entities/bank-account/service/bank-account.service.ts`）である。
- バックエンドは `BankAccountResource.getBankAccount(id)`（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/BankAccountResource.java`）である。`bankAccountRepository.findOneWithEagerRelationships(id)` を呼び、これは `left join fetch bankAccount.user` を伴うクエリーで、銀行口座と一緒にユーザーを読み込む。結果は `ResponseUtil.wrapOrNotFound(bankAccount)` で返り、値がなければ 404 になる。
- 要求ヘッダーは `authInterceptor` が `Authorization: Bearer <トークン>` を付ける（トークンがあるとき）。バックエンドは `/api/**` に認証を要求する（バックエンドの `src/main/java/io/github/jhipster/sample/config/SecurityConfiguration.java`）。
- 401 のときは `authExpiredInterceptor` が現在の URL を `StateStorageService.storeUrl()` で保存し、ログアウトして `/login` へ遷移する。

### 5.4 画面遷移

| 遷移先 | 条件 | トリガー |
| --- | --- | --- |
| 銀行口座編集（`/bank-account/:id/edit`） | ログインしていること | Edit ボタン |
| ブラウザーの履歴の前の画面 | 履歴があること | Back ボタン（`previousState()`） |
| 404 画面（`/404`） | `GET api/bank-accounts/{id}` が 404 を返した | リゾルバー `bankAccountResolve`（`router.navigate(['404'])`） |
| エラー画面（`/error`） | `GET api/bank-accounts/{id}` が 404 以外の失敗を返した | リゾルバー `bankAccountResolve`（`router.navigate(['error'])`） |
| ログイン（`/login`） | 未ログインのままこの画面を開いた | `userRouteAccessService`（遷移前の URL を `StateStorageService.storeUrl()` で保存してから遷移する） |
