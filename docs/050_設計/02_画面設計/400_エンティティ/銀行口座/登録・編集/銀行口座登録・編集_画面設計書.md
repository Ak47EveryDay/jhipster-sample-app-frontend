## 2. 機能概要

- 1 つの画面で登録（`/bank-account/new`）と編集（`/bank-account/:id/edit`）の両方を担う。どちらであるかは、フォームの `id` の値が `null` かどうかで区別する。
- 編集のときは、ルートのリゾルバー `bankAccountResolve` が `GET api/bank-accounts/{id}` で取得した銀行口座をフォームに設定する。登録のときはリゾルバーが API を呼ばずに `null` を返し、フォームは既定値（`id` は `null`）で始まる。
- 入力項目は Name、Balance、User の 3 つである。ID は編集のときだけ読み取り専用で表示する。
- User は選択リストから選ぶ。選択肢は `GET api/users` で取得したユーザーに、編集対象が持つユーザーを加えたものである。先頭に未選択の空欄がある。
- Name と Balance は必須である。フォームが無効な間と保存中は、保存ボタンが無効になる。
- 保存は、登録なら `POST api/bank-accounts`、編集なら `PUT api/bank-accounts/{id}` を送る。成功したらブラウザーの履歴を 1 つ戻る。
- 保存に失敗したら画面にとどまり、エラーを `<jhi-alert-error />` に表示する。保存ボタンは再び有効になる。
- Cancel ボタンでブラウザーの履歴を 1 つ戻る。入力内容を破棄するかどうかの確認はしない。
- この画面には `<jhi-alert />` がない。保存の成功通知は、戻った先の画面の `<jhi-alert />` に表示される。

## 3. 画面レイアウト

画面は `Main` の `<router-outlet />` の中に表示される（`src/app/layouts/main/main.html`）。テンプレートは中央寄せの `<div class="d-flex justify-content-center">` と `<div class="col-8">` で囲み、その中に `<form name="editForm" novalidate (ngSubmit)="save()" [formGroup]="editForm">` を置く。フォームの中を上から順に次の領域が占める。

```
見出し領域（<h2>、id="jhi-bank-account-heading"）

アラート領域
    <jhi-alert-error />

    ID       … 編集のときだけ表示（読み取り専用）

    User     … 選択リスト（空欄 + ユーザーの一覧）

    [Cancel] [Save]
```

## 5. イベント処理

### 5.1 イベント一覧

| No. | イベント発生源 | イベント | 遷移先 | イベント物理名 |
| --- | --- | --- | --- | --- |
| 1 | 画面 | 初期化（この画面への遷移。ルートの解決、フォームへの値の設定、User の選択肢の取得） | 編集でデータがなければ `/404` または `/error` | `ngOnInit()`（`activatedRoute.data` の購読、`updateForm()`、`loadRelationshipsOptions()`） |
| 2 | Name 入力欄 | 入力 | なし | `formControlName="name"` |
| 3 | Balance 入力欄 | 入力 | なし | `formControlName="balance"` |
| 4 | User 選択リスト | 選択の変更 | なし | `formControlName="user"` |
| 5 | Cancel ボタン | クリック | ブラウザーの履歴の前の画面 | `previousState()` |
| 6 | Save ボタン | クリック（フォームの送信） | 保存に成功したらブラウザーの履歴の前の画面 | `(ngSubmit)="save()"` |

### 5.2 イベント詳細

#### 5.2.1 画面初期化

- トリガー: `/bank-account/new` または `/bank-account/:id/edit` への遷移。
- 処理手順:
  1. ルートガード `userRouteAccessService` がアカウントを確認する。未ログインなら遷移前の URL を保存して `/login` へ遷移し、ここで終わる。
  2. リゾルバー `bankAccountResolve(route)` が動く。`/bank-account/new` には `id` がないため `of(null)` を返し、API を呼ばない。`/bank-account/:id/edit` では `BankAccountService.find(id)` で `GET api/bank-accounts/{id}` を送る。失敗したときは 404 なら `/404`、それ以外なら `/error` へ遷移して `EMPTY` を返す。
  3. コンポーネントのフィールド初期化で `this.bankAccountFormService.createBankAccountFormGroup()` が引数なしで実行され、フォームグループ `editForm` ができる。この時点の値は `id` が `null`、`name`、`balance`、`user` は `undefined` である。`name` と `balance` は必須のため、この時点のフォームは無効である。
  4. `ngOnInit()` が `this.activatedRoute.data` を購読し、`data.bankAccount`（リゾルバーの結果）を受け取る。
  5. `bankAccount` が真（編集）なら `updateForm(bankAccount)` を呼ぶ。`this.bankAccount` に代入し、`this.bankAccountFormService.resetForm(this.editForm, bankAccount)` でフォームに値を設定する。続けて `usersSharedCollection` に対し、`bankAccount.user` がまだ選択肢になければそれを先頭に加える（`userService.addUserToCollectionIfMissing`）。
  6. `bankAccount` が `null`（登録）なら `updateForm` を呼ばず、手順 3 の既定値のまま使う。
  7. `loadRelationshipsOptions()` が `this.userService.query()` で `GET api/users` を送る。応答の本文（`res.body ?? []`）に対し、`this.bankAccount?.user` がなければそれを加え、`usersSharedCollection.set(users)` で選択肢を置き換える。
- フォームサービス `BankAccountFormService` の働き:
  - `createBankAccountFormGroup(bankAccount?)`: 既定値（`getFormDefaults()` は `{ id: null }`）と引数（なければ `{ id: null }`）をマージして `FormGroup` を作る。コントロールは次の 4 つである。
    - `id`: 初期値はマージ結果の `id`。`disabled: true`、`nonNullable: true`、`validators: [Validators.required]`。
    - `name`: 初期値はマージ結果の `name`。`validators: [Validators.required]`。
    - `balance`: 初期値はマージ結果の `balance`。`validators: [Validators.required]`。
    - `user`: 初期値はマージ結果の `user`。バリデーターはない。
  - `resetForm(form, bankAccount)`: 既定値と引数をマージした値で `form.reset()` を呼ぶ。`id` は `id: { value: bankAccountRawValue.id, disabled: true }` として渡し、無効の状態を保つ。
  - `getBankAccount(form)`: `form.getRawValue()` を返す。無効なコントロール（`id`）の値も含まれる。
- 登録と編集の判定: テンプレートは `editForm.controls.id.value !== null` のときだけ ID 入力欄を表示する。`save()` は `getBankAccount()` で取り出した値の `id` が `null` なら登録（`create`）、そうでなければ編集（`update`）として扱う。
- 状態変化: `bankAccount`、`editForm` の各コントロールの値、`usersSharedCollection`。
- 遷移: 通常はなし。編集でリゾルバーが失敗したときだけ `/404` または `/error` へ遷移する。

#### 5.2.2 入力（Name、Balance、User）

- トリガー: 各入力欄への入力、User の選択の変更。
- 処理手順: Reactive Forms がコントロールの値を更新し、バリデーターを評価し直す。この画面には入力時のメソッド呼び出しはない。
- 状態変化: `editForm` の各コントロールの値と、`invalid`、`dirty`、`touched` の状態。
- 表示の変化:
  - Name: `nameRef.invalid && (nameRef.dirty || nameRef.touched)` で、`nameRef.errors?.required` なら翻訳キー `entity.validation.required`（「This field is required.」）を表示する。
  - Balance: `balanceRef.invalid && (balanceRef.dirty || balanceRef.touched)` のとき、`balanceRef.errors?.required` なら翻訳キー `entity.validation.required` を表示する。`balanceRef.errors?.number` のときに翻訳キー `entity.validation.number`（「This field should be a number.」）を表示する分岐もあるが、`number` エラーを設定するバリデーターはコード上にない（入力チェック一覧の 2 章参照）。
  - Save ボタン: `editForm.invalid || isSaving()` が真の間は無効である。登録の初期状態では `name` と `balance` が未入力のため、無効である。
- 遷移: なし。

#### 5.2.3 Cancel ボタンクリック

- トリガー: `(click)="previousState()"`。
- 処理手順: `previousState()` は `globalThis.history.back()` を呼ぶだけである。入力内容の破棄を確認する処理はない。
- 状態変化: なし（画面が破棄される）。
- 遷移: ブラウザーの履歴を 1 つ戻る。遷移先は履歴による（銀行口座一覧から来たなら銀行口座一覧に戻る）。履歴がない場合の遷移先は、コードからは確認できない。

#### 5.2.4 Save ボタンクリック（保存）

- トリガー: Save ボタン（`type="submit"`）によるフォームの送信（`(ngSubmit)="save()"`）。ボタンは `editForm.invalid || isSaving()` の間は無効である。
- 処理手順:
  1. `this.isSaving.set(true)` にする。
  2. `this.bankAccountFormService.getBankAccount(this.editForm)` で `form.getRawValue()` を取り出す。中身は `id`、`name`、`balance`、`user` である。
  3. `bankAccount.id === null` なら `this.bankAccountService.create(bankAccount)`（`POST api/bank-accounts`）を、そうでなければ `this.bankAccountService.update(bankAccount)`（`PUT api/bank-accounts/{id}`）を呼ぶ。`PUT` のパスの `id` は本文の `id`（`getBankAccountIdentifier(bankAccount)`）である。
  4. `subscribeToSaveResponse(result)` が結果を購読する。
     - 成功（`next`）: `onSaveSuccess()` が `previousState()` を呼び、ブラウザーの履歴を 1 つ戻る。応答本文は使わない。
     - 失敗（`error`）: `onSaveError()` は何もしない（コメント「Api for inheritance.」）。
     - 成功・失敗とも（`finalize`）: `onSaveFinalize()` が `this.isSaving.set(false)` を実行し、保存ボタンを再び有効にする。
  5. 成功の通知: バックエンドはレスポンスヘッダー `x-jhipstersampleapplicationapp-alert` に翻訳キー（登録は `jhipsterSampleApplicationApp.bankAccount.created`、編集は `jhipsterSampleApplicationApp.bankAccount.updated`）を、`x-jhipstersampleapplicationapp-params` に ID を返す。`notificationInterceptor` がこれを成功アラートとして `AlertService` に追加する。この画面には `<jhi-alert />` がないため、アラートは戻った先の画面の `<jhi-alert />` に表示される（銀行口座一覧と銀行口座詳細にはある）。
  6. 失敗の通知: `errorHandlerInterceptor` がイベント `jhipsterSampleApplicationApp.httpError` を配信し、この画面の `<jhi-alert-error />` にエラーが表示される。エラーごとの表示内容は [銀行口座登録・編集_入力チェック一覧](./銀行口座登録・編集_入力チェック一覧.md) の 4 章に書く。
- 状態変化: `isSaving`（`true` にしたあと `false` に戻る）。フォームの値は変更しない。
- 遷移: 保存に成功したときだけブラウザーの履歴を 1 つ戻る。

### 5.3 API呼び出し一覧

| No. | 目的 | メソッド | パス | 要求パラメーター | 応答 | 成功時 | エラー時 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 編集対象の取得（ルートの解決。編集のみ） | GET | `api/bank-accounts/{id}` | パスパラメーター `id` | 200: `IBankAccount` 1 件 | リゾルバーが `IBankAccount` を返し、`data.bankAccount` に入る | 404 ならリゾルバーが `/404` へ、その他の失敗なら `/error` へ遷移する |
| 2 | User の選択肢の取得 | GET | `api/users` | なし | 200: `IUser` の配列（`id`、`login`） | `usersSharedCollection` に設定する | `usersSharedCollection` は更新されない。画面にはエラー時の処理が書かれていない。`<jhi-alert-error />` にエラーが表示される |
| 3 | 登録 | POST | `api/bank-accounts` | 本文: `id`（`null`）、`name`、`balance`、`user`（ユーザーのオブジェクト、または `null`） | 201: 作成された `IBankAccount`。ヘッダー `Location`、`x-jhipstersampleapplicationapp-alert`、`x-jhipstersampleapplicationapp-params` | ブラウザーの履歴を 1 つ戻る。成功アラートが追加される | 画面にとどまる。`isSaving` を `false` に戻し、`<jhi-alert-error />` にエラーを表示する |
| 4 | 編集 | PUT | `api/bank-accounts/{id}` | パスパラメーター `id`（本文の `id` と同じ値）。本文: `id`、`name`、`balance`、`user` | 200: 更新後の `IBankAccount`。ヘッダー `x-jhipstersampleapplicationapp-alert`、`x-jhipstersampleapplicationapp-params` | 登録に同じ | 登録に同じ |

補足:

- 呼び出し元は次のとおりである。
  - No. 1: リゾルバー `bankAccountResolve`（`src/app/entities/bank-account/route/bank-account-routing-resolve.service.ts`）の `BankAccountService.find(id)`。
  - No. 2: `BankAccountUpdate.loadRelationshipsOptions()` の `UserService.query()`（`src/app/entities/user/service/user.service.ts`）。引数がないためクエリパラメーターは付かない。
  - No. 3、4: `BankAccountUpdate.save()` の `BankAccountService.create()`、`BankAccountService.update()`。URL の起点は `resourceUrl`（`${serverApiUrl}api/bank-accounts`）で、`serverApiUrl` はビルド時定数 `SERVER_API_URL` である（`src/app/config/endpoint.constants.ts`）。
- 本文の `user` にはフォームコントロール `user` の値がそのまま入る。選択肢から選んだ場合は `GET api/users` の要素、編集で選択し直さなかった場合は `GET api/bank-accounts/{id}` の応答にあった `user` のオブジェクト、未選択の場合は `null` である。フロントエンドの型は `id` と `login` だけを宣言している（`src/app/entities/bank-account/bank-account.model.ts` の `IBankAccount`、`src/app/entities/user/user.model.ts` の `IUser`）。
- バックエンドの `BankAccountResource`（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/BankAccountResource.java`）の確認事項:
  - `createBankAccount`: `@Valid @RequestBody BankAccount` を受け取る。`id` が `null` でなければ 400（`idexists`）を返す。保存に成功したら 201 と、`Location` ヘッダー（`new URI("/api/bank-accounts/" + bankAccount.getId())`）を返す。
  - `updateBankAccount`: パスの `id` と `@Valid @RequestBody BankAccount` を受け取る。本文の `id` が `null` なら 400（`idnull`）、パスと本文の `id` が一致しなければ 400（`idinvalid`）、ID のレコードが存在しなければ 400（`idnotfound`）を返す。保存に成功したら 200 を返す。
  - `@Valid` により、エンティティのクラス `BankAccount`（バックエンド）の `name` と `balance` の `@NotNull` 違反は 400 になる。
  - 400 のうち `BadRequestAlertException` によるものは、レスポンスヘッダー `x-jhipstersampleapplicationapp-error`（`error.<errorKey>`）と `x-jhipstersampleapplicationapp-params`（`bankAccount`）を返す。ヘッダー名は大文字と小文字を区別しないため、フロントエンドの定数（`src/app/shared/jhipster/constants.ts`）の小文字の表記と一致する。
- `GET api/users` のバックエンドは `PublicUserResource.getAllPublicUsers(pageable)`（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/PublicUserResource.java`）である。`Pageable` を受け取り、1 ページ分の `UserDTO`（`id` と `login`）と、ヘッダー `X-Total-Count` と `Link` を返す。フロントエンドはページ番号も件数も指定しないため、バックエンドの既定のページングが適用される。既定の件数はこのリポジトリのコードからは確認できない。編集対象のユーザーがこのページに含まれない場合は、`addUserToCollectionIfMissing` が選択肢にそれを加える。
- 要求ヘッダーは `authInterceptor` が `Authorization: Bearer <トークン>` を付ける（トークンがあるとき）。バックエンドは `/api/**` に認証を要求する（バックエンドの `src/main/java/io/github/jhipster/sample/config/SecurityConfiguration.java`）。
- 401 のときは `authExpiredInterceptor` が現在の URL を `StateStorageService.storeUrl()` で保存し、ログアウトして `/login` へ遷移する。
