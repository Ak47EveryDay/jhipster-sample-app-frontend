## 2. 機能概要

- ユーザー（`IUserManagement`）を削除する確認のダイアログである。管理者用の画面である。
- ユーザ管理一覧の Delete ボタンで開く。削除対象は一覧画面が `userManagement` として渡す。
- 確認の文言に削除対象のログイン ID を示し、「Cancel」で取り消し、「Delete」で削除する。
- 削除は `DELETE api/admin/users/{login}` を呼ぶ。バックエンドは削除の確認をしない。
- 削除が成功したら、ダイアログは理由 `ITEM_DELETED_EVENT`（`'deleted'`）で閉じる。一覧画面はそれを受け取って一覧を再取得する。
- 削除に失敗したときは、ダイアログは閉じず、`<jhi-alert-error />` にエラーを表示する。
- ログイン中のユーザー自身の行では、一覧画面の Delete ボタンが無効であるため、このダイアログは開かない。

## 3. 画面レイアウト

`NgbModal` で開くモーダルダイアログである。サイズは `lg`、背景は `static`（背景をクリックしても閉じない）である。テンプレート全体を `@if (userManagement)` で囲む。

```
モーダルダイアログ（<form name="deleteForm">）
    ダイアログ見出し領域（<div class="modal-header">）
        Confirm delete operation
    ダイアログ本文領域（<div class="modal-body">）
        <jhi-alert-error />       … エラー
        Are you sure you want to delete user <login>?
    ダイアログボタン領域（<div class="modal-footer">）
        [Cancel]
        [Delete]
```

| 領域 | テンプレート上の要素 | 表示条件 | 4 章の対応 |
| --- | --- | --- | --- |
| ダイアログ見出し領域 | `<div class="modal-header">` の中の `<h4 class="modal-title" data-cy="userManagementDeleteDialogHeading">` | `userManagement` に値があるとき | `### ダイアログ見出し領域` |
| ダイアログ本文領域 | `<div class="modal-body">` | 同上 | `### ダイアログ本文領域` |
| ダイアログボタン領域 | `<div class="modal-footer">` | 同上 | `### ダイアログボタン領域` |

## 5. イベント処理

### 5.1 イベント一覧

| No. | イベント発生源 | イベント | 遷移先 | イベント物理名 |
| --- | --- | --- | --- | --- |
| 1 | ユーザ管理一覧の Delete ボタン | ダイアログが開く | なし | `UserManagement.delete()`（`modalService.open()`） |
| 2 | Cancel ボタン | クリック | なし（ダイアログを閉じる） | `cancel()`（`activeModal.dismiss()`） |
| 3 | Delete ボタン | フォームの送信 | なし（削除してダイアログを閉じる） | `confirmDelete(login)` |
| 4 | ダイアログ | 削除が成功して閉じる | なし（一覧が再取得する） | `activeModal.close(ITEM_DELETED_EVENT)` |

### 5.2 イベント詳細

#### 5.2.1 ダイアログを開く

- トリガー: ユーザ管理一覧の Delete ボタン（`(click)="delete(userManagement)"`）。
- 処理手順:
  1. 一覧画面の `delete()` が `this.modalService.open(UserManagementDeleteDialog, { size: 'lg', backdrop: 'static' })` を実行する。
  2. `modalRef.componentInstance.userManagement = userManagement` で、削除対象をダイアログに渡す。
- 状態変化: ダイアログの `userManagement`。一覧画面は `modalRef.closed` を購読する。
- 遷移: なし。
- 補足: ダイアログは API を呼ばずに開く。表示する確認文言は、渡された `userManagement.login` だけで組み立てる。

#### 5.2.2 Cancel ボタンクリック

- トリガー: `(click)="cancel()"`。
- 処理手順: `this.activeModal.dismiss()` でダイアログを閉じる。
- 状態変化: なし。
- 遷移: なし。
- 補足: `dismiss()` で閉じたときは `modalRef.closed` は流れない（`dismissed` に流れる。ng-bootstrap の仕様であり、本リポジトリのコードではない）。そのため一覧は再取得しない。

#### 5.2.3 Delete ボタンクリック（削除の実行）

- トリガー: フォームの送信（`(ngSubmit)="confirmDelete(userManagement.login)"`）。
- 処理手順:
  1. `confirmDelete(login)` が `this.userManagementService.delete(login)` を呼ぶ。
  2. `UserManagementService.delete(login)` は `DELETE api/admin/users/{login}` を送る。
  3. 成功したら `this.activeModal.close(ITEM_DELETED_EVENT)` でダイアログを閉じる。
  4. 一覧画面は `modalRef.closed` の理由が `ITEM_DELETED_EVENT` であることを確認し、`load()` で一覧を再取得する。
  5. バックエンドは成功時にヘッダー `x-jhipstersampleapplicationapp-alert`（`userManagement.deleted`）を返す。`notificationInterceptor` が成功アラートを `AlertService` に追加し、削除後の一覧画面の `<jhi-alert />` に「A user is deleted with identifier {{ param }}」が表示される。
- 状態変化: バックエンドのユーザーが削除される。一覧は再取得される。
- 遷移: なし（ダイアログが閉じる）。
- 補足: `subscribe()` に `error` の処理は書かれていない。失敗してもダイアログは閉じず、`isSaving` のような保存中の状態も持たない。エラーは `<jhi-alert-error />` に表示される。

### 5.3 API呼び出し一覧

| No. | 目的 | メソッド | パス | 要求パラメーター | 応答 | 成功時 | エラー時 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | ユーザーの削除 | DELETE | `api/admin/users/{login}` | パスパラメーター: `login` | 204。ヘッダー `x-jhipstersampleapplicationapp-alert`（`userManagement.deleted`）、`x-jhipstersampleapplicationapp-params`（`login`） | ダイアログが閉じ、一覧が再取得される | ダイアログは閉じず、`<jhi-alert-error />` に表示される |

補足:

- 呼び出し元は `UserManagementDeleteDialog.confirmDelete()`（`src/app/entities/admin/user-management/delete/user-management-delete-dialog.ts`）が呼ぶ `UserManagementService.delete(login)` である。URL は `${serverApiUrl}api/admin/users/${encodeURIComponent(login)}` である。
- 要求ヘッダーは `authInterceptor` が `Authorization: Bearer <トークン>` を付ける。バックエンドは `/api/admin/**` に `ROLE_ADMIN` を要求する。
- バックエンドの `UserResource.deleteUser()` は `UserService.deleteUser(login)` を呼び、204 を返す（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/UserResource.java`）。`UserService.deleteUser()` は、ログイン ID に該当するユーザーがあれば削除し、なければ何もしない（バックエンドの `src/main/java/io/github/jhipster/sample/service/UserService.java`）。存在しないユーザーでも 204 になると読める。
- パスの `login` はバックエンドで `Constants.LOGIN_REGEX` と照合される（`@Pattern`。バックエンドの `src/main/java/io/github/jhipster/sample/config/Constants.java`）。
- エラー時の共通の動きは次のとおりである。
  - 401 のときは `authExpiredInterceptor` がログアウトして `/login` へ遷移する。
  - HTTP エラーは `errorHandlerInterceptor` がイベント `jhipsterSampleApplicationApp.httpError` として配信する。購読しているのはこのダイアログの `<jhi-alert-error />` と、開いた元の一覧画面の `<jhi-alert-error />` である。

### 5.4 画面遷移

| 遷移先 | 条件 | トリガー |
| --- | --- | --- |
| ダイアログを閉じる（遷移しない） | Cancel を押した | `cancel()` |
| ダイアログを閉じる（遷移しない。一覧が再取得する） | 削除に成功した | `activeModal.close(ITEM_DELETED_EVENT)` |
| ダイアログを閉じない（遷移しない） | 削除に失敗した | － |
| ログイン（`/login`） | 削除の要求が 401 を返した | `authExpiredInterceptor` |

### 5.5 内部構造

- `UserManagementDeleteDialog` は `NgbActiveModal` を注入して自分自身を閉じる（`src/app/entities/admin/user-management/delete/user-management-delete-dialog.ts`）。
- `userManagement` は入力（`input()`）ではなく公開のプロパティである。一覧画面が `modalRef.componentInstance.userManagement` で直接設定する。
- `<form>` に `(ngSubmit)` を付け、Delete ボタンを `type="submit"` にしている。そのため Delete ボタンを押すとフォームの送信として `confirmDelete()` が呼ばれる。
- 成功アラートの表示先は一覧画面である。削除ダイアログには `<jhi-alert />` がない。

### 5.6 確認文言のプレースホルダー

- 翻訳キー `userManagement.delete.question` の英文は「Are you sure you want to delete user {{ login }}?」であり、プレースホルダーは `login` である（`src/i18n/en/user-management.json`）。
- テンプレートは `[translateValues]="{ id: userManagement.login }"` を渡し、埋め込み値の名前は `id` である（`src/app/entities/admin/user-management/delete/user-management-delete-dialog.html`）。
- 名前が一致しないため、翻訳後の文言では `{{ login }}` が置き換えられないと読める。実機での表示は確認していない。
