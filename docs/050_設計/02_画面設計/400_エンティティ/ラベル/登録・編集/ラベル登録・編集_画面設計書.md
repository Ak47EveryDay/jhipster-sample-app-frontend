## 2. 機能概要

- 1 つの画面で登録（`/label/new`）と編集（`/label/:id/edit`）の両方を担う。どちらであるかは、フォームの `id` の値が `null` かどうかで区別する。
- 編集のときは、ルートのリゾルバー `labelResolve` が `GET api/labels/{id}` で取得したラベルをフォームに設定する。登録のときはリゾルバーが API を呼ばずに `null` を返し、フォームは既定値（`id` は `null`、`operations` は空配列）で始まる。
- 入力項目は Label と Operation の 2 つである。ID は編集のときだけ読み取り専用で表示する。
- Label は必須で、3 文字以上である。
- Operation は複数選択のリストで、ラベルに紐づける取引を選ぶ。選択肢は `GET api/operations` で取得した取引に、編集対象のラベルが持つ取引を加えたものである。先頭に未選択の空欄はない。何も選ばなければ空配列になる。
- フォームが無効な間と保存中は、保存ボタンが無効になる。
- 保存は、登録なら `POST api/labels`、編集なら `PUT api/labels/{id}` を送る。本文には選択した取引のオブジェクトの配列が `operations` として入る。成功したらブラウザーの履歴を 1 つ戻る。
- 保存に失敗したら画面にとどまり、エラーを `<jhi-alert-error />` に表示する。保存ボタンは再び有効になる。
- Cancel ボタンでブラウザーの履歴を 1 つ戻る。入力内容を破棄するかどうかの確認はしない。
- この画面には `<jhi-alert />` がない。保存の成功通知は、戻った先の画面の `<jhi-alert />` に表示される。

## 3. 画面レイアウト

画面は `Main` の `<router-outlet />` の中に表示される（`src/app/layouts/main/main.html`）。テンプレートは中央寄せの `<div class="d-flex justify-content-center">` と `<div class="col-8">` で囲み、その中に `<form name="editForm" novalidate (ngSubmit)="save()" [formGroup]="editForm">` を置く。フォームの中を上から順に次の領域が占める。

```
見出し領域（<h2>、id="jhi-label-heading"）
    Create or edit a Label
アラート領域
    <jhi-alert-error />
入力フォーム領域
    ID        … 編集のときだけ表示（読み取り専用）
    Label     … テキストボックス              [This field is required.]
                                                [This field is required to be at least 3 characters.]
    Operation … 複数選択リスト（取引の ID の一覧）
ボタン領域
    [Cancel] [Save]
```

| 領域 | テンプレート上の要素 | 表示条件 | 4 章の対応 |

| 見出し領域 | `<h2>`（`id="jhi-label-heading"`、`data-cy="LabelCreateUpdateHeading"`） | 常に | `### 見出し領域` |

## 5. イベント処理

### 5.1 イベント一覧

| No. | イベント発生源 | イベント | 遷移先 | イベント物理名 |
| --- | --- | --- | --- | --- |
| 1 | 画面 | 初期化（この画面への遷移。ルートの解決、フォームへの値の設定、Operation の選択肢の取得） | 編集でデータがなければ `/404` または `/error` | `ngOnInit()`（`activatedRoute.data` の購読、`updateForm()`、`loadRelationshipsOptions()`） |
| 2 | Label 入力欄 | 入力 | なし | `formControlName="label"` |
| 3 | Operation 選択リスト | 選択の変更 | なし | `formControlName="operations"` |
| 4 | Cancel ボタン | クリック | ブラウザーの履歴の前の画面 | `previousState()` |
| 5 | Save ボタン | クリック（フォームの送信） | 保存に成功したらブラウザーの履歴の前の画面 | `(ngSubmit)="save()"` |

### 5.2 イベント詳細

#### 5.2.1 画面初期化

- トリガー: `/label/new` または `/label/:id/edit` への遷移。
- 処理手順:
  1. ルートガード `userRouteAccessService` がアカウントを確認する。未ログインなら遷移前の URL を保存して `/login` へ遷移し、ここで終わる。
  2. リゾルバー `labelResolve(route)` が動く。`/label/new` には `id` がないため `of(null)` を返し、API を呼ばない。`/label/:id/edit` では `LabelService.find(id)` で `GET api/labels/{id}` を送る。失敗したときは 404 なら `/404`、それ以外なら `/error` へ遷移して `EMPTY` を返す。
  3. コンポーネントのフィールド初期化で `this.labelFormService.createLabelFormGroup()` が引数なしで実行され、フォームグループ `editForm` ができる。この時点の値は `id` が `null`、`label` が `undefined`、`operations` が `[]` である。`label` は必須のため、この時点のフォームは無効である。
  4. `ngOnInit()` が `this.activatedRoute.data` を購読し、`data.label`（リゾルバーの結果）を受け取る。
  5. `label` が真（編集）なら `updateForm(label)` を呼ぶ。`this.label` に代入し、`this.labelFormService.resetForm(this.editForm, label)` でフォームに値を設定する。続けて `operationsSharedCollection` に対し、`label.operations ?? []` のうちまだ選択肢にない取引を先頭に加える（`operationService.addOperationToCollectionIfMissing`）。
  6. `label` が `null`（登録）なら `updateForm` を呼ばず、手順 3 の既定値のまま使う。
  7. `loadRelationshipsOptions()` が `this.operationService.query()` で `GET api/operations` を送る。引数がないためクエリパラメーターは付かない。応答の本文（`res.body ?? []`）に対し、`this.label?.operations ?? []` のうちまだなければそれを加え、`operationsSharedCollection.set(operations)` で選択肢を置き換える。
- フォームサービス `LabelFormService` の働き:
  - `createLabelFormGroup(label?)`: 既定値（`getFormDefaults()` は `{ id: null, operations: [] }`）と引数（なければ `{ id: null }`）をマージして `FormGroup` を作る。コントロールは次の 3 つである。
    - `id`: 初期値はマージ結果の `id`。`disabled: true`、`nonNullable: true`、`validators: [Validators.required]`。
    - `label`: 初期値はマージ結果の `label`。`validators: [Validators.required, Validators.minLength(3)]`。
    - `operations`: 初期値はマージ結果の `operations`（なければ `[]`）。バリデーターはない。
  - `resetForm(form, label)`: 既定値と引数をマージした値で `form.reset()` を呼ぶ。`id` は `id: { value: labelRawValue.id, disabled: true }` として渡し、無効の状態を保つ。
  - `getLabel(form)`: `form.getRawValue()` を返す。無効なコントロール（`id`）の値も含まれる。
- 登録と編集の判定: テンプレートは `editForm.controls.id.value !== null` のときだけ ID 入力欄を表示する。`save()` は `getLabel()` で取り出した値の `id` が `null` なら登録（`create`）、そうでなければ編集（`update`）として扱う。
- Operation の選択の対応づけ: `<select>` の `[compareWith]="compareOperation"` は `OperationService.compareOperation()` を呼び、2 つの取引の `id` が等しければ同じものとみなす。編集のときはフォームの `operations` に取得した `label.operations` が入り、`id` で選択肢と対応づけられる（`compareWith` による対応づけは Angular の標準の動きであり、本リポジトリのコードではない）。
- 状態変化: `label`、`editForm` の各コントロールの値、`operationsSharedCollection`。
- 遷移: 通常はなし。編集でリゾルバーが失敗したときだけ `/404` または `/error` へ遷移する。

#### 5.2.2 入力（Label、Operation）

- トリガー: Label 入力欄への入力、Operation の選択の変更。
- 処理手順: Reactive Forms がコントロールの値を更新し、バリデーターを評価し直す。この画面には入力時のメソッド呼び出しはない。
- 状態変化: `editForm` の各コントロールの値と、`invalid`、`dirty`、`touched` の状態。
- 表示の変化:
  - Label: `labelRef.invalid && (labelRef.dirty || labelRef.touched)` のとき、`labelRef.errors?.required` なら翻訳キー `entity.validation.required`（「This field is required.」）を、`labelRef.errors?.minlength` なら翻訳キー `entity.validation.minlength`（`[translateValues]="{ min: '3' }`、「This field is required to be at least 3 characters.」）を表示する。
  - Operation: エラーメッセージの表示はない。
  - Save ボタン: `editForm.invalid || isSaving()` が真の間は無効である。登録の初期状態では `label` が未入力のため、無効である。
- 遷移: なし。

#### 5.2.3 Cancel ボタンクリック

- トリガー: `(click)="previousState()"`。
- 処理手順: `previousState()` は `globalThis.history.back()` を呼ぶだけである。入力内容の破棄を確認する処理はない。
- 状態変化: なし（画面が破棄される）。
- 遷移: ブラウザーの履歴を 1 つ戻る。遷移先は履歴による（ラベル一覧から来たならラベル一覧に戻る）。履歴がない場合の遷移先は、コードからは確認できない。

#### 5.2.4 Save ボタンクリック（保存）

- トリガー: Save ボタン（`type="submit"`）によるフォームの送信（`(ngSubmit)="save()"`）。ボタンは `editForm.invalid || isSaving()` の間は無効である。
- 処理手順:
  1. `this.isSaving.set(true)` にする。
  2. `this.labelFormService.getLabel(this.editForm)` で `form.getRawValue()` を取り出す。中身は `id`、`label`、`operations` である。
  3. `label.id === null` なら `this.labelService.create(label)`（`POST api/labels`）を、そうでなければ `this.labelService.update(label)`（`PUT api/labels/{id}`）を呼ぶ。`PUT` のパスの `id` は本文の `id`（`getLabelIdentifier(label)`）である。
  4. `subscribeToSaveResponse(result)` が結果を購読する。
     - 成功（`next`）: `onSaveSuccess()` が `previousState()` を呼び、ブラウザーの履歴を 1 つ戻る。応答本文は使わない。
     - 失敗（`error`）: `onSaveError()` は何もしない（コメント「Api for inheritance.」）。
     - 成功・失敗とも（`finalize`）: `onSaveFinalize()` が `this.isSaving.set(false)` を実行し、保存ボタンを再び有効にする。
  5. 成功の通知: バックエンドはレスポンスヘッダー `x-jhipstersampleapplicationapp-alert` に翻訳キー（登録は `jhipsterSampleApplicationApp.label.created`、編集は `jhipsterSampleApplicationApp.label.updated`）を、`x-jhipstersampleapplicationapp-params` に ID を返す。`notificationInterceptor` がこれを成功アラートとして `AlertService` に追加する。この画面には `<jhi-alert />` がないため、アラートは戻った先の画面の `<jhi-alert />` に表示される（ラベル一覧とラベル詳細にはある）。
  6. 失敗の通知: `errorHandlerInterceptor` がイベント `jhipsterSampleApplicationApp.httpError` を配信し、この画面の `<jhi-alert-error />` にエラーが表示される。エラーごとの表示内容は [ラベル登録・編集_入力チェック一覧](./ラベル登録・編集_入力チェック一覧.md) の 4 章に書く。
- 状態変化: `isSaving`（`true` にしたあと `false` に戻る）。フォームの値は変更しない。
- 遷移: 保存に成功したときだけブラウザーの履歴を 1 つ戻る。

| 2 | Operation の選択肢の取得 | GET | `api/operations` | なし（クエリパラメーターを付けない） | 200: `IOperation` の配列（`id`、`date`、`description`、`amount`、`bankAccount`、`labels`）の 1 ページ分 | `operationsSharedCollection` に設定する | `operationsSharedCollection` は更新されない。画面にはエラー時の処理が書かれていない。`<jhi-alert-error />` にエラーが表示される |
| 3 | 登録 | POST | `api/labels` | 本文: `id`（`null`）、`label`、`operations`（選択した取引のオブジェクトの配列。未選択なら空配列） | 201: 作成された `ILabel`。ヘッダー `Location`、`x-jhipstersampleapplicationapp-alert`、`x-jhipstersampleapplicationapp-params` | ブラウザーの履歴を 1 つ戻る。成功アラートが追加される | 画面にとどまる。`isSaving` を `false` に戻し、`<jhi-alert-error />` にエラーを表示する |

補足:

- 呼び出し元は次のとおりである。
  - No. 1: リゾルバー `labelResolve`（`src/app/entities/label/route/label-routing-resolve.service.ts`）の `LabelService.find(id)`。
  - No. 2: `LabelUpdate.loadRelationshipsOptions()` の `OperationService.query()`（`src/app/entities/operation/service/operation.service.ts`）。引数がないためクエリパラメーターは付かない。
  - No. 3、4: `LabelUpdate.save()` の `LabelService.create()`、`LabelService.update()`。URL の起点は `resourceUrl`（`${serverApiUrl}api/labels`）で、`serverApiUrl` はビルド時定数 `SERVER_API_URL` である（`src/app/config/endpoint.constants.ts`）。
- 本文の `operations` にはフォームコントロール `operations` の値がそのまま入る。選択した取引のオブジェクト（`IOperation`）の配列であり、未選択なら `[]` である。銀行口座登録・編集の `user` のように `null` を送る空欄の選択肢はない。フロントエンドの型は `src/app/entities/operation/operation.model.ts` の `IOperation` と `src/app/entities/label/label.model.ts` の `ILabel` である。
- No. 2 のバックエンドは `OperationResource.getAllOperations(pageable, eagerload)`（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/OperationResource.java`）である。`Pageable` を受け取って 1 ページ分を返すが、フロントエンドはページ番号も件数も並び順も指定しないため、バックエンド側の既定のページングが適用される。既定の件数はこのリポジトリのコードからは確認できない。`eagerload` も指定しないため引数の既定値 `true` になり、各取引は `bankAccount` と `labels` を一緒に読み込む。選択肢はこの 1 ページ分と編集対象のラベルが持つ取引だけである。編集対象の取引がこのページに含まれない場合は、`addOperationToCollectionIfMissing` が選択肢にそれを加える。
- No. 3、4 のバックエンドの `LabelResource`（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/LabelResource.java`）の確認事項:
  - `createLabel`: `@Valid @RequestBody Label` を受け取る。`id` が `null` でなければ 400（`idexists`）を返す。保存に成功したら 201 と、`Location` ヘッダー（`new URI("/api/labels/" + label.getId())`）を返す。
  - `updateLabel`: パスの `id` と `@Valid @RequestBody Label` を受け取る。本文の `id` が `null` なら 400（`idnull`）、パスと本文の `id` が一致しなければ 400（`idinvalid`）、ID のレコードが存在しなければ 400（`idnotfound`）を返す。保存に成功したら 200 を返す。
  - `@Valid` により、エンティティのクラス `Label`（バックエンド）の `label` の `@NotNull` と `@Size(min = 3)` の違反は 400 になる。
  - 400 のうち `BadRequestAlertException` によるものは、レスポンスヘッダー `x-jhipstersampleapplicationapp-error`（`error.<errorKey>`）と `x-jhipstersampleapplicationapp-params`（`label`）を返す。ヘッダー名は大文字と小文字を区別しないため、フロントエンドの定数（`src/app/shared/jhipster/constants.ts`）の小文字の表記と一致する。
- `operations` の保存について: `createLabel` と `updateLabel` は `labelRepository.save(label)` を呼ぶ。エンティティの `Label.operations` は多対多の被所有側（`mappedBy = "labels"`）でカスケードの指定がなく、所有側は `Operation.labels`（`@JoinTable` の名前は `rel_operation__label`）である（バックエンドの `src/main/java/io/github/jhipster/sample/domain/Label.java`、`Operation.java`）。選択した `operations` が結合テーブルの行に反映されるかどうかは、コードからは確認できない。
- 要求ヘッダーは `authInterceptor` が `Authorization: Bearer <トークン>` を付ける（トークンがあるとき）。バックエンドは `/api/**` に認証を要求する（バックエンドの `src/main/java/io/github/jhipster/sample/config/SecurityConfiguration.java`）。
- 401 のときは `authExpiredInterceptor` が現在の URL を `StateStorageService.storeUrl()` で保存し、ログアウトして `/login` へ遷移する。
