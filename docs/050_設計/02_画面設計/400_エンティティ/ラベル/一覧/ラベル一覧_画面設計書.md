## 2. 機能概要

- ラベル（`ILabel`）の一覧をテーブル形式で表示する。
- 一覧は `GET api/labels` で全件を取得する。ページングと無限スクロールはない。
- 取得した一覧はサービスの `labelsResource`（`httpResource`）が保持し、画面はその値をシグナル `labels` に写す。
- 見出し行の ID と Label の 2 列をクリックして並び替えられる。Operation 列には並び替えの指定がない。並び替えの状態はクエリパラメーター `sort` に反映され、画面を再読み込みしても同じ並び順になる。
- 並び替えのたびにバックエンドへ再取得に行く。バックエンドの `getAllLabels()` は引数を持たず `sort` を使わないため、並び替えは画面側（`refineData()`）で行う。
- 送るクエリパラメーターは `sort` だけである。銀行口座一覧が関連の読み込みのために送る `eagerload` に当たるものはない。
- 各行の Operation 列には、ラベルに紐づく取引の ID を取引詳細へのリンクとして表示する。
- 「Refresh list」ボタンで一覧を再取得する。
- 「Create a new Label」ボタンで登録画面へ遷移する。
- 各行に詳細表示、編集、削除の操作がある。削除は確認ダイアログを開き、削除が完了したら一覧を再取得する。
- 件数が 0 件のときはテーブルの代わりに「No Labels found」の警告を表示する。
- HTTP エラーは `<jhi-alert-error />` に、登録・更新・削除の成功通知は `<jhi-alert />` に表示する。

## 3. 画面レイアウト

画面は `Main` の `<router-outlet />` の中、`<div class="card jh-card">` の内側に表示される（`src/app/layouts/main/main.html`）。テンプレートのルートは `<div>` 1 つで、その中を上から順に次の領域が占める。

```
見出し領域（<h2 id="page-heading" data-cy="LabelHeading">）
    Labels
    [Refresh list]
    [Create a new Label]
アラート領域
    <jhi-alert-error />   … エラー
    <jhi-alert />         … 成功通知
検索結果なし領域（#no-result）      … labels().length === 0 のとき
    No Labels found
一覧テーブル領域（#entities）       … 上記以外のとき
    ヘッダー行: ID | Label | Operation | （操作）
    データ行:   id | label | 取引の ID へのリンク（カンマ区切り） | 表示 | 編集 | 削除
```

| 領域 | テンプレート上の要素 | 表示条件 | 4 章の対応 |
| --- | --- | --- | --- |
| 見出し領域 | `<h2 id="page-heading" data-cy="LabelHeading">` | 常に | `### 見出し領域` |
| アラート領域 | `<jhi-alert-error />`、`<jhi-alert />` | 常に（アラートがあるときだけ内容が表示される） | `### アラート領域` |

### 5.2 イベント詳細

#### 5.2.1 画面初期化

- トリガー: コンポーネントが生成された後の最初の変更検知で、`constructor` 内の 2 つの `effect` が実行される。以後はルートのクエリパラメーター（`sort`）が変わるたびに、2 つ目の `effect` が再実行される。
- 処理手順:
  1. `activatedRouteState`（`queryParamMap` と `data` を `toSignal` にしたもの）の初期値は `activatedRoute.snapshot` の値である。
  2. 2 つ目の `effect` が `untracked()` の中で `fillComponentAttributeFromRoute(queryParamMap, data)` を呼ぶ。`sortState` に `sortService.parseSortParam(params.get(SORT) ?? data[DEFAULT_SORT_DATA])` を設定する。クエリパラメーター `sort` がなければ、ルートの `data.defaultSort`（`id,asc`）を使う。
  3. 続けて `load()` を呼ぶ。`load()` は `queryBackend()` を呼ぶ。`queryBackend()` は `{ sort: this.sortService.buildSortParam(this.sortState()) }` を `queryObject` として作り、`this.labelService.labelsParams.set(queryObject)` を実行する。
  4. サービス `LabelsService` の `labelsResource`（`httpResource<ILabel[]>`）は `labelsParams()` を見てリクエストを組み立てる。値が `undefined` ならリクエストしない。値があれば `{ url: this.resourceUrl, params }` として `GET api/labels` を送る。
  5. 応答が届くと `labelsResource` の値が変わり、`computed` である `labels`（サービス）が変わる。
  6. 1 つ目の `effect` が `this.labels.set(this.fillComponentAttributesFromResponseBody([...this.labelService.labels()]))` を実行する。`fillComponentAttributesFromResponseBody` は `refineData` を呼び、`sortState` の `predicate` と `order` で一覧を並び替えて、画面の `labels` シグナルに入れる。
- 状態変化: `sortState`、`labelsParams`（サービス）、`isLoading`（`labelsResource.isLoading`）、`labels`（サービスと画面）。
- 遷移: なし。

#### 5.2.2 Refresh list ボタンクリック

- トリガー: `(click)="load()"`。`isLoading()` が `true` の間はボタンが無効である。
- 処理手順: `load()` が `queryBackend()` を呼び、`labelsParams` に新しいオブジェクトを設定する。以降は 5.2.1 の手順 4 から 6 と同じである。
- 状態変化: `labelsParams`、`isLoading`、`labels`（`sortState` は変わらない）。
- 遷移: なし。

#### 5.2.3 並び替え（見出し行のクリック）

- トリガー: `jhiSortBy` を持つ `<th>`（ID、Label）のクリック。`SortByDirective` はホスト要素の `(click)` で `onClick()` を呼ぶ。Operation 列の `<th>` には `jhiSortBy` がないため、クリックしても何も起きない。
- 処理手順:
  1. `SortByDirective.onClick()` が親の `SortDirective` の `this.sort.sort(this.jhiSortBy())` を呼ぶ。
  2. `SortDirective.sort(field)` は、今の `predicate` と同じ列なら `order` を `asc` と `desc` で反転させ、別の列なら `asc` にする。`sortState` を更新し、`sortChange` に新しい状態を出す。
  3. テンプレートの `(sortChange)="navigateToWithComponentValues($event)"` が `handleNavigation(sortState)` を呼ぶ。
  4. `handleNavigation` は `{ sort: this.sortService.buildSortParam(sortState) }` を `queryParamsObj` として作り、`this.router.navigate(['./'], { relativeTo: this.activatedRoute, queryParams: queryParamsObj })` を実行する。URL は `/label?sort=<列>,<順>` になる（例: `/label?sort=label,desc`）。
  5. クエリパラメーターが変わると `activatedRouteState` が変わり、5.2.1 と同じ流れで、並び替え状態の設定、再取得、画面側の並び替えが行われる。
  6. `SortByDirective` の `effect` は、`<th>` の中の `<fa-icon>` のアイコンを `sortState` に応じて切り替える（対象の列でなければ `faSort`、`asc` なら `faSortUp`、`desc` なら `faSortDown`）。
- 並び替えの実体: `refineData()` は、`sortState` に `predicate` と `order` の両方があるとき `data.sort(this.sortService.startSort({ predicate, order }))` で並び替える。`startSort` の比較には `new Intl.Collator(undefined, { numeric: true, sensitivity: 'base' })` を使い、`desc` のときは比較結果の符号を反転する。
- 並び替えの対象: `id` と `label` は、いずれも項目の直下のプロパティーである。`startSort` は `a[predicate]` を直接比較するため、この 2 列では比較が有効に働くと読める。
- バックエンドとの関係: `queryBackend()` は `sort` をクエリパラメーターで送るが、バックエンドの `LabelResource.getAllLabels()` には引数がなく、呼び出す `labelRepository.findAll()` にも並び順を指定する引数がない。並び順は画面側の `refineData()` だけで決まる。
- 状態変化: `sortState`、URL のクエリパラメーター `sort`、5.2.1 と同じシグナル群。
- 遷移: 画面遷移はない（同じルート `/label` のクエリパラメーターだけが変わる）。

#### 5.2.4 Delete ボタンクリック（削除ダイアログを開く）

- トリガー: `(click)="delete(label)"`。
- 処理手順:
  1. `this.modalService.open(LabelDeleteDialog, { size: 'lg', backdrop: 'static' })` で削除ダイアログを開く。`backdrop: 'static'` は、背景をクリックしてもダイアログを閉じない ng-bootstrap の指定である。
  2. `modalRef.componentInstance.label = label` で、削除対象をダイアログに渡す。
  3. `modalRef.closed` を購読する。`closed` はダイアログが `close()` で閉じられたときに流れる Observable である（`dismiss()` で閉じられたときは流れない）。
  4. 理由が `ITEM_DELETED_EVENT`（`'deleted'`）のときだけ `load()` を呼び、一覧を再取得する。
- 状態変化: ダイアログが開く。削除が確定した場合は、5.2.1 の手順 4 から 6 と同じシグナル群が変わる。
- 遷移: なし。ダイアログの中の処理（`DELETE api/labels/{id}`）は [ラベル削除_画面設計書](../削除/ラベル削除_画面設計書.md) に書く。

#### 5.2.5 リンクによる遷移

- トリガー: Create a new Label ボタン、ID リンク、View、Edit、Operation 列のリンクのクリック。
- 処理手順: `[routerLink]` に従って遷移する。遷移先のルートには `canActivate: [userRouteAccessService]` がある。
- 遷移先: `/label/new`、`/label/:id/view`、`/label/:id/edit`、`/operation/:id/view`。
- 状態変化: この画面は破棄される。破棄のとき `<jhi-alert />`（`Alert`）の `ngOnDestroy()` が `alertService.clear()` を呼ぶ。

### 5.3 API呼び出し一覧

| No. | 目的 | メソッド | パス | 要求パラメーター | 応答 | 成功時 | エラー時 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 一覧の取得 | GET | `api/labels` | クエリパラメーター: `sort`（`<列>,<asc または desc>`。例: `id,asc`） | 200: `ILabel` の配列（`id`、`label`、`operations`） | `labelsResource` が値を持ち、サービスの `labels` を経て画面の `labels` に入る | サービスの `labels` は空配列になる。エラーは `<jhi-alert-error />` に表示される |

補足:

- 呼び出し元は `LabelsService.labelsResource`（`src/app/entities/label/service/label.service.ts`）である。URL は `resourceUrl`（`${serverApiUrl}api/labels`）で、`serverApiUrl` はビルド時定数 `SERVER_API_URL` である（`src/app/config/endpoint.constants.ts`）。
- `LabelService.query(req?)` も同じ URL を `HttpClient` の `get` で呼ぶが、この画面は使わない。本体で `LabelService` の `query()` を呼んでいるのは取引の登録・編集画面である（`src/app/entities/operation/update/operation-update.ts` の `loadRelationshipsOptions()`）。`partialUpdate()` を呼ぶ箇所は本体にない。
- バックエンドは `LabelResource.getAllLabels()`（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/LabelResource.java`）である。引数がなく、クエリパラメーターは受け取らない。`labelRepository.findAll()` の結果を `List<Label>` としてそのまま返し、ページングのヘッダーは付けていない。送った `sort` は並び順には使われない。
- バックエンドは DTO を使わず、エンティティのクラス `Label`（バックエンドの `src/main/java/io/github/jhipster/sample/domain/Label.java`。画面コンポーネントの `Label` とは別のものである）をそのまま JSON で返す。フロントエンドの `ILabel` は `id`、`label`、`operations` を定義する（`src/app/entities/label/label.model.ts`）。
- Operation 列の値について: バックエンドの `Label.operations` は `@ManyToMany(fetch = FetchType.LAZY, mappedBy = "labels")` であり、`findAll()` にこれを一緒に読み込む指定はない。`spring.jpa.open-in-view` は `false` である（バックエンドの `src/main/resources/config/application.yml`）。応答の `operations` にどのような値が入るかは、シリアライズを担うライブラリー（`JacksonHibernateConfiguration` が登録する `Hibernate7Module`。バックエンドの `src/main/java/io/github/jhipster/sample/config/JacksonHibernateConfiguration.java`）の動きによるため、コードからは確認できない。テンプレートは `label.operations` の要素を取引詳細へのリンクとして描く。
- 要求ヘッダーは `authInterceptor` が `Authorization: Bearer <トークン>` を付ける（トークンがあるとき）。バックエンドは `/api/**` に認証を要求する（バックエンドの `src/main/java/io/github/jhipster/sample/config/SecurityConfiguration.java`）。
- エラー時の共通の動きは次のとおりである。
  - 401 のときは `authExpiredInterceptor` が現在の URL を `StateStorageService.storeUrl()` で保存し、ログアウトして `/login` へ遷移する。
  - この画面の API に対する HTTP エラーは `errorHandlerInterceptor` がイベント `jhipsterSampleApplicationApp.httpError` として配信する（配信しないのは 401 で、かつ `message` が空か URL に `api/account` を含む場合だけである）。`AlertError` はステータスに応じた文言を `<jhi-alert-error />` に表示する（404 は `error.url.not.found`、サーバーに到達できないときは `error.server.not.reachable`、400 はレスポンスヘッダーや本文の内容を使う）。
