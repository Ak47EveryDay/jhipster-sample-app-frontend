## 2. 機能概要

- 権限（`IAuthority`）の一覧をテーブル形式で表示する。管理者用の画面である。
- 一覧は `GET api/authorities` で全件を取得する。ページングと無限スクロールはない。
- 取得した一覧はサービスの `authoritiesResource`（`httpResource`）が保持し、画面はその値を並び替えてシグナル `authorities` に入れる。
- 見出し行の Name 列をクリックして並び替えられる。並び替えの状態はクエリパラメーター `sort` に反映され、画面を再読み込みしても同じ並び順になる。
- 並び替えのたびにバックエンドへ再取得に行く。バックエンドは `sort` を使わないため、並び替えは画面側（`refineData()`）で行う。
- 「Refresh list」ボタンで一覧を再取得する。
- 「Create a new Authority」ボタンで登録画面へ遷移する。
- 各行に詳細表示と削除の操作がある。編集の操作はない（権限には編集のルートがない）。削除は確認ダイアログを開き、削除が完了したら一覧を再取得する。
- 件数が 0 件のときはテーブルの代わりに「No Authorities found」の警告を表示する。
- HTTP エラーは `<jhi-alert-error />` に、登録・削除の成功通知は `<jhi-alert />` に表示する。

## 3. 画面レイアウト

画面は `Main` の `<router-outlet />` の中、`<div class="card jh-card">` の内側に表示される（`src/app/layouts/main/main.html`）。テンプレートのルートは `<div>` 1 つで、その中を上から順に次の領域が占める。

```
見出し領域（<h2 id="page-heading" data-cy="AuthorityHeading">）
    Authorities
    [Refresh list]
    [Create a new Authority]
アラート領域
    <jhi-alert-error />   … エラー
    <jhi-alert />         … 成功通知
検索結果なし領域（#no-result）      … authorities().length === 0 のとき
    No Authorities found
一覧テーブル領域（#entities）       … 上記以外のとき
    ヘッダー行: Name | （操作）
    データ行:   name | 表示 | 削除
```

| 領域 | テンプレート上の要素 | 表示条件 | 4 章の対応 |
| --- | --- | --- | --- |
| 見出し領域 | `<h2 id="page-heading" data-cy="AuthorityHeading">` | 常に | `### 見出し領域` |
| アラート領域 | `<jhi-alert-error />`、`<jhi-alert />` | 常に（アラートがあるときだけ内容が表示される） | `### アラート領域` |

### 5.2 イベント詳細

#### 5.2.1 画面初期化

- トリガー: コンポーネントが生成された後の最初の変更検知で、`constructor` 内の 2 つの `effect` が実行される。以後はルートのクエリパラメーター（`sort`）が変わるたびに、2 つ目の `effect` が再実行される。
- 処理手順:
  1. `activatedRouteState`（`queryParamMap` と `data` を `toSignal` にしたもの）の初期値は `activatedRoute.snapshot` の値である。
  2. 2 つ目の `effect` が `untracked()` の中で `fillComponentAttributeFromRoute(queryParamMap, data)` を呼ぶ。`sortState` に `sortService.parseSortParam(params.get(SORT) ?? data[DEFAULT_SORT_DATA])` を設定する。クエリパラメーター `sort` がなければ、ルートの `data.defaultSort` を使うが、このルートには `defaultSort` の定義がないため、`sortState` は `{ predicate: undefined }` になる。
  3. 続けて `load()` を呼ぶ。`load()` は `queryBackend()` を呼ぶ。`queryBackend()` は `{ sort: this.sortService.buildSortParam(this.sortState()) }` を `queryObject` として作り、`this.authorityService.authoritiesParams.set(queryObject)` を実行する。
  4. サービス `AuthoritiesService` の `authoritiesResource`（`httpResource<IAuthority[]>`）は `authoritiesParams()` を見てリクエストを組み立てる。値が `undefined` ならリクエストしない。値があれば `{ url: this.resourceUrl, params }` として `GET api/authorities` を送る。
  5. 応答が届くと `authoritiesResource` の値が変わり、`computed` である `authorities`（サービス）が変わる。失敗したときは空配列になる。
  6. 1 つ目の `effect` が `this.authorities.set(this.fillComponentAttributesFromResponseBody([...this.authorityService.authorities()]))` を実行する。`fillComponentAttributesFromResponseBody` は `refineData` を呼び、`sortState` の `predicate` と `order` で一覧を並び替えて、画面の `authorities` シグナルに入れる。
- 状態変化: `sortState`、`authoritiesParams`（サービス）、`isLoading`（`authoritiesResource.isLoading`）、`authorities`（サービスと画面）。
- 遷移: なし。

#### 5.2.2 Refresh list ボタンクリック

- トリガー: `(click)="load()"`。`isLoading()` が `true` の間はボタンが無効である。
- 処理手順: `load()` が `queryBackend()` を呼び、`authoritiesParams` に新しいオブジェクトを設定する。以後は 5.2.1 の手順 4 から 6 と同じである。
- 状態変化: `authoritiesParams`、`isLoading`、`authorities`（`sortState` は変わらない）。
- 遷移: なし。

#### 5.2.3 並び替え（見出し行のクリック）

- トリガー: `jhiSortBy` を持つ `<th>` のクリック。`SortByDirective` はホスト要素の `(click)` で `onClick()` を呼ぶ。
- 処理手順:
  1. `SortByDirective.onClick()` が親の `SortDirective` の `this.sort.sort(this.jhiSortBy())` を呼ぶ。
  2. `SortDirective.sort(field)` は、今の `predicate` と同じ列なら `order` を `asc` と `desc` で反転させ、別の列なら `asc` にする。`sortState` を更新し、`sortChange` に新しい状態を出す。
  3. テンプレートの `(sortChange)="navigateToWithComponentValues($event)"` が `handleNavigation(sortState)` を呼ぶ。
  4. `handleNavigation` は `{ sort: this.sortService.buildSortParam(sortState) }` を `queryParamsObj` として作り、`this.router.navigate(['./'], { relativeTo: this.activatedRoute, queryParams: queryParamsObj })` を実行する。URL は `/authority?sort=<列>,<順>` になる（例: `/authority?sort=name,desc`）。
  5. クエリパラメーターが変わると `activatedRouteState` が変わり、5.2.1 と同じ流れで、並び替え状態の設定、再取得、画面側の並び替えが行われる。
  6. `SortByDirective` の `effect` は、`<th>` の中の `<fa-icon>` のアイコンを `sortState` に応じて切り替える（対象の列でなければ `faSort`、`asc` なら `faSortUp`、`desc` なら `faSortDown`）。
- 並び替えの実体: `refineData()` は、`sortState` に `predicate` と `order` の両方があるとき `data.sort(this.sortService.startSort({ predicate, order }))` で並び替える。`startSort` の比較には `new Intl.Collator(undefined, { numeric: true, sensitivity: 'base' })` を使い、`desc` のときは比較結果の符号を反転する。
- バックエンドとの関係: `queryBackend()` は `sort` をクエリパラメーターで送るが、バックエンドの `AuthorityResource.getAllAuthorities()` には引数がなく、呼び出すリポジトリーメソッド（`authorityRepository.findAll()`）にも並び順を指定する句がない。並び順は画面側の `refineData()` だけで決まる。
- 状態変化: `sortState`、URL のクエリパラメーター `sort`、5.2.1 と同じシグナル群。
- 遷移: 画面遷移はない（同じルート `/authority` のクエリパラメーターだけが変わる）。

#### 5.2.4 Delete ボタンクリック（削除ダイアログを開く）

- トリガー: `(click)="delete(authority)"`。
- 処理手順:
  1. `this.modalService.open(AuthorityDeleteDialog, { size: 'lg', backdrop: 'static' })` で削除ダイアログを開く。`backdrop: 'static'` は、背景をクリックしてもダイアログを閉じない ng-bootstrap の指定である。
  2. `modalRef.componentInstance.authority = authority` で、削除対象をダイアログに渡す。
  3. `modalRef.closed` を購読する。`closed` はダイアログが `close()` で閉じられたときに流れる Observable である（`dismiss()` で閉じられたときは流れない）。
  4. 理由が `ITEM_DELETED_EVENT`（`'deleted'`）のときだけ `load()` を呼び、一覧を再取得する。
- 状態変化: ダイアログが開く。削除が確定した場合は、5.2.1 の手順 4 から 6 と同じシグナル群が変わる。
- 遷移: なし。ダイアログの中の処理（`DELETE api/authorities/{name}`）は [権限削除_画面設計書](../削除/権限削除_画面設計書.md) に書く。

#### 5.2.5 リンクによる遷移

- トリガー: Create a new Authority ボタン、Name リンク、View のクリック。
- 処理手順: `[routerLink]` に従って遷移する。遷移先のルートには `canActivate: [userRouteAccessService]` と `data.authorities` がある。
- 遷移先: `/authority/new`、`/authority/:name/view`。
- 状態変化: この画面は破棄される。破棄のとき `<jhi-alert />`（`Alert`）の `ngOnDestroy()` が `alertService.clear()` を呼ぶ。

### 5.3 API呼び出し一覧

| No. | 目的 | メソッド | パス | 要求パラメーター | 応答 | 成功時 | エラー時 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 一覧の取得 | GET | `api/authorities` | クエリパラメーター: `sort`（`<列>,<asc または desc>`。未指定ならなし） | 200: `IAuthority` の配列（`name`） | `authoritiesResource` が値を持ち、サービスの `authorities` を経て画面の `authorities` に入る | サービスの `authorities` は空配列になる。エラーは `<jhi-alert-error />` に表示される |

補足:

- 呼び出し元は `AuthoritiesService.authoritiesResource`（`src/app/entities/admin/authority/service/authority.service.ts`）である。URL は `resourceUrl`（`${serverApiUrl}api/authorities`）で、`serverApiUrl` はビルド時定数 `SERVER_API_URL` である（`src/app/config/endpoint.constants.ts`）。
- `AuthorityService.query(req?)` も同じ URL を `HttpClient` の `get` で呼ぶが、この画面は使わない。本体で `query()` を呼んでいる箇所はない。
- `authoritiesParams` は、ユーザ管理登録・編集画面も `{}` を設定して共有している（`src/app/entities/admin/user-management/update/user-management-update.ts` の `this.authorityService.authoritiesParams.set({})`）。`AuthoritiesService` は `@Service()` を付けたクラスであり、`providedIn` の指定はない。インスタンスを画面ごとに作るかアプリ全体で共有するかは Angular の依存の注入の仕様で決まり、本リポジトリのコードからは確認できない。
- 要求ヘッダーは `authInterceptor` が `Authorization: Bearer <トークン>` を付ける（トークンがあるとき）。バックエンドは `/api/authorities` の各メソッドで `ROLE_ADMIN` を要求する（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/AuthorityResource.java` の `@PreAuthorize`）。
- バックエンドの `getAllAuthorities()` は `authorityRepository.findAll()` の結果をそのまま返す。ページングはなく、レスポンスヘッダー `X-Total-Count`、`Link` も返さない。並び順は指定していない。
- エラー時の共通の動きは次のとおりである。
  - 401 のときは `authExpiredInterceptor` が現在の URL を `StateStorageService.storeUrl()` で保存し、ログアウトして `/login` へ遷移する。
  - HTTP エラーは `errorHandlerInterceptor` がイベント `jhipsterSampleApplicationApp.httpError` として配信する。`AlertError` はステータスに応じた文言を `<jhi-alert-error />` に表示する（404 は `error.url.not.found`、サーバーに到達できないときは `error.server.not.reachable`）。

### 5.4 画面遷移

| 遷移先 | 条件 | トリガー |
| --- | --- | --- |
| 権限登録（`/authority/new`） | `ROLE_ADMIN` を持つこと | Create a new Authority ボタン |
| 権限詳細（`/authority/:name/view`） | 行の `authority.name` を使う | Name リンク、View ボタン |
| 削除ダイアログ（遷移しない） | 対象の行を選んだ | Delete ボタン |
| 同じ画面（再取得。遷移しない） | 削除ダイアログが `ITEM_DELETED_EVENT` で閉じた、Refresh list を押した | `modalRef.closed`、`load()` |
| アクセス拒否（`/accessdenied`） | ログインしているが `ROLE_ADMIN` を持たない | `userRouteAccessService` |
| ログイン（`/login`） | 未ログインのままこの画面を開いた | `userRouteAccessService`（遷移前の URL を `StateStorageService.storeUrl()` で保存してから遷移する） |
