## 2. 単項目チェック

| No. | 項目 | チェック内容 | 必須 | 最大長 / 形式 | エラーメッセージ (翻訳キー) | 根拠 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | Name | 必須チェック（`Validators.required`）。未入力ならエラーにする | 必須 | － | `entity.validation.required`（「This field is required.」） | `src/app/entities/admin/authority/update/authority-form.service.ts`（`name` の `validators` の `Validators.required`）、`src/app/entities/admin/authority/update/authority-update.html`（`nameRef.errors?.required`）、`src/i18n/en/global.json` |
| 2 | Name | 最大長チェック（`Validators.maxLength(50)`）。51 文字以上ならエラーにする | － | 最大 50 文字。文字種の制限はない（英大文字・小文字、数字、記号のいずれも入力できる） | `entity.validation.maxlength`（「This field cannot be longer than {{ max }} characters.」。`max` は `50`） | `src/app/entities/admin/authority/update/authority-form.service.ts`（`name` の `validators` の `Validators.maxLength(50)`）、`src/app/entities/admin/authority/update/authority-update.html`（`nameRef.errors?.maxlength`、`[translateValues]="{ max: '50' }"`） |

補足:

- エラーメッセージの表示条件: コントロールが `invalid` で、かつ `dirty` または `touched` のときだけメッセージのブロックを表示する（`nameRef.invalid && (nameRef.dirty \|\| nameRef.touched)`）。
- 保存ボタンとの関係: Save ボタンは `[disabled]="editForm.invalid \|\| isSaving()"` の間は無効である。Name が未入力、または 51 文字以上のときは押せない。保存メソッド `save()` には、入力値を確認する処理は書かれていない。
- ブラウザーの標準の検証: `<form>` に `novalidate` があるため、ブラウザー自身の検証メッセージは使わない。
- 初期状態: `name` の初期値は `null` である（`getFormDefaults()` の `name: null`）。最初から必須エラーの状態であるが、`dirty` も `touched` も立っていないため、メッセージは表示されない。Save ボタンは無効である。
- 入力欄の状態: 入力欄は `[readonly]="editForm.get('name')!.disabled"` であり、コントロールが無効のときは読み取り専用になる。このルートでは `resetForm()` が呼ばれないため、コントロールは無効にならず、入力欄は常に編集できる。

## 3. 相関チェック

該当なし。`AuthorityFormService.createAuthorityFormGroup()` は `FormGroup` にグループ単位のバリデーターを指定しておらず、コントロールをまたぐチェックはコード上にない（コントロールは `name` の 1 つだけである）。

## 4. サーバ側チェック

保存（`POST api/authorities`）が失敗したとき、画面のコンポーネントは何も処理しない（`onSaveError()` は空である）。共通部品がエラーを受け取り、この画面の `<jhi-alert-error />` に危険アラートとして表示する。表示内容は HTTP ステータスと応答の内容で決まる。

| No. | 発生条件（バックエンド） | HTTP ステータス | バックエンドの応答 | 画面の表示 | この画面から発生するか |
| --- | --- | --- | --- | --- | --- |
| 1 | 同じ名前の権限が既に存在する | 400 | ヘッダー `x-jhipstersampleapplicationapp-error`（`idexists`）、`x-jhipstersampleapplicationapp-params`（`adminAuthority`）。本文は Problem Details で、`message`（`error.idexists`）、`params`（`adminAuthority`）を持つ | 翻訳キー `error.idexists`（「A new {{ entityName }} cannot already have an ID」）。`entityName` は翻訳キー `global.menu.entities.adminAuthority`（「Authority」）の翻訳文 | 発生し得る（既存の権限と同じ名前を入力した場合。画面には重複のチェックがない） |
| 2 | 本文の `name` が `null`（エンティティの `@NotNull`） | 400 | 本文に `fieldErrors`（`objectName`、`field`、`message` の配列）と `message`（`error.validation`）を持つ Problem Details | `AlertError.handleFieldsError()` が危険アラートを追加する。項目名は翻訳できない（下の補足参照） | 通常は発生しない（行番号 1 の必須チェックと保存ボタンの無効化で送信できない） |
| 3 | 本文の `name` が 51 文字以上（エンティティの `@Size(max = 50)`） | 400 | 同上 | 同上 | 通常は発生しない（行番号 2 の最大長チェックと保存ボタンの無効化で送信できない） |
| 4 | 権限がない（`ROLE_ADMIN` を持たない） | 403 | － | 本文に `message` がなければ本文がそのまま表示される | 発生しない（ルートガードが `ROLE_ADMIN` を要求する。ただし画面を開いた後に権限を失った場合は発生し得る） |
| 5 | 認証の失敗 | 401 | － | `authExpiredInterceptor` が現在の URL を保存してログアウトし、`/login` へ遷移する | トークンが無効になったとき |
| 6 | サーバーに到達できない | 0 | － | 翻訳キー `error.server.not.reachable`（「Server not reachable」） | 発生し得る |
| 7 | 上記以外の失敗 | 400、500 など | Problem Details（`message`、`detail`、`params` など） | 本文の `message` を翻訳キーとして表示する（`detail` を既定文言、`params` を埋め込み値にする）。`message` がなければ本文を原文のまま表示する | コードからは確認できない |

補足:

- バックエンド側の定義は次のとおりである。
  - `AuthorityResource.createAuthority()` は、本文を `@Valid @RequestBody Authority` で受け取る。エンティティのクラスをそのまま DTO として使う（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/AuthorityResource.java`）。
  - エンティティの `name` には `@NotNull` と `@Size(max = 50)` が付いている（バックエンドの `src/main/java/io/github/jhipster/sample/domain/Authority.java`）。
  - 重複の確認は `authorityRepository.existsById(authority.getName())` である（同 `AuthorityResource.java`）。
  - `BadRequestAlertException` は `ExceptionTranslator.buildHeaders()` によってヘッダー `x-jhipstersampleapplicationapp-error` と `x-jhipstersampleapplicationapp-params` を付ける（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/errors/ExceptionTranslator.java`、`BadRequestAlertException.java`）。
- 行番号 2、3 の項目名について: `fieldErrors` の `objectName` は、Spring が本文の引数に付ける名前から末尾の `DTO` を除いたものである（`getFieldErrors()` の `f.getObjectName().replaceFirst("DTO$", "")`）。本文の型はエンティティの `Authority` であるため、引数の名前がクラス名と同じなら `objectName` は `Authority` のままである。画面は翻訳キー `jhipsterSampleApplicationApp.<objectName>.name` を引くが（`src/app/shared/alert/alert-error.ts` の `handleFieldsError()`）、翻訳ファイルにあるのは `jhipsterSampleApplicationApp.adminAuthority.name` である（`src/i18n/en/adminAuthority.json`）。名前が一致しないため、項目名は翻訳できないと読める。引数の名前自体はコードからは確認できない。実機での表示は確認していない。
- 行番号 2、3 の文言について: `@NotNull` 違反の `fieldErrors` の `message` は、バックエンドの統合テスト `ExceptionTranslatorIT` では `must not be null` になると検証されている（バックエンドの `src/test/java/io/github/jhipster/sample/web/rest/errors/ExceptionTranslatorIT.java`）。翻訳キー `error.must not be null` は `src/i18n/en/global.json` にないため、既定文言 `Error on field "<項目名>"` になると読める。
- 画面のチェックとバックエンドの制約の対応: 必須（画面は `Validators.required`、バックエンドは `@NotNull`）と最大長 50（画面は `Validators.maxLength(50)`、バックエンドは `@Size(max = 50)`）は一致している。画面には形式（文字種）のチェックがなく、バックエンドにもない。
- 権限名の形式について: バックエンドは権限名の形式を検査しない。画面から任意の文字列を登録できる。登録した権限名をユーザーに付与するには、ユーザ管理登録・編集の Profiles で選ぶ（[ユーザ管理登録・編集_画面設計書](../../ユーザ管理/登録・編集/ユーザ管理登録・編集_画面設計書.md)）。
- エラー時の共通の動き: 保存が失敗しても画面は遷移せず、`isSaving` が `false` に戻って保存ボタンが再び有効になる（`src/app/entities/admin/authority/update/authority-update.ts` の `subscribeToSaveResponse()`、`onSaveFinalize()`）。
