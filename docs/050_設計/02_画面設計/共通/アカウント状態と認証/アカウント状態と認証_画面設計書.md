## 2. 機能概要

- アカウント状態の持ち主は `AccountService` である。ログイン中のアカウントを読み取り専用シグナル `account` として公開し、値はアカウント（`Account`）または `null` である。
- 認証の方式は JWT（JSON Web Token）である。ログイン時にバックエンドが発行したトークンをブラウザーに保存し、以後の HTTP 要求に `Authorization` ヘッダーで付ける（ヘッダーを付けるのは [HTTP共通処理_画面設計書](../HTTP共通処理/HTTP共通処理_画面設計書.md) の `authInterceptor` である）。
- トークンと遷移前の URL は `StateStorageService` が Web Storage（`localStorage` と `sessionStorage`）に保存する。
- ログインとログアウトをまとめるのが `LoginService` である。ログインは「トークンを得る」「アカウントを取得する」の 2 段である。
- ログアウトはバックエンドを呼ばない。トークンを消して、アカウントを `null` にするだけである。
- 呼ぶ API は `POST api/authenticate` と `GET api/account` の 2 つ、保存（`AccountService.save()`）の `POST api/account` を加えた 3 つである。

### トークンと保存値

`StateStorageService`（`src/app/core/auth/state-storage.service.ts`）が扱う保存値である。トークンと `previousUrl` は `JSON.stringify()` して保存し、`JSON.parse()` して戻す。`locale` は文字列をそのまま保存する。

| キー | 保存先 | 内容 | 書くメソッド | 読むメソッド |
| --- | --- | --- | --- | --- |
| `jhi-authenticationToken` | `rememberMe` が `true` なら `localStorage`、`false` なら `sessionStorage` | 認証トークン | `storeAuthenticationToken(authenticationToken, rememberMe)` | `getAuthenticationToken()`（`localStorage` を先に調べ、なければ `sessionStorage` を調べる） |
| `previousUrl` | `sessionStorage` | ログイン前に要求された URL | `storeUrl(url)` | `getUrl()` |
| `locale` | `sessionStorage` | 選んだ言語 | `storeLocale(locale)` | `getLocale()` |

消すメソッドは `clearAuthenticationToken()`（両方のストレージからトークンを消す）、`clearUrl()`、`clearLocale()` である。

## 5. イベント処理

### 5.1 イベント一覧

| No. | イベント発生源 | イベント | 遷移先 | イベント物理名 |
| --- | --- | --- | --- | --- |
| 1 | アプリの起動、画面の表示 | アカウントを取得する | 保存された URL（あれば） | `AccountService.identity()` |
| 2 | ログイン画面の Sign in ボタン | ログインする | ホーム、または保存された URL | `Login.login()`、`LoginService.login()` |
| 3 | ナビゲーションバーの Sign out | ログアウトする | ホーム（`/`） | `Navbar.logout()`、`LoginService.logout()` |
| 4 | HTTP の 401 | トークンの期限切れなどのためログアウトする | ログイン（`/login`） | `authExpiredInterceptor`、`LoginService.logout()` |
| 5 | 設定画面の Save ボタン | アカウントを保存して状態を更新する | なし | `Settings.save()`、`AccountService.save()`、`AccountService.authenticate(account)` |
| 6 | HTTP 要求 | トークンを要求に付ける | － | `authInterceptor`、`StateStorageService.getAuthenticationToken()` |

### 5.2 イベント詳細

#### 5.2.1 アカウントの取得（`AccountService.identity()`）

- トリガー: `identity()` が呼ばれること。呼び出し元は次のとおりである。
  - `Main.ngOnInit()`（`src/app/layouts/main/main.ts`）: 画面を開いたときの自動ログイン。
  - `userRouteAccessService`（`src/app/core/auth/user-route-access.service.ts`）: ガード付きルートへ入る前。
  - `Login.ngOnInit()`（`src/app/login/login.ts`）: ログイン画面を開いたときに、ログイン済みならホームへ戻すため。
  - `LoginService.login()`（`src/app/login/login.service.ts`）: ログイン直後（`force` が `true`）。
  - `Settings.ngOnInit()`（`src/app/account/settings/settings.ts`）: フォームの初期値を得るため。
- 処理手順:
  1. キャッシュ（`accountCache$`）がなければ、`fetch()` で `GET api/account` を呼ぶ。`force` が `true` ならキャッシュがあっても呼ぶ。
  2. 応答の `tap()` で、`authenticate(account)` によりシグナル `userIdentity` にアカウントを入れる。
  3. アカウントに `langKey` があり、かつ sessionStorage に選んだ言語の保存がなければ、`translateService.use(account.langKey)` でアカウントの言語に切り替える。
  4. `navigateToStoredUrl()` を呼ぶ。保存された URL（`previousUrl`）があれば消して、そこへ遷移する。
  5. 結果は `shareReplay()` で共有される。同じキャッシュに対するあとからの購読は、再度 HTTP を送らない。
  6. 失敗（401 など）は `catchError(() => of(null))` で `null` に変える。未ログインとして扱われる。
- 状態変化: `userIdentity`（シグナル）、`accountCache$`、翻訳の言語、sessionStorage の `previousUrl`。
- 遷移: 保存された URL があればそこへ遷移する。なければ遷移しない。
- 補足: `GET api/account` は保護された API であるため、トークンがなければバックエンドは 401 を返す。バックエンドは `AccountResource.getAccount()` で、現在のユーザーと権限を `AdminUserDTO` として返す（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/AccountResource.java`）。

#### 5.2.2 ログイン

- トリガー: ログイン画面の Sign in ボタン（`Login.login()`、`src/app/login/login.ts`）。
- 処理手順:
  1. `Login.login()` が `loginService.login(this.loginForm.getRawValue())` を呼ぶ。引数は `username`、`password`、`rememberMe` である。
  2. `LoginService.login()` は `authServerProvider.login(credentials)` を呼ぶ。
  3. `AuthServerProvider.login()` は `POST api/authenticate` を送る。応答（`id_token`）を受け取ると `authenticateSuccess(response, credentials.rememberMe)` でトークンを保存する。
  4. 続いて `accountService.identity(true)` が `GET api/account` を呼び、アカウントをシグナルに入れる（5.2.1）。
  5. `Login.login()` の `next` で `authenticationError` を `false` にする。このときナビゲーション中でなければ（`this.router.currentNavigation()` がなければ）、`router.navigate([''])` でホームへ遷移する。
  6. `error` で `authenticationError` を `true` にする。画面には「Failed to sign in!」の危険アラートが出る。
- 状態変化: Web Storage のトークン、`userIdentity`、`accountCache$`、`authenticationError`（ログイン画面）。
- 遷移: 5.2.1 の手順 4 で保存された URL へ遷移した場合は、そこで完了する。していなければホーム（`/`）へ遷移する。
- バックエンドとの関係: `AuthenticateController.authorize()`（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/AuthenticateController.java`）は、`LoginVM`（`username` は 1 文字以上 254 文字以下、`password` は 4 文字以上 100 文字以下）を `@Valid` で受け取る。認証に成功すると JWT を作り、本文の `id_token` と `Authorization: Bearer` ヘッダーに入れて 200 を返す。トークンの有効期間はバックエンドの設定（バックエンドの `src/main/resources/config/application-dev.yml`、`application-prod.yml` の `token-validity-in-seconds` は 86400、`token-validity-in-seconds-for-remember-me` は 2592000）である。

#### 5.2.3 ログアウト

- トリガー: ナビゲーションバーの Account メニューの「Sign out」（`Navbar.logout()`、`src/app/layouts/navbar/navbar.ts`）。
- 処理手順:
  1. `Navbar.logout()` が `collapseNavbar()` でメニューを閉じる。
  2. `loginService.logout()` を呼ぶ。`AuthServerProvider.logout()` が `clearAuthenticationToken()` でトークンを消し、完了後に `accountService.authenticate(null)` でアカウントを `null` にしてキャッシュも消す。
  3. `router.navigate([''])` でホームへ遷移する。
- 状態変化: Web Storage のトークン、`userIdentity`（`null`）、`accountCache$`（`null`）。
- 遷移: ホーム（`/`）。
- 補足: ログアウトでバックエンドは呼ばない。発行済みのトークンは有効期限まで残る。

#### 5.2.4 HTTP 401 によるログアウト

- トリガー: 保護された API が 401 を返すこと。
- 処理手順: `authExpiredInterceptor`（`src/app/core/interceptor/auth-expired.interceptor.ts`）が、URL に `api/account` を含まない 401 のとき、次の 3 つを実行する。
  1. `stateStorageService.storeUrl(router.routerState.snapshot.url)` で今の URL を保存する。
  2. `loginService.logout()`（5.2.3 の手順 2 と同じ）。
  3. `router.navigate(['/login'])`。
- 状態変化: Web Storage のトークン、`userIdentity`、`accountCache$`、sessionStorage の `previousUrl`。
- 遷移: ログイン（`/login`）。ログインし直せば保存した URL へ戻る。
- 補足: 詳細は [HTTP共通処理_画面設計書](../HTTP共通処理/HTTP共通処理_画面設計書.md) に書く。

#### 5.2.5 アカウントの保存（設定画面）

- トリガー: 設定画面の Save ボタン（`Settings.save()`、`src/app/account/settings/settings.ts`）。
- 処理手順:
  1. `accountService.save(account)` が `POST api/account` を送る。
  2. 成功したら、設定画面が `accountService.authenticate(account)` を呼び、フォームの値でシグナルを更新する。
  3. 言語（`langKey`）が変わっていれば `translateService.use(account.langKey)` で切り替える。
- 状態変化: `userIdentity`（シグナル）。
- 遷移: なし。

### 5.3 API呼び出し一覧

| No. | 目的 | メソッド | パス | 要求パラメーター | 応答 | 成功時 | エラー時 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | トークンの取得（ログイン） | POST | `api/authenticate` | 本文: `username`、`password`、`rememberMe` | 200: `{ id_token }` | トークンを保存し、No. 2 でアカウントを取る | ログイン画面が `authenticationError` を `true` にする |
| 2 | アカウントの取得 | GET | `api/account` | なし | 200: `Account`（`login`、`firstName`、`lastName`、`email`、`activated`、`langKey`、`imageUrl`、`authorities`） | シグナル `account` に入る | `identity()` は `null` を返す。未ログインとして扱われる |
| 3 | アカウントの保存 | POST | `api/account` | 本文: `Account` | 200（本文なし） | 設定画面がシグナルを更新する | `<jhi-alert-error />` に表示される（設定画面） |

補足:

- 呼び出し元は `AuthServerProvider.login()`（No. 1）、`AccountService.fetch()`（No. 2）、`AccountService.save()`（No. 3）である。URL は `serverApiUrl`（ビルド時定数 `SERVER_API_URL`、`src/app/config/endpoint.constants.ts`）を先頭に付ける。
- 要求ヘッダーは `authInterceptor` が `Authorization: Bearer <トークン>` を付ける（トークンがあるとき）。`POST api/authenticate` はトークンがなくても呼べる（バックエンドは `POST` と `GET` の `/api/authenticate` を認証不要にしている。バックエンドの `src/main/java/io/github/jhipster/sample/config/SecurityConfiguration.java`）。
- No. 2 と No. 3 の失敗が 401 のとき、`authExpiredInterceptor` も `errorHandlerInterceptor` も動かない（URL に `api/account` を含むためである）。`GET api/account` が 401 になるのは、未ログインのまま画面を開いたときである。

### 5.4 画面遷移

| 遷移先 | 条件 | トリガー |
| --- | --- | --- |
| ホーム（`/`） | ログインに成功し、保存された URL がない | `Login.login()` の `this.router.navigate([''])` |

### 5.6 内部構造

- `AccountService` のメンバー（`src/app/core/auth/account.service.ts`）:

| メンバー | 種類 | 内容 |
| --- | --- | --- |
| `userIdentity` | `signal`（`private`） | ログイン中のアカウントまたは `null` |
| `account` | 読み取り専用シグナル | `userIdentity.asReadonly()`。画面とディレクティブはこれを読む |
| `accountCache$` | `Observable`（`private`） | `GET api/account` の結果のキャッシュ |
| `authenticate(identity)` | メソッド | シグナルに値を設定する。`null` のときはキャッシュも `null` にする |
| `hasAnyAuthority(authorities)` | メソッド | アカウントの `authorities` に引数の権限のどれかが含まれるか。未ログインなら `false` |
