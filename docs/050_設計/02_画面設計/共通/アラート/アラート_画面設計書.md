## 2. 機能概要

- HTTP の成否を利用者に知らせる共通の部品である。部品は 2 つある。
  - 成功アラート `<jhi-alert />`（`Alert`）: 登録・更新・削除などの成功時に、バックエンドがレスポンスヘッダー `x-jhipstersampleapplicationapp-alert` で返す翻訳キー（または文言）を緑のアラートで表示する。
  - エラーアラート `<jhi-alert-error />`（`AlertError`）: HTTP エラーを赤のアラートで表示する。
- アラートの実体（文言、種別、自動的に消えるまでの時間など）はサービス `AlertService`（`src/app/core/util/alert.service.ts`）が組み立てる。
- 成功アラートは `AlertService` が 1 つだけ持つシグナルに入る。そのため、`<jhi-alert />` を置いた画面はどれも同じアラートを表示する。
- エラーアラートは `AlertError` のコンポーネントごとのシグナルに入る。画面が変わると、その画面に出ていたエラーアラートは消える。
- アラートは既定で 5000 ミリ秒後に自動的に消える。閉じるボタンでも消せる。
- 文言は翻訳キーなら翻訳してから表示する。翻訳キーでなければ、そのまま表示する。
- アラートは API を呼ばない。材料はインターセプターが HTTP の応答から作る。

## 3. 画面レイアウト

`alert.html` と `alert-error.html` は同じ構造である。

```
<jhi-alert /> または <jhi-alert-error />
    <div class="alerts" role="alert">
        @for (alert of alerts(); track $index) {
            <div [class]="setClasses(alert)">                    … class="jhi-toast" と alert.position
                @if (alert.message) {
                    <ngb-alert [type]="alert.type" (closed)="close(alert)">
                        <pre [innerHTML]="alert.message"></pre>
                    </ngb-alert>
                }
            </div>
        }
    </div>
```

| 領域 | テンプレート上の要素 | 表示条件 | 4 章の対応 |
| --- | --- | --- | --- |
| アラート領域 | `<div class="alerts" role="alert">` の中の `<ngb-alert>` | アラートが 1 つ以上あり、かつ `alert.message` に値があるとき | `### アラート領域` |

## 5. イベント処理

### 5.1 イベント一覧

| No. | イベント発生源 | イベント | 遷移先 | イベント物理名 |
| --- | --- | --- | --- | --- |
| 1 | HTTP の成功応答 | レスポンスヘッダー `x-jhipstersampleapplicationapp-alert` に値がある | なし（成功アラートを追加する） | `notificationInterceptor`（`alertService.addAlert(...)`） |
| 2 | HTTP のエラー応答 | インターセプターがイベント `jhipsterSampleApplicationApp.httpError` を配信する | なし（エラーアラートを追加する） | `errorHandlerInterceptor`、`AlertError.handleHttpError()` |
| 3 | イベント `jhipsterSampleApplicationApp.error` | イベントが配信される | なし（エラーアラートを追加する） | `AlertError.errorListener`、`AlertError.addErrorAlert()` |
| 4 | 閉じるボタン | クリック | なし | `close(alert)` |
| 5 | 時間の経過 | アラートの追加から `alert.timeout`（既定は 5000 ミリ秒）が経った | なし | `addAlert()` 内の `setTimeout(...)`、`closeAlert()` |
| 6 | 画面の破棄（`Alert`） | `<jhi-alert />` を置いた画面がなくなった | － | `Alert.ngOnDestroy()`（`alertService.clear()`） |
| 7 | 画面の破棄（`AlertError`） | `<jhi-alert-error />` を置いた画面がなくなった | － | `AlertError.ngOnDestroy()`（`eventManager.destroy(...)`） |

### 5.2 イベント詳細

#### 5.2.1 HTTP の成功応答（成功アラート）

- トリガー: `HttpClient` の要求に成功応答（`HttpResponse`）が届くこと。
- 処理手順:
  1. `notificationInterceptor`（`src/app/core/interceptor/notification.interceptor.ts`）が応答のヘッダーを取り出し、`getMessageFromHeaders(headers)`（`src/app/shared/jhipster/headers.ts`）に渡す。
  2. ヘッダー `x-jhipstersampleapplicationapp-alert` の値が翻訳キーの形（英数字とドットだけ）なら `alertKey`、そうでなければ `alertMessage` になる。
  3. `alertKey` があれば、`alertService.addAlert({ type: 'success', translationKey: message.alertKey, translationParams: { param: message.param } })` を呼ぶ。`message.param` はヘッダー `x-jhipstersampleapplicationapp-params` の値（URL デコードし、`+` を半角スペースに置き換えたもの）である。
  4. `alertKey` がなくて `alertMessage` があれば、`alertService.addAlert({ type: 'success', message: message.alertMessage })` を呼ぶ。
  5. どちらもなければ、何もしない。
- 状態変化: `AlertService` のアラートの一覧（シグナル `alertsSignal`）に成功アラートが 1 つ加わる。
- 遷移: なし。
- バックエンドとの関係: エンティティの登録・更新・削除は、バックエンドの各 REST リソースクラスがアラートのヘッダーを付けて返す（例: バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/BankAccountResource.java` の `createBankAccount()` は `HeaderUtil.createEntityCreationAlert()` の結果を `headers()` に渡す）。`HeaderUtil` は JHipster フレームワークのライブラリーのクラスであり、バックエンドのリポジトリにはソースがない。ヘッダー名は定数 `MESSAGE_ALERT_HEADER_NAME`、`MESSAGE_PARAM_HEADER_NAME`（`src/app/shared/jhipster/constants.ts`）である。

#### 5.2.2 HTTP のエラー応答（エラーアラート）

- トリガー: `HttpClient` の要求がエラーになること。
- 処理手順:
  1. `errorHandlerInterceptor`（`src/app/core/interceptor/error-handler.interceptor.ts`）が、エラーをイベント `jhipsterSampleApplicationApp.httpError` として `EventManager.broadcast()` で配信する。ただし、ステータスが 401 で、かつ `err.message` が空文字列か `err.url` に `api/account` を含む場合は配信しない。
  2. `AlertError` は `constructor` でこのイベントを購読している（`httpErrorListener`）。購読したすべての `<jhi-alert-error />` が同じイベントを受け取る。
  3. `handleHttpError()` がステータスで分岐する（5.6 の表を参照）。
  4. `addErrorAlert()` が `alertService.addAlert({ type: 'danger', message, translationKey, translationParams }, this.alerts)` を呼ぶ。第 2 引数にコンポーネント自身のシグナル `alerts` を渡すため、アラートはこの部品の中だけで保持される。
- 状態変化: `AlertError` のシグナル `alerts` に危険アラートが加わる。
- 遷移: なし。
- 401 のときの共通の動き: `authExpiredInterceptor` が現在の URL を保存し、ログアウトして `/login` へ遷移する（[HTTP共通処理_画面設計書](../HTTP共通処理/HTTP共通処理_画面設計書.md) 参照）。

#### 5.2.3 イベント `jhipsterSampleApplicationApp.error`

- トリガー: イベント `jhipsterSampleApplicationApp.error` が配信されること。
- 処理手順: `errorListener` がイベントの内容（`AlertErrorModel`）から `message`、`key`、`params` を取り出し、`addErrorAlert()` を呼ぶ。
- 状態変化: `AlertError` のシグナル `alerts` に危険アラートが加わる。
- 遷移: なし。
- 注意: このイベントを配信している箇所は本体のコードにない（配信しているのは `errorHandlerInterceptor` の `jhipsterSampleApplicationApp.httpError` だけである）。

#### 5.2.4 閉じるボタン、自動的に消えるまでの時間

- トリガー: `ngb-alert` の閉じるボタン、または `setTimeout` の満了。
- 処理手順: どちらも `closeAlert(alert.id, extAlerts)` を呼ぶ。`closeAlert()` は、対象の id 以外のアラートだけを残す。
- 状態変化: 該当するアラートが一覧から除かれる。
- 遷移: なし。

#### 5.2.5 画面の破棄

- トリガー: 部品を置いた画面がなくなること。
- 処理手順:
  - `Alert`（成功アラート）: `ngOnDestroy()` が `alertService.clear()` を呼び、`AlertService` のアラートをすべて消す。`<jhi-alert />` はどの画面も同じ一覧を見ているため、画面が変われば成功アラートは引き継がれない。
  - `AlertError`（エラーアラート）: `ngOnDestroy()` が 2 つの購読（`errorListener`、`httpErrorListener`）を解除する。アラートはコンポーネントと一緒になくなる。
- 状態変化: 上記のとおり。
- 遷移: なし。

### 5.4 画面遷移

該当なし。リンクはなく、この部品を起点とする遷移はない。

### 5.5 利用箇所

- `<jhi-alert />`（成功アラート）を置いているのは 10 のテンプレートである。5 つのエンティティ（銀行口座、ラベル、取引、ユーザ管理、権限）の一覧と詳細である。

  - `src/app/entities/label/list/label.html`、`src/app/entities/label/detail/label-detail.html`
  - `src/app/entities/operation/list/operation.html`、`src/app/entities/operation/detail/operation-detail.html`
  - `src/app/entities/admin/user-management/list/user-management.html`、`src/app/entities/admin/user-management/detail/user-management-detail.html`
  - `src/app/entities/admin/authority/list/authority.html`、`src/app/entities/admin/authority/detail/authority-detail.html`
- `<jhi-alert-error />`（エラーアラート）を置いているのは 22 のテンプレートである。上記の 10 に、各エンティティの登録・編集と削除ダイアログ（10）、パスワード再設定依頼（`src/app/account/password-reset/init/password-reset-init.html`）、設定（`src/app/account/settings/settings.html`）を加えたものである。
- ログイン、登録、アカウント有効化、パスワード変更、パスワード再設定完了、ホーム、管理画面の 5 画面には、どちらの部品も置かれていない。

### 5.6 内部構造

- アラートの追加 (`AlertService.addAlert()`、`src/app/core/util/alert.service.ts`):
  1. 一意の `id`（0 から始まる連番）を振る。
  2. `translationKey` があれば `translateService.instant(translationKey, translationParams)` で翻訳し、結果が未定義を表す文言（`translation-not-found[<キー>]`）でなければ `message` にする。翻訳できなければ `translationKey` をそのまま `message` にする。
  3. `message` を `DomSanitizer.sanitize(SecurityContext.HTML, ...)` で無害化してから `<pre [innerHTML]>` に注入する。
  4. `timeout`（既定 `5000`）、`toast`（既定 `false`）、`position`（既定 `'top right'`）を補う。`timeout` が 0 より大きければ `setTimeout()` で自動的に消す。
  5. 第 2 引数 `extAlerts` があればそのシグナルに、なければ `AlertService` 自身のシグナルに追加する。
- 既定値は `AlertService` のフィールド（`timeout`、`toast`、`position`）であり、画面ごとに変えている箇所はない。`toast: true` を指定している箇所もないため、クラス `jhi-toast`（画面の端に固定するスタイル）は実際には付かないと読める。
- イベントの配信 (`EventManager`、`src/app/core/util/event-manager.service.ts`): 1 つの共有された Observable に、名前（`EventWithContent.name`）を付けて流す。`subscribe(eventNames, callback)` は名前で絞り込んで購読する。
- HTTP エラーのステータスと表示内容 (`AlertError.handleHttpError()`):

| HTTP ステータス | 呼ばれる処理 | 表示内容 |
| --- | --- | --- |
| 0（サーバーに到達できない） | `addErrorAlert()` | 翻訳キー `error.server.not.reachable`（「Server not reachable」） |
| 400 | `handleBadRequest()` | レスポンスヘッダーと本文で決まる（下の表を参照） |
| 404 | `addErrorAlert()` | 翻訳キー `error.url.not.found`（「Not found」） |
| 上記以外（403、500 など） | `handleDefaultError()` | 本文に `message` があれば、翻訳キー `error.<message>`（既定文言は `detail`、埋め込み値は `params`）。なければ本文をそのまま表示する |

- 400 のときの表示内容 (`handleBadRequest()`):

| 応答の内容 | 表示内容 |
| --- | --- |
| ヘッダー `x-jhipstersampleapplicationapp-error` の値が翻訳キーの形 | 翻訳キー `<値>`。`x-jhipstersampleapplicationapp-params` があれば、`entityName` に翻訳キー `global.menu.entities.<params>` の文言を埋め込む |
| ヘッダー `x-jhipstersampleapplicationapp-error` の値が翻訳キーの形でない | その値を文言として表示する |
| 本文に `fieldErrors` がある | `handleFieldsError()`。`fieldErrors` の要素ごとに 1 つのアラート。文言は翻訳キー `error.<message>`（既定文言 `Error on field "<項目名>"`）、`fieldName` に翻訳キー `jhipsterSampleApplicationApp.<objectName>.<field>` の文言を埋め込む |
| 本文に `message` がある | 翻訳キー `<message>`（既定文言は `detail`、埋め込み値は `params`） |
| 上記以外 | 本文をそのまま表示する |

- `handleFieldsError()` の補足: `message` が `Min`、`Max`、`DecimalMin`、`DecimalMax` のときは `Size` に置き換える。`field` の `[数字]` は `[]` に置き換えてから翻訳キーを作る。
- 使われる翻訳キー（`src/i18n/en/global.json` の `error`）: `server.not.reachable`、`url.not.found`、`NotNull`、`Size`、`userexists`、`emailexists`、`idexists`、`idnull`、`idinvalid`、`idnotfound`。
- スタイル（`src/content/scss/global.scss`）: `.alerts .alert pre` は背景、罫線、余白を除いてアラートの文字体裁を引き継ぐ。`.alerts .jhi-toast` は画面に固定（`position: fixed`）し、位置のクラス（`left`、`right`、`top`、`bottom`）で位置を決める。
