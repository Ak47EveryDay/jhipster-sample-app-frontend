## 2. 機能概要

- 全画面の上部に表示される共通のナビゲーションバーである。
- ブランド（ロゴ、アプリケーション名、バージョン）と、Home、Entities、Administration、Language、Account の 5 種類のメニューでできている。
- 表示は `AccountService` の読み取り専用シグナル `account` に応じて変わる。Entities メニューと Account メニューの Settings、Password、Sign out はログイン中だけ表示し、Sign in と Register は未ログインのときだけ表示する。
- Administration メニューは、ログイン中のアカウントが権限 `ROLE_ADMIN` を持つときだけ表示する（構造ディレクティブ `HasAnyAuthorityDirective` による）。
- `Navbar.ngOnInit()` が `ProfileService.getProfileInfo()` で `GET management/info` を呼び、その結果で API メニューと Database メニューの表示を切り替える。
- Language メニューは `LANGUAGES` が 2 つ以上のときだけ表示される。現在は `'en'` の 1 つだけであるため、表示されない。
- 「Sign out」でログアウトしてホームへ遷移する。
- 入力項目はない。

ナビゲーションバーを含むページの枠組みはページフレーム `Main`（`src/app/layouts/main/main.ts`、セレクター `jhi-main`）である。ルートコンポーネント `App`（`src/app/app.ts`、セレクター `jhi-app`）はテンプレート `<jhi-main />` だけを持ち、`Main` がページリボン、ナビゲーションバー、画面本体、フッターを並べる。この文書では、文脈のためにページフレームも併せて説明する。

## 3. 画面レイアウト

**ページフレーム（`Main`）**

`Main` のテンプレート `src/app/layouts/main/main.html` は、上から次の要素を置く。

```
<jhi-main />                                        … src/app/layouts/main/main.html
    <jhi-page-ribbon />                             … ページリボン
    <div>
        <router-outlet name="navbar" />             … ナビゲーションバー（この部品）
    </div>
    <div class="container-fluid">
        <div class="card jh-card">
            <router-outlet />                       … 画面本体（主アウトレット）
        </div>
        <jhi-footer />                              … フッター
    </div>
```

| 領域 | テンプレート上の要素 | 表示条件 | 対応する文書 |
| --- | --- | --- | --- |
| ページリボン領域 | `<jhi-page-ribbon />` | バックエンドのプロファイル情報に `ribbonEnv` があるとき | [ページリボン_画面設計書](../ページリボン/ページリボン_画面設計書.md) |
| ナビゲーションバー領域 | `<router-outlet name="navbar" />` | 常に | この文書の 4 章 |
| 画面本体領域 | `<div class="card jh-card">` の中の `<router-outlet />` | 常に | 各画面の文書 |
| フッター領域 | `<jhi-footer />` | 常に | [フッター_画面設計書](../フッター/フッター_画面設計書.md) |

**ナビゲーションバー（`Navbar`）**

テンプレートのルートは `<nav data-cy="navbar" class="navbar navbar-dark navbar-expand-md bg-dark">` であり、その中にブランド、開閉ボタン、メニュー領域がこの順に置かれる。

```
ブランド領域（<a class="navbar-brand logo" routerLink="/">）
    [ロゴ画像]  JhipsterSampleApplication  <バージョン>
開閉ボタン領域（<a class="navbar-toggler d-lg-none">）
    [bars アイコン]                       … クリックでメニュー領域の開閉を反転する
メニュー領域（<div class="navbar-collapse collapse" id="navbarResponsive">）
    Home                                   … 常に
    Entities ▾                             … ログイン中だけ
        Bank Account / Label / Operation
    Administration ▾                       … 権限 ROLE_ADMIN を持つときだけ
        User Management / Authority / Metrics / Health / Configuration / Logs
        [API]（openAPIEnabled が真のとき）  [Database]（inProduction が偽のとき）
    Language ▾                             … LANGUAGES が 2 つ以上のとき（現在は表示されない）
    Account ▾
        ログイン中:  Settings / Password / Sign out
        未ログイン:  Sign in / Register
```

| 領域 | テンプレート上の要素 | 表示条件 | 4 章の対応 |
| --- | --- | --- | --- |
| ブランド領域 | `<a class="navbar-brand logo" routerLink="/">` | 常に | `### ブランド領域` |
| 開閉ボタン領域 | `<a class="navbar-toggler d-lg-none">` | 常に（幅 768px 以上では Bootstrap の CSS により非表示になる） | `### 開閉ボタン領域` |
| メニュー領域・Home | `routerLink="/"` を持つ `<a class="nav-link">` の `<li>` | 常に | `### メニュー領域・Home` |
| メニュー領域・Entities | `<li ngbDropdown data-cy="entity">` | `account() !== null` | `### メニュー領域・Entities` |
| メニュー領域・Administration | `*jhiHasAnyAuthority="'ROLE_ADMIN'"` を持つ `<li ngbDropdown data-cy="adminMenu">` | 権限 `ROLE_ADMIN` を持つこと | `### メニュー領域・Administration` |
| メニュー領域・Language | `<li ngbDropdown class="nav-item dropdown pointer">`（`id="languagesnavBarDropdown"`） | `languages.length > 1`（現状は偽） | `### メニュー領域・Language` |
| メニュー領域・Account | `<li ngbDropdown data-cy="accountMenu">` | 常に（メニュー項目は `account()` で変わる） | `### メニュー領域・Account` |

| 11 | Language メニューの言語名 | クリック | なし（言語を切り替える） | `(click)="changeLanguage(language); collapseNavbar()"` |
| 12 | Sign in | クリック | `/login` | `login()` |
| 13 | Register | クリック | `/account/register` | `routerLink="/account/register"`、`collapseNavbar()` |
| 14 | Settings、Password | クリック | `/account/settings`、`/account/password` | `routerLink`、`collapseNavbar()` |
| 15 | Sign out | クリック | `/` | `logout()` |
| 16 | 画面 | ルートが変わった | なし（選択中のメニューにクラス `active` を付ける） | `routerLinkActive` |

### 5.2 イベント詳細

#### 5.2.1 画面初期化（ページフレーム）

- トリガー: アプリケーションの起動。`App` のテンプレート `<jhi-main />` によって `Main` が生成され、`Main.ngOnInit()` が実行される。
- 処理手順:
  1. `this.accountService.identity().subscribe()` を呼ぶ。キャッシュがなければ `GET api/account` が送られ、結果がシグナル `account` に入る。これにより、ブラウザーに保存されたトークンでログイン状態が復元される。
  2. `this.translateService.onLangChange.subscribe(...)` で言語の変更を購読する。言語が変わるたびに、`this.titleStrategy.updateTitle(this.router.routerState.snapshot)` でブラウザーのタイトルを更新し、`dayjs.locale(langChangeEvent.lang)` で日付のロケールを変え、`this.renderer.setAttribute(this.htmlElement, 'lang', langChangeEvent.lang)` で `<html>` 要素の `lang` 属性を変える。
- 状態変化: シグナル `account`（`AccountService`）。
- 遷移: なし。ただし `identity()` の成功時に保存された URL があれば、`AccountService.navigateToStoredUrl()` がそこへ遷移する。
- 補足: `Main` が import しているのは `RouterOutlet`、`Footer`、`PageRibbon` だけである。ナビゲーションバーはルート（名前付きアウトレット）によって表示される。

#### 5.2.2 画面初期化（ナビゲーションバー）

- トリガー: `Navbar.ngOnInit()`。
- 処理手順:
  1. `this.profileService.getProfileInfo()` を呼ぶ。`ProfileService` は最初の呼び出しだけ `GET management/info` を送り、その結果を `shareReplay()` で後の呼び出しにも共有する。
  2. `ProfileService` の `map` が応答を `ProfileInfo` に変換する。`inProduction` は `activeProfiles` が `prod` を含むか、`openAPIEnabled` は `api-docs` を含むかである。
  3. 受け取った `profileInfo` で `this.inProduction.set(profileInfo.inProduction ?? true)` と `this.openAPIEnabled.set(profileInfo.openAPIEnabled ?? false)` を実行する。
  4. `openAPIEnabled()` が真なら Administration メニューに API が、`!inProduction()` が真なら Database が表示される。
- 状態変化: シグナル `inProduction`、シグナル `openAPIEnabled`。
- 遷移: なし。
- 補足: `subscribe` に `error` のハンドラーはない。失敗したときは 2 つのシグナルは初期値（`inProduction` は `true`、`openAPIEnabled` は `false`）のままであると読める。HTTP エラーは `errorHandlerInterceptor` がイベント `jhipsterSampleApplicationApp.httpError` として配信し、表示中の画面に `<jhi-alert-error />` があればそこに表示される。
- 補足: ページリボン（`PageRibbon`）も同じ `getProfileInfo()` を呼ぶため、ナビゲーションバーとページリボンでリクエストは 1 回であると読める。

#### 5.2.3 開閉ボタンクリック

- トリガー: `(click)="isNavbarCollapsed.update(isNavbarCollapsed => !isNavbarCollapsed)"`。
- 処理手順: シグナル `isNavbarCollapsed` が反転する。メニュー領域は `[ngbCollapse]="isNavbarCollapsed()"` を持つため、真のときは閉じ、偽のときは開く（開閉の描画は ng-bootstrap の指定である）。`[attr.aria-expanded]="!isNavbarCollapsed()"` も同じ値に従う。
- 状態変化: シグナル `isNavbarCollapsed`。
- 遷移: なし。
- 補足: 幅が 768px 以上のときは、Bootstrap のクラス `navbar-expand-md` によりメニュー領域が常に展開され、開閉ボタンは非表示になる（Bootstrap の CSS の働きであり、本リポジトリのコードによる処理ではない）。

#### 5.2.4 メニュー項目のクリック（遷移を伴うもの）

- トリガー: ブランド、Home、Entities、Administration（Database を除く）、Account の Register、Settings、Password のクリック。
- 処理手順:
  1. 各メニュー項目は `(click)="collapseNavbar()"` を持ち、クリックすると `isNavbarCollapsed` が `true` になり、メニュー領域が閉じる。
  2. `routerLink` に従って遷移する。遷移先のうち `/admin` 配下、`/user-management`、`/authority`、`/account/settings`、`/account/password`、エンティティの各画面にはルートガード `userRouteAccessService` がある。
- 状態変化: シグナル `isNavbarCollapsed`。
- 遷移: 5.4 のとおり。

#### 5.2.5 Language メニューによる言語の切り替え

- トリガー: 言語名のクリック。現在の `LANGUAGES` ではメニュー自体が表示されないため、起こらない。
- 処理手順:
  1. `changeLanguage(languageKey)` が `this.stateStorageService.storeLocale(languageKey)` で言語コードを `sessionStorage` に保存する。
  2. 続けて `this.translateService.use(languageKey)` で言語を切り替える。言語の変更は `onLangChange` として購読側に伝わる（`Main`、`TranslateDirective`、`ActiveMenuDirective` などが購読している）。
  3. `collapseNavbar()` でメニュー領域を閉じる。
- 状態変化: `sessionStorage` のキー `locale`、シグナル `isNavbarCollapsed`。
- 遷移: なし。

#### 5.2.6 Sign in、Register のクリック

- トリガー: 未ログインのときに Account メニューに表示される Sign in と Register のクリック。
- 処理手順: Sign in は `login()` が `this.router.navigate(['/login'])` を呼ぶ。Register は `routerLink="/account/register"` で遷移する。
- 状態変化: なし。
- 遷移: `/login`、`/account/register`。

#### 5.2.7 Sign out クリック（ログアウト）

- トリガー: `(click)="logout()"`。
- 処理手順:
  1. `this.collapseNavbar()` でメニュー領域を閉じる。
  2. `this.loginService.logout()` を呼ぶ。`LoginService.logout()` は `AuthServerProvider.logout()` を購読し、その完了時に `this.accountService.authenticate(null)` を実行する。`AuthServerProvider.logout()` は `StateStorageService.clearAuthenticationToken()` でトークンを `sessionStorage` と `localStorage` から削除する。
  3. `authenticate(null)` によりシグナル `account` が `null` になり、アカウントのキャッシュ（`accountCache$`）も消える。メニューの表示は未ログインの内容に切り替わる。
  4. `this.router.navigate([''])` でホームへ遷移する。
- 状態変化: シグナル `account`（`null`）、シグナル `isNavbarCollapsed`、ブラウザーのストレージからトークンが消える。
- 遷移: `/`。
- 補足: ログアウトでバックエンドを呼ぶことはない。

#### 5.2.8 アカウントの状態による表示の切り替え

- トリガー: シグナル `account` の値が変わること（ログイン、ログアウト、`identity()` による取得、設定画面での保存）。
- 処理手順:
  1. テンプレートの `@if (account() !== null)` が評価し直され、Entities メニューの表示と非表示が切り替わる。
  2. Account メニューは `@let accountRef = account()` の値で、`accountRef !== null` のとき Settings、Password、Sign out を、その以外のとき Sign in、Register を表示する。
  3. Administration メニューの `HasAnyAuthorityDirective` は、シグナル `account` と `AccountService.hasAnyAuthority()` から `computed` で `hasPermission` を作り、`effect` で要素を描画または除去する。
- 状態変化: なし（`account` の変化に追従するだけである）。
- 遷移: なし。

#### 5.2.9 ルートが変わったとき（選択中のメニューの強調）

- トリガー: ルートの遷移。
- 処理手順: `routerLinkActive="active"` を持つ要素のうち、URL が一致するものに Angular がクラス `active` を付ける。これは Angular の標準の動きであり、本リポジトリのコードではない。
- 補足: 指定の仕方は要素ごとに次のとおりである。
  - Home の `<li>`、Entities の `<li>`、Account の `<li>`、Entities の各メニュー項目は `[routerLinkActiveOptions]="{ exact: true }"` を持ち、URL が完全に一致したときだけ `active` になる。`<li>` 自身には `routerLink` がないため、コードからは配下のリンクのいずれかが一致したときに `active` になると読める。
  - User Management、Authority、Metrics、Health、Configuration、Logs、API のメニュー項目は `routerLinkActive="active"` だけであるため、前方一致で `active` になる。

### 5.3 API呼び出し一覧

| No. | 目的 | メソッド | パス | 要求パラメーター | 応答 | 成功時 | エラー時 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 動作環境情報の取得 | GET | `management/info` | なし | 200: `InfoResponse`（`activeProfiles`、`display-ribbon-on-profiles`、`git`、`build`） | シグナル `inProduction`、`openAPIEnabled` が設定され、API メニューと Database メニューの表示が決まる | 画面側にエラー処理はない。2 つのシグナルは初期値のままである |

補足:

- 呼び出し元は `ProfileService.getProfileInfo()`（`src/app/layouts/profiles/profile.service.ts`）であり、URL は `infoUrl`（`${serverApiUrl}management/info`）である。
- バックエンドでは `/management/info` は認証不要である（バックエンドの `src/main/java/io/github/jhipster/sample/config/SecurityConfiguration.java` の `permitAll`）。エンドポイントのパスはバックエンドの `src/main/resources/config/application.yml`（`management.endpoints.web.base-path`）による。
- `activeProfiles` の中身はバックエンドの起動時のプロファイルに依存するため、フロントエンドのコードからは確認できない。`git` と `build` が出力に含まれるかも同様である。
- 要求ヘッダーは `authInterceptor` がトークンのあるとき `Authorization: Bearer <トークン>` を付ける。401 のときは `authExpiredInterceptor` が動く（`management/info` は `api/account` を含まない）。

### 5.5 利用箇所

- `Navbar` は `src/app/app.routes.ts` の `loadComponent: () => import('./layouts/navbar/navbar')` で読み込まれ、`src/app/layouts/main/main.html` の `<router-outlet name="navbar" />` に表示される。テンプレートに `<jhi-navbar />` を直接書いている箇所はない。
- 主アウトレットに表示される 35 のルートすべて（ホーム 1、ログイン 1、アカウント 6、管理画面 5、エンティティ 19、エラー画面 3）で表示される。ルートに `canActivate` のない画面（ホーム、ログイン、登録など）でも表示され、その場合は未ログインの内容になる。
- ページフレーム `Main` を import しているのは `src/app/app.ts` だけである。

### 5.6 内部構造

- `Navbar` が依存するサービス等は次のとおりである。
  - `AccountService`: 読み取り専用シグナル `account`。メニューの表示の分岐に使う。
  - `LoginService`: `logout()` だけを使う。
  - `StateStorageService`: `changeLanguage()` で `storeLocale()` を呼ぶ。
  - `ProfileService`: `getProfileInfo()`。シグナル `inProduction`、`openAPIEnabled` の設定に使う。
  - `TranslateService`: `changeLanguage()` で `use()` を呼ぶ。
  - `Router`: `login()`、`logout()` の遷移に使う。
  - 環境ファイル `src/environments/environment.ts` の `VERSION`: ブランドに表示するバージョンの元。`LANGUAGES`: Language メニューの言語の一覧。
- `Navbar` が使うディレクティブ等は次のとおりである。
  - `HasAnyAuthorityDirective`（`src/app/shared/auth/has-any-authority.directive.ts`）: 権限 `ROLE_ADMIN` で Administration メニューの描画を制御する。詳しくは [ルートガードと認可_画面設計書](../ルートガードと認可/ルートガードと認可_画面設計書.md) に書く。
  - `ActiveMenuDirective`（`src/app/layouts/navbar/active-menu.directive.ts`、セレクター `[jhiActiveMenu]`）: 入力 `jhiActiveMenu` の値と `TranslateService.getCurrentLang()` が等しければホスト要素にクラス `active` を付け、等しくなければ除く。`ngOnInit()` で `onLangChange` を購読し、言語が変わるたびに判定し直す。利用箇所は Language メニューだけである。
  - `TranslateDirective`、`FindLanguageFromKeyPipe`（`src/app/shared/language/`）: 文言の翻訳と言語名の表示。[国際化_画面設計書](../国際化/国際化_画面設計書.md) に書く。
  - ng-bootstrap の `NgbCollapse`（メニュー領域の開閉）、`NgbDropdown`、`NgbDropdownToggle`、`NgbDropdownMenu`（ドロップダウン）。`FontAwesomeModule`（アイコン）。
- ページフレーム `Main` が依存するサービス等は次のとおりである。`AccountService`（`identity()`）、`TranslateService`（`onLangChange`）、`TitleStrategy`（`updateTitle()`。`src/app/app-page-title-strategy.ts` の `AppPageTitleStrategy` が渡される）、`Router`、`DOCUMENT`、`RendererFactory2`。`Main` が import する部品は `Footer` と `PageRibbon` である。
- メニューのモデル `NavbarItem`（`src/app/layouts/navbar/navbar-item.model.d.ts`）は、`name`、`route`、`translationKey` の 3 つのプロパティーを持つ型であるが、本体からは import されていない。メニュー項目はテンプレートに直接書かれている。
