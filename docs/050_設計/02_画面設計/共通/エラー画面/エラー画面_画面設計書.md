## 2. 機能概要

- エラーが起きたことを利用者に知らせる共通の画面である。
- 1 つのコンポーネント `Error` が、次の 3 つのルートで使い分けられる。表示するメッセージはルートの `data.errorMessage`（翻訳キー）で指定する。
  - `/error`: メッセージなし。見出しの「Error page!」だけを表示する。
  - `/accessdenied`: 翻訳キー `error.http.403`（「You are not authorized to access this page.」）。
  - `/404`: 翻訳キー `error.http.404`（「The page does not exist.」）。
- 定義にないパスを開いたときは、ワイルドカードのルート（`**`）が `/404` へリダイレクトする。
- 画面はページフレーム `Main` の `<router-outlet />` の中に表示され、ナビゲーションバーとフッターは通常どおり出る。
- 画面に戻るボタンやリンクはない。元の画面へ戻るにはブラウザーの戻る操作を使う。
- 画面は API を呼ばない。

## 3. 画面レイアウト

テンプレートのルートは `<div>` で、Bootstrap の格子（`row`、`col-md-4`、`col-md-8`）で左右に分かれる。

```
<jhi-error />                                   … src/app/layouts/error/error.html
    <div>
        <div class="row">
            <div class="col-md-4">
                <span class="hipster img-fluid rounded"></span>     … 画像
            </div>
            <div class="col-md-8">
                <h1 jhiTranslate="error.title">Error page!</h1>     … 見出し
                @if (errorMessage(); as errMessage) {
                    <div class="alert alert-danger">{{ errMessage }}</div>   … エラーメッセージ
                }
            </div>
        </div>
    </div>
```

| 領域 | テンプレート上の要素 | 表示条件 | 4 章の対応 |
| --- | --- | --- | --- |
| 見出し領域 | `<div class="col-md-8">` の中の `<h1 jhiTranslate="error.title">` | 常に | `### 見出し領域` |
| エラーメッセージ領域 | `<div class="alert alert-danger">` | `errorMessage()` が空文字列でも `undefined` でもないとき | `### エラーメッセージ領域` |

## 5. イベント処理

### 5.1 イベント一覧

| No. | イベント発生源 | イベント | 遷移先 | イベント物理名 |
| --- | --- | --- | --- | --- |
| 1 | 画面 | 初期化（ルートの `data` を受け取る） | なし | `ngOnInit()` 内の `this.route.data.subscribe(...)` |
| 2 | 画面外（言語の変更） | 翻訳言語が変わった | なし | `translateService.onLangChange`（購読） |
| 3 | 画面 | 破棄（別の画面へ遷移した） | － | `ngOnDestroy()`（`langChangeSubscription.unsubscribe()`） |

### 5.2 イベント詳細

#### 5.2.1 画面初期化

- トリガー: `/error`、`/accessdenied`、`/404` のいずれかへ遷移してコンポーネントが生成されること。
- 処理手順:
  1. `ngOnInit()` が `this.route.data` を購読する。`ActivatedRoute.data` は、そのルートの `data` を流す Observable である（Angular の標準の動きであり、本リポジトリのコードではない）。
  2. 受け取った `routeData.errorMessage` に値があるとき、その値（翻訳キー）を `errorKey` に入れて `getErrorMessageTranslation()` を呼ぶ。続けて `translateService.onLangChange` を購読し、言語が変わるたびに `getErrorMessageTranslation()` を呼ぶようにする（購読は `langChangeSubscription` に保持する）。
  3. `routeData.errorMessage` に値がないとき（`/error`）は、何もしない。`errorMessage` は `undefined` のままであり、エラーメッセージ領域は表示されない。
  4. `getErrorMessageTranslation()` は、まず `errorMessage` に空文字列を設定する。次に `translateService.get(errorKey)` を購読し、届いた翻訳文を `errorMessage` に設定する。
- 状態変化: `errorKey`、`errorMessage`、`langChangeSubscription`。
- 遷移: なし。

#### 5.2.2 言語が変わったとき

- トリガー: `TranslateService.use()` によって言語が変わり、`onLangChange` が流れること。
- 処理手順: 5.2.1 で購読した `onLangChange` が `getErrorMessageTranslation()` を呼び、メッセージを新しい言語で読み直す。`/error` では購読していないため、何も起こらない。
- 状態変化: `errorMessage`。
- 遷移: なし。
- 補足: 現在は `LANGUAGES` が `'en'` の 1 つだけであるため、実際に言語が変わるかどうかはコードからは確認できない（[国際化_画面設計書](../国際化/国際化_画面設計書.md) 参照）。

#### 5.2.3 画面の破棄

- トリガー: ほかの画面へ遷移してコンポーネントが破棄されること。
- 処理手順: `ngOnDestroy()` が、`langChangeSubscription` があれば購読を解除する。
- 状態変化: なし。

### 5.4 画面遷移

この画面を表示するきっかけ（遷移元）は次のとおりである。この画面から出ていく遷移はない。

| 遷移先 | 条件 | トリガー |
| --- | --- | --- |
| アクセス拒否（`/accessdenied`） | ログインしているが、開こうとしたルートの `data.authorities` に自分の権限がない | `userRouteAccessService` の `router.navigate(['accessdenied'])`（`src/app/core/auth/user-route-access.service.ts`） |
| アクセス拒否（`/accessdenied`） | ナビゲーション中のエラーの `status` が 403 | `withNavigationErrorHandler` の `router.navigate(['/accessdenied'])`（`src/app/app.config.ts`） |
| Not Found（`/404`） | 詳細・編集のリゾルバーで `GET` が 404 を返した | 5 つのリゾルバーの `router.navigate(['404'])`（`src/app/entities/bank-account/route/bank-account-routing-resolve.service.ts`、`src/app/entities/label/route/label-routing-resolve.service.ts`、`src/app/entities/operation/route/operation-routing-resolve.service.ts`、`src/app/entities/admin/user-management/route/user-management-routing-resolve.service.ts`、`src/app/entities/admin/authority/route/authority-routing-resolve.service.ts`） |
| Not Found（`/404`） | ナビゲーション中のエラーの `status` が 404 | `withNavigationErrorHandler` の `router.navigate(['/404'])`（`src/app/app.config.ts`） |
| Not Found（`/404`） | ルート定義にないパスを開いた | `path: '**'` の `redirectTo: '/404'`（`src/app/layouts/error/error.route.ts`） |
| エラー（`/error`） | 詳細・編集のリゾルバーで 404 以外のエラーが返った（到達できないときの 0 を含む） | 5 つのリゾルバーの `router.navigate(['error'])`（上記のファイル） |
| エラー（`/error`） | ナビゲーション中のエラーの `status` が 403、404、401 のいずれでもない | `withNavigationErrorHandler` の `router.navigate(['/error'])`（`src/app/app.config.ts`） |

補足:

- 未ログインで `/accessdenied` や `/404` を開いても、ログイン画面には戻されない（ルートに `canActivate` がないためである）。
- リゾルバーは 5 つとも同じ形である。ルートパラメーターがあって、かつサービスの `find()` が失敗したときに、404 なら `404` へ、それ以外なら `error` へ遷移し、`EMPTY` を返す。リゾルバーが自前で遷移するため、ナビゲーションエラーのハンドラーが動く場面はコードからは確認できない。

### 5.5 内部構造

- `Error` は `TranslateDirective` だけを import する。注入するのは `TranslateService` と `ActivatedRoute` である（`src/app/layouts/error/error.ts`）。
- `errorMessage` は `signal<string | undefined>(undefined)` である。テンプレートの `@if (errorMessage(); as errMessage)` は、値が `undefined` と空文字列のときに偽になる。そのため、翻訳が届くまでの間（5.2.1 の手順 4 で空文字列を入れた後）はメッセージ領域が表示されない。
- 3 つのルートとも `title: 'error.title'` を持つため、ブラウザーのタイトルは「Error page!」になる（[画面タイトル_画面設計書](../画面タイトル/画面タイトル_画面設計書.md) 参照）。
