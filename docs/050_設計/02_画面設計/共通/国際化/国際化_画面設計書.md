## 2. 機能概要

- 翻訳の仕組みに ngx-translate（`@ngx-translate/core`）を使う。設定は `provideTranslation()` にまとめ、`appConfig` の providers に指定する（`src/app/app.config.ts`）。
- 対応する言語は英語（`en`）の 1 つだけである。言語の一覧は `LANGUAGES`（`src/app/config/language.constants.ts`）である。
- 翻訳文は `src/i18n/en/` 配下の JSON ファイル（19 ファイル）に、画面・機能ごとに分けて置く。
- ビルド時に esbuild のプラグイン `build-plugins/i18n-esbuild.ts` が 19 ファイルを 1 つに結合し、`i18n/en.json` として読み込めるようにする。結合した結果はビルドの出力にだけ存在し、リポジトリの `src/i18n/` 配下には置かれていない。
- テンプレートで文言を表示する方法は 3 つある。
  - `jhiTranslate` ディレクティブ（本リポジトリの `TranslateDirective`）。ほとんどの画面で使う。
  - ngx-translate 標準の `translate` パイプ。主に入力欄の `placeholder` で使う。
  - `findLanguageFromKey` パイプ。言語コードを言語名に変える。
- TypeScript のコードからは `TranslateService` の `get()`、`instant()`、`use()` を使う。
- 翻訳キーが見つからないときは、`translation-not-found[<キー>]` と表示する。
- 選んだ言語は sessionStorage のキー `locale` に保存する。次にアプリを開いたときに引き継ぐ。
- 国際化の部品は API を呼ばない。

## 5. イベント処理

### 5.1 イベント一覧

| No. | イベント発生源 | イベント | 遷移先 | イベント物理名 |
| --- | --- | --- | --- | --- |
| 1 | アプリの起動 | 翻訳の読み込みと初期言語の決定 | なし | `provideAppInitializer()` の中の `translateService.use(langKey)` |
| 2 | テンプレート | `jhiTranslate`、`translateValues` の値が設定される、変わる | なし | `TranslateDirective.ngOnChanges()`（`getTranslation()`） |
| 3 | 画面外（言語の変更） | 言語が変わる、翻訳が読み直される | なし | `translateService.onLangChange`、`onTranslationChange`（購読） |
| 4 | 言語メニュー | 言語が選ばれる | なし | `Navbar.changeLanguage(languageKey)` |
| 5 | アカウントの取得 | アカウントに言語（`langKey`）がある | なし | `AccountService.identity()` の `translateService.use(account.langKey)` |
| 6 | 設定画面 | 言語を変えて保存できる | なし | `Settings.save()` の `translateService.use(account.langKey)` |
| 7 | TypeScript のコード | 翻訳キーから文言を得る | なし | `translateService.get()`、`translateService.instant()` |

### 5.2 イベント詳細

#### 5.2.1 アプリの起動

- トリガー: アプリの初期化（`appConfig` の providers が適用されること）。
- 処理手順:
  1. `provideAppInitializer()` が `translateService.setFallbackLang('en')` を呼ぶ。
  2. `stateStorageService.getLocale()`（sessionStorage のキー `locale`）で前回選んだ言語を読む。値がなければ `'en'` を使う。
  3. `translateService.use(langKey)` を呼ぶ。loader の `translatePartialLoader()` が `loadLocale(lang)` を呼び、言語の翻訳文を読み込む。
  4. `loadLocale(locale)`（`src/i18n/index.ts`）は 2 つの動的 import を行う。`angularLanguages[locale]()` で Angular のロケールデータ（`@angular/common/locales/en`）を読み、`languagesData[locale]()` で翻訳文（`i18n/en.json`）を読む。
- 状態変化: ngx-translate が持つ翻訳と言語（`getCurrentLang()`）。
- 遷移: なし。

#### 5.2.2 `jhiTranslate` の設定と変更

- トリガー: `jhiTranslate` を持つ要素が描かれる、または入力の値が変わること。
- 処理手順:
  1. `ngOnChanges()` が `getTranslation()` を呼ぶ。
  2. `translateService.get(jhiTranslate(), translateValues())` を購読し、届いた値を `el.nativeElement.innerHTML` に設定する。
  3. `ngOnInit()` で `onLangChange` と `onTranslationChange` を購読しており、どちらかが流れるたびに `getTranslation()` を呼ぶ。
  4. `ngOnDestroy()` で `directiveDestroyed`（`Subject`）を完了させ、購読を止める。
- 状態変化: 要素の `innerHTML`。
- 遷移: なし。
- 補足:
  - 購読が失敗したときの処理（`error:`）は文字列を返すだけで、要素の内容は変えない。そのためテンプレートに書いた既定の英語が残ると読める。
  - `jhiTranslate` は要素の中身をまるごと置き換える。テンプレートに書かれた英語は、翻訳が届くまでの間だけ見える。
  - 翻訳キーが見つからないときは、未定義キーの処理（`MissingTranslationHandlerImpl`）により `translation-not-found[<キー>]` が要素に表示される。

#### 5.2.3 言語が変わったとき

- トリガー: `translateService.use()` が別の言語で呼ばれること。
- 処理手順: ngx-translate が `onLangChange` を流す。購読している部品がそれぞれ文言を読み直す。
  - `TranslateDirective`: すべての `jhiTranslate` 要素の `innerHTML` を設定し直す（5.2.2）。
  - `ActiveMenuDirective`（`src/app/layouts/navbar/active-menu.directive.ts`）: 現在の言語でメニューの強調を更新する。
  - `Main`（`src/app/layouts/main/main.ts`）: `titleStrategy.updateTitle(this.router.routerState.snapshot)` でブラウザーのタイトルを読み直し、`dayjs.locale(langChangeEvent.lang)` で日付のライブラリーのロケールを変え、`<html>` 要素の `lang` 属性を新しい言語に設定する。
  - `Error`（`src/app/layouts/error/error.ts`）: エラーメッセージを読み直す。
- 状態変化: 各要素の文言、ブラウザーのタイトル、`<html>` の `lang` 属性、dayjs のロケール。
- 遷移: なし。

#### 5.2.4 言語メニューの選択

- トリガー: ナビゲーションバーの言語メニューで言語を選ぶこと。
- 処理手順: `Navbar.changeLanguage(languageKey)` が `stateStorageService.storeLocale(languageKey)` で sessionStorage に保存し、`translateService.use(languageKey)` で言語を切り替える。
- 状態変化: sessionStorage の `locale`、翻訳と言語。
- 遷移: なし。
- 注意: 言語メニューは `@if (languages.length > 1)` のときだけ表示される（`src/app/layouts/navbar/navbar.html`）。`LANGUAGES` が `'en'` の 1 つだけである現在のコードでは、メニューは表示されず、この処理は呼ばれない。

#### 5.2.5 アカウントの言語

- トリガー: `AccountService.identity()` がアカウントを取得すること。
- 処理手順: アカウントに `langKey` があり、かつ sessionStorage に言語の保存（`getLocale()`）がないとき、`translateService.use(account.langKey)` でアカウントの言語に切り替える。
- 状態変化: 翻訳と言語。
- 遷移: なし。

#### 5.2.6 TypeScript のコードからの利用

- トリガー: コンポーネントやサービスが `TranslateService` を使うこと。
- 処理手順: 使っている箇所は次のとおりである。

| 使い方 | 箇所 | 用途 |
| --- | --- | --- |
| `translateService.get()` | `src/app/app-page-title-strategy.ts`、`src/app/layouts/error/error.ts` | ブラウザーのタイトルとエラーメッセージの翻訳（Observable） |
| `translateService.instant()` | `src/app/core/util/alert.service.ts`、`src/app/shared/alert/alert-error.ts` | アラートの文言、項目名とエンティティ名の翻訳 |

- 遷移: なし。

### 5.5 利用箇所

- `jhiTranslate` を使っているテンプレートは 45 ファイルである（`src/app` 配下の `.html`）。
- `jhiTranslate` をコードで使っているのは `TranslateDirective` 自身と、`PageRibbon`（`src/app/layouts/profiles/page-ribbon.ts`）、`ItemCount`（`src/app/shared/pagination/item-count.ts`）である。
- `TranslatePipe` を import しているのは、ログイン、登録、パスワード変更、パスワード再設定依頼、パスワード再設定完了、設定の各コンポーネントと、`Filter`（`src/app/shared/filter/filter.ts`）である。

### 5.6 内部構造

- 翻訳文の結合（`build-plugins/i18n-esbuild.ts`）: `angular.json` の `plugins` に指定された esbuild プラグインである。`src/i18n/<言語>/` 配下の `*.json` を `deepmerge` で結合し、`import('i18n/<言語>.json')` がその結果を返すようにする。ファイルが同じパスに置かれていないのはこのためである。
- 結合の順序: `prepareLanguage()` は `glob('*.json')` で見つかった順に結合する。同じキーが複数のファイルにあるときは後から結合したファイルの値で上書きされると読める（`deepmerge` の動きであり、本リポジトリのコードではない。順序も確認していない）。
- 未定義のキー: `MissingTranslationHandlerImpl.handle()` は `translation-not-found[<キー>]` を返す。`AlertService.addAlert()` はこの文言と一致した場合を「翻訳できない」とみなし、翻訳キー自体を文言にする（[アラート_画面設計書](../アラート/アラート_画面設計書.md) 参照）。
- 言語の保存: `StateStorageService` の `storeLocale()`、`getLocale()`、`clearLocale()` が sessionStorage のキー `locale` を扱う（`src/app/core/auth/state-storage.service.ts`）。`clearLocale()` を呼んでいる箇所は本体のコードにない。
- `I18N_HASH`: プラグインは翻訳ファイルのハッシュをビルド時定数 `I18N_HASH` として定義するが、これを参照している箇所は本体のコードにない。
- ユーザーの言語: 登録画面は `langKey` に `translateService.getCurrentLang() ?? 'en'` を送る（`src/app/account/register/register.ts`）。ユーザ管理登録・編集の言語の選択肢は `LANGUAGES` である（`langKeyValues = LANGUAGES`、`src/app/entities/admin/user-management/update/user-management-update.ts`）。
