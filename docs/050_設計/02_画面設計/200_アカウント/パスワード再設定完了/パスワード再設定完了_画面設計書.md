## 2. 機能概要

- パスワード再設定のメールのリンクを開いたユーザーが、新しいパスワードとその確認を入力してパスワードを再設定する。URL のクエリパラメーター `key`（リセットキー）と新しいパスワードを `POST api/account/reset-password/finish` に送る。確認用のパスワードは送らない。
- クエリパラメーター `key` がないときは「The reset key is missing.」を表示し、フォームは表示しない。
- 再設定に成功するとフォームを隠し、「Your password has been reset.」の成功アラートと、ログイン画面への「sign in」リンクを表示する。自動では遷移しない。
- 失敗すると「Your password couldn't be reset.」の危険アラートを表示する。エラーの種類によらず表示は同じである。
- 新しいパスワードと確認用のパスワードが一致しないときは要求を送らず、「The password and its confirmation do not match!」の危険アラートを表示する。
- New password と New password confirmation は必須である。フォームが無効な間は Validate new password ボタンが無効になる。
- New password の下にパスワード強度バーを表示する。強度は表示するだけで、フォームの妥否には影響しない。
- この画面はトークンを保存せず、アカウントの状態も変えない。再設定してもログイン状態にはならない。
- この画面には `<jhi-alert-error />` と `<jhi-alert />` はない。

## 3. 画面レイアウト

画面は `Main` の `<router-outlet />` の中、`<div class="card jh-card">` の内側に表示される（`src/app/layouts/main/main.html`）。テンプレートのルートは `<div>` で、その中の中央寄せの `<div class="d-flex justify-content-center">` と `<div class="col-md-4">` の中を、上から順に次の領域が占める。

```
見出し領域（<h1 jhiTranslate="reset.finish.title">）
    Reset password
アラート領域
    The reset key is missing.                          … initialized() && !key()
    Choose a new password                              … key() && !success()（案内）
    Your password couldn't be reset. ...               … error()
    Your password has been reset. Please sign in.      … success()
    The password and its confirmation do not match!    … doNotMatch()
入力フォーム領域（<form name="form">）                    … key() && !success()
    New password               … パスワードボックス、パスワード強度バー
    New password confirmation  … パスワードボックス
ボタン領域
    [Validate new password]
```

| 領域 | テンプレート上の要素 | 表示条件 | 4 章の対応 |
| --- | --- | --- | --- |
| 見出し領域 | `<h1 jhiTranslate="reset.finish.title">` | 常に | `### 見出し領域` |
| アラート領域 | リセットキーなし、案内、失敗、成功、パスワード不一致の各アラートの `<div>`（要素と表示条件は次の表のとおり） | 次の表のとおり | `### アラート領域` |
| 入力フォーム領域 | `<form name="form" (ngSubmit)="finishReset()" [formGroup]="passwordForm">` の中の 2 つの `<div class="mb-3">` | `key() && !success()` | `### 入力フォーム領域` |
| ボタン領域 | Validate new password ボタン | `key() && !success()`（フォームの中にある） | `### ボタン領域` |

アラート領域の 5 つの要素の表示条件は次のとおりである。

| 要素 | テンプレート上の要素 | 表示条件 |
| --- | --- | --- |
| リセットキーなし | `<div class="alert alert-danger" jhiTranslate="reset.finish.messages.keymissing">` | `initialized() && !key()` |
| 案内 | `<div class="alert alert-warning">`（`reset.finish.messages.info`） | `key() && !success()` |

| 成功 | `<div class="alert alert-success">`（`reset.finish.messages.success` と `sign in` リンク） | `success()` |
| パスワード不一致 | `<div class="alert alert-danger" jhiTranslate="global.messages.error.dontmatch">` | `doNotMatch()` |

### 5.2 イベント詳細

#### 5.2.1 画面初期化（クエリパラメーターの読み取り）

- トリガー: `/account/reset/finish?key=<リセットキー>` への遷移。ルートに `canActivate` も `resolve` もないため、ガードとリゾルバーは動かない。
- 処理手順:
  1. フィールド初期化で `passwordForm` ができ、`key`（`''`）、`initialized`（`false`）などのシグナルが初期化される。
  2. `ngOnInit()` が `this.route.queryParams` を購読する。値が流れるたびに、`params.key` が真なら `this.key.set(params.key)` とし、`this.initialized.set(true)` にする。
  3. `key()` が空のままなら、フォームと案内は表示せず、「The reset key is missing.」を表示する。API は呼ばない。
  4. `key()` があれば、案内とフォームを表示する。
- 状態変化: `key`、`initialized`。
- トークンとアカウントの状態: この画面はトークンを保存せず、`AccountService` のアカウントも変えない。
- 遷移: なし。

#### 5.2.2 表示後のフォーカス設定

- トリガー: 画面の表示が済んだとき。
- 処理手順: `ngAfterViewInit()` は `this.newPassword().nativeElement.focus()` を呼ぶ。
- フォーカスについて: `newPassword` は `viewChild.required<ElementRef>('newPassword')` で定義され、テンプレート参照変数 `#newPassword` を探す。しかし `src/app/account/password-reset/finish/password-reset-finish.html` には `#newPassword` がない（入力欄にあるのは `id="newPassword"` と `name="newPassword"` だけである）。Angular の必須のシグナルクエリーは結果がなければ実行時エラーを投げる（Angular の標準の動きであり、本リポジトリのコードではない）。コードからは、この画面ではフォーカスは設定されず、`ngAfterViewInit()` がエラーを投げると読める。エラーが画面の表示と操作に与える影響は、コードからは確認できない。
- 状態変化: なし。
- 遷移: なし。

#### 5.2.3 入力（New password、New password confirmation）

- トリガー: 各入力欄への入力。
- 処理手順: Reactive Forms がコントロールの値を更新し、バリデーターを評価し直す。この画面には入力時のメソッド呼び出しはない。
- 状態変化: `passwordForm` の各コントロールの値と、`invalid`、`dirty`、`touched` の状態。
- 表示の変化: 各入力欄の下に、コントロールが `invalid` で、かつ `dirty` または `touched` のときだけメッセージのブロックを表示する。
  - New password: `newPasswordRef.errors?.required` なら翻訳キー `global.messages.validate.newpassword.required`、`minlength` なら `global.messages.validate.newpassword.minlength`、`maxlength` なら `global.messages.validate.newpassword.maxlength`。
  - New password confirmation: `confirmPasswordRef.errors?.required` なら翻訳キー `global.messages.validate.confirmpassword.required`、`minlength` なら `global.messages.validate.confirmpassword.minlength`、`maxlength` なら `global.messages.validate.confirmpassword.maxlength`。
- パスワード強度バー `<jhi-password-strength-bar>`（`PasswordStrengthBar`、`src/app/account/password/password-strength-bar/password-strength-bar.ts`）の動き:
  - 入力 `passwordToCheck`（既定値は空文字列）に New password のコントロールの値（`newPasswordRef.value`）を渡す。
  - テンプレートは「Password strength:」の文言と、`<ul id="strengthBar">` の 5 つの `<li class="point">` である。各 `li` は幅 20px、高さ 5px で、既定の背景色は `#ddd` である（`password-strength-bar.scss`）。
  - `constructor` の `effect` が `passwordToCheck()` を読む。値が空のときは何もしない（色は前の表示のまま）。値があれば `measureStrength()` で強度を数値にし、`getColor()` で色と個数を決める。ホスト要素にクラスがあれば取り除いたあと、先頭からその個数の `li` に色を付け、残りを `#DDD` にする。
  - `measureStrength(p)`: 小文字（`/[a-z]+/`）、大文字（`/[A-Z]+/`）、数字（`/\d+/`）、記号（変数 `regex` の正規表現）の 4 種類のうち、含む種類の数を `passedMatches`（0 から 4）とする。`force` の初期値は 0 で、これに `2 * p.length + (p.length >= 10 ? 1 : 0)` と `passedMatches * 10` を加える。次の上限を上から順に適用する。
    - `p.length` が 6 以下なら `force` の上限は 10 である。
    - `passedMatches` が 1 なら上限は 10、2 なら上限は 20、3 なら上限は 40 である。
  - `getColor(s)`: `s` が 10 以下なら 1 個（`#F00`）、10 を超え 20 以下なら 2 個（`#F90`）、20 を超え 30 以下なら 3 個（`#FF0`）、30 を超え 40 以下なら 4 個（`#9F0`）、40 を超えれば 5 個（`#0F0`）である。
  - 強度バーは表示だけである。強度によってフォームを無効にすることはなく、強度の値を送信することもない。例と計算は [パスワード変更_画面設計書](../パスワード変更/パスワード変更_画面設計書.md) の 5.2.2 に書く。
- 遷移: なし。

#### 5.2.4 Validate new password ボタンクリック（パスワードの再設定）

- トリガー: Validate new password ボタン（`type="submit"`）によるフォームの送信（`(ngSubmit)="finishReset()"`）。ボタンは `passwordForm.invalid` の間は無効である。
- 処理手順:
  1. `finishReset()` は最初に `doNotMatch` と `error` を `false` にする。
  2. `this.passwordForm.getRawValue()` から `newPassword` と `confirmPassword` を取り出し、`===` で比較する。
  3. 一致しなければ `this.doNotMatch.set(true)` にして終わる。要求は送らない。
  4. 一致すれば `this.passwordResetFinishService.save(this.key(), newPassword)` を購読する。`PasswordResetFinishService.save(key, newPassword)` は `POST api/account/reset-password/finish` を、本文 `{ key, newPassword }` で送る。
  5. 成功（`next`）: `this.success.set(true)` にする。テンプレートは `@if (key() && !success())` の案内とフォームを隠し、成功アラートと「sign in」リンクを表示する。遷移はしない。フォームの値は消さない。
  6. 失敗（`error`）: `this.error.set(true)` にする。危険アラートを表示する。応答の内容は見ない。フォームと入力値はそのまま残る。
- パスワードの一致チェックについて: バリデーターではなく `finishReset()` の中の比較である。2 つの入力欄が異なっていてもフォームは有効なので Validate new password ボタンは押せる。比較は送信のたびに行われ、入力中には行わない。
- HTTP エラーの共通処理: `errorHandlerInterceptor` は失敗をイベント `jhipsterSampleApplicationApp.httpError` として配信するが、この画面に `<jhi-alert-error />` はないため、配信された内容は表示されない。`authExpiredInterceptor` は 401 のときだけ動くが、バックエンドはこの API を認証なしで受け付けるため、コード上は起こらない。
- バックエンドの動き（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/AccountResource.java`、`finishPasswordReset()`）:
  - 本文を `KeyAndPasswordVM`（`key`、`newPassword`）として受け取る。制約の検証は付いていない。
  - 新しいパスワードが空、4 文字未満、100 文字超のいずれかなら `InvalidPasswordException`（400）を投げる。
  - `UserService.completePasswordReset(newPassword, key)`（バックエンドの `src/main/java/io/github/jhipster/sample/service/UserService.java`）は、リセットキーが一致するユーザーを探す。リセット日時が現在時刻より 1 日前よりも後であること（`user.getResetDate().isAfter(Instant.now().minus(1, ChronoUnit.DAYS))`）を条件にする。条件を満たせば新しいパスワードをハッシュ化して設定し、`resetKey` と `resetDate` を `null` にして、ユーザーのキャッシュを消す。
  - ユーザーが見つからなければ `AccountResourceException` を投げ、400 になる。このときレスポンスの時間差からキーの有無を推測させないため、ダミーのハッシュ化を実行してから例外を投げる。
  - 成功すると 200 を返す。本文もアラートのヘッダーもない。バックエンドのテスト `src/test/java/io/github/jhipster/sample/web/rest/AccountResourceIT.java` は、成功で 200、新しいパスワードが 3 文字の場合とリセットキーが誤っている場合に 400 を検証している。
  - 既存のトークンを無効化する処理はコード上にない。バックエンドの JWT の検証は署名と有効期限だけである（バックエンドの `src/main/java/io/github/jhipster/sample/config/SecurityJwtConfiguration.java` の `jwtDecoder`）。
- 成功後の再送について: 成功するとフォームを隠すため、この画面から同じキーで再送することはできない。コードからは、リセットキーは `null` に置き換わるため、同じ URL をもう一度開いても 400 になり、失敗のアラートになると読める。
- 状態変化: `doNotMatch`、`error`、`success`。
- 遷移: なし。

#### 5.2.5 sign in リンククリック

- トリガー: 成功アラートの中の `sign in`（`routerLink="/login"`）のクリック。
- 処理手順: ログイン画面へ遷移する。ログイン画面の初期化で、すでにログイン済みならホームへ遷移する。
- 状態変化: なし（画面が破棄される）。
- 遷移: `/login`。

### 5.3 API呼び出し一覧

| No. | 目的 | メソッド | パス | 要求パラメーター | 応答 | 成功時 | エラー時 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | パスワードの再設定 | POST | `api/account/reset-password/finish` | 本文: `key`（URL のクエリパラメーター `key` の値）、`newPassword` | 200: 本文なし | `success` を `true` にし、フォームを隠して成功アラートと「sign in」リンクを表示する | `error` を `true` にし、失敗アラートを表示する。フォームは残る |

補足:

- 呼び出し元は `PasswordResetFinish.finishReset()` の `PasswordResetFinishService.save(key, newPassword)`（`src/app/account/password-reset/finish/password-reset-finish.service.ts`）である。URL の起点は `serverApiUrl` で、中身はビルド時定数 `SERVER_API_URL` である（`src/app/config/endpoint.constants.ts`）。
- 要求ヘッダーは `authInterceptor` が `Authorization: Bearer <トークン>` を付ける（ストレージにトークンがあるとき）。バックエンドはこの API を認証なしで受け付ける。
- エラーごとの表示は [パスワード再設定完了_入力チェック一覧](./パスワード再設定完了_入力チェック一覧.md) の 4 章に書く。

### 5.4 画面遷移

| 遷移先 | 条件 | トリガー |
| --- | --- | --- |
| ログイン（`/login`） | 再設定に成功した（リンクは成功アラートの中にだけある） | sign in リンク |
| 同じ画面（遷移しない） | 再設定に成功した | Validate new password ボタン（`success.set(true)` でフォームを隠す） |
| 同じ画面（遷移しない） | 再設定に失敗した、またはパスワードが一致しなかった | Validate new password ボタン |
