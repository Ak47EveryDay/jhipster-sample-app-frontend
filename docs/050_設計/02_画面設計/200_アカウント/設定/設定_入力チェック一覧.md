補足:

- エラーメッセージの表示条件: 各コントロールが `invalid` で、かつ `dirty` または `touched` のときだけメッセージのブロックを表示する（例: `firstNameRef.invalid && (firstNameRef.dirty || firstNameRef.touched)`）。1 つの入力欄で複数のエラーが立ったときは、メッセージを並べて表示する。
- 送信ボタンとの関係: Save ボタンは `[disabled]="settingsForm.invalid"` の間は無効である。上記 10 行のいずれかのエラーがあると押せない。`save()` には、単項目の入力値を確認する処理は書かれていない。
- ブラウザーの標準の検証: `<form>` に `novalidate` があるため、ブラウザー自身の検証メッセージは使わない。
- 初期状態: コントロールの初期値は `undefined` なので、最初は必須エラーの状態でフォームは無効である。画面初期化の `patchValue(account)` で値が入る。`dirty` も `touched` も立っていないため、メッセージは表示されない。

## 4. サーバ側チェック

`POST api/account` が失敗したとき、`Settings.save()` の `error` は何もしない（コメント「Handled by interceptor.」）。エラーの表示は `<jhi-alert-error />`（`AlertError`）だけである。失敗しても画面は遷移せず、フォームと入力値は残る。

| No. | 発生条件（バックエンド） | HTTP ステータス | バックエンドの応答 | 画面の表示 | この画面から発生するか |
| --- | --- | --- | --- | --- | --- |
| 1 | ほかのユーザーが同じメールアドレスを使っている（`AccountResource.saveAccount()` が `EmailAlreadyUsedException` を投げる） | 400 | Problem Details。`type` は `https://www.jhipster.tech/problem/email-already-used`。ヘッダー `x-jhipstersampleapplicationapp-error`（`error.emailexists`）、`x-jhipstersampleapplicationapp-params`（`userManagement`） | `<jhi-alert-error />` に翻訳キー `error.emailexists`（「Email is already in use!」）の危険アラート | 発生し得る |
| 2 | `@Valid` による制約違反（`AdminUserDTO` の `firstName`、`lastName` の `@Size(max = 50)`、`email` の `@Email` と `@Size(min = 5, max = 254)` など） | 400 | 本文に `fieldErrors`（`objectName`、`field`、`message` の配列）と `message`（`error.validation`）を持つ Problem Details | `AlertError.handleFieldsError()` が項目ごとに危険アラートを追加する。文言は翻訳キー `error.<message>` の翻訳、翻訳がなければ既定文言 `Error on field "<項目名>"` | 通常は発生しない（行番号 3、6 と 8 から 10 のチェックと Save ボタンの無効化で送信できない） |
| 3 | `AccountResourceException`（トークンからログイン ID を取得できない、またはログイン ID のユーザーが見つからない） | 400 | Problem Details。`title` は `Account resource request invalid`、`message` は `error.http.400` | `<jhi-alert-error />` に「Bad request.」（翻訳キー `error.http.400`）の危険アラート | 通常は発生しない |
| 4 | 認証の失敗（トークンがない、または無効） | 401 | － | 表示なし。`authExpiredInterceptor` と `errorHandlerInterceptor` は URL が `api/account` を含むため動かず、ログアウトも `/login` への遷移もしない | トークンが無効になったとき |
| 5 | サーバーに到達できない | 0 | － | `<jhi-alert-error />` に「Server not reachable」（翻訳キー `error.server.not.reachable`）の危険アラート | 発生し得る |
| 6 | 上記以外の失敗 | 500 など | Problem Details（`message`、`detail`、`params` など） | `<jhi-alert-error />` に、本文の `message` を翻訳キーとして表示する（`error.http.500` なら「Internal server error.」）。翻訳がなければ `detail` を既定文言にする。`message` がなければ本文を原文のまま表示する | コードからは確認できない |

補足:

- バックエンド側の定義は次のとおりである。
  - `AccountResource.saveAccount()` は、本文を `@Valid @RequestBody AdminUserDTO` で受け取る（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/AccountResource.java`）。
  - `AdminUserDTO` には、`firstName` と `lastName` に `@Size(max = 50)`、`email` に `@Email` と `@Size(min = 5, max = 254)`、`login` に `@NotBlank`、`@Pattern`、`@Size(min = 1, max = 50)`、`imageUrl` に `@Size(max = 256)`、`langKey` に `@Size(min = 2, max = 10)` が付いている（バックエンドの `src/main/java/io/github/jhipster/sample/service/dto/AdminUserDTO.java`）。
  - `@Valid` 違反は `ExceptionTranslator` が 400 に変換し、本文に `fieldErrors` を入れる。`fieldErrors` の `message` には制約の既定のメッセージが入る（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/errors/ExceptionTranslator.java` の `getFieldErrors()`）。
  - `EmailAlreadyUsedException` は `BadRequestAlertException` のサブクラスで、`ExceptionTranslator` が 400 とヘッダー `x-jhipstersampleapplicationapp-error`、`x-jhipstersampleapplicationapp-params` に変換する（同ファイルの `buildHeaders()`、バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/errors/EmailAlreadyUsedException.java`）。ヘッダー名は大文字と小文字を区別しないため、フロントエンドの定数（`src/app/shared/jhipster/constants.ts`）の小文字の表記と一致する。
  - バックエンドのテスト `src/test/java/io/github/jhipster/sample/web/rest/AccountResourceIT.java` は、成功で 200、形式が不正なメールアドレスで 400、ほかのユーザーが使っているメールアドレスで 400 を検証している。E2E テスト `cypress/e2e/account/settings-page.cy.ts` は、氏名とメールアドレスの変更で 200、ほかのユーザーのメールアドレスへの変更で 400 を検証している。
- 行番号 1 の表示: `AlertError.handleBadRequest()` は、ヘッダー `x-jhipstersampleapplicationapp-error` の値（`error.emailexists`）を翻訳キーとして表示する。埋め込み値 `entityName` は翻訳キー `global.menu.entities.userManagement` から作るが、このキーは `src/i18n/en/` にはなく、文言 `error.emailexists` にも埋め込みの箇所がないため、表示には影響しない。`src/i18n/en/settings.json` にある `settings.messages.error.emailexists` と `settings.messages.error.fail` は、テンプレートでは使っていない。
- 行番号 2 の文言について: `handleFieldsError()` は、項目名を翻訳キー `jhipsterSampleApplicationApp.<objectName>.<field>` で探す。`src/i18n/en/` で `jhipsterSampleApplicationApp` 配下にあるのは `bankAccount`、`adminAuthority`、`label`、`operation` の 4 つだけで、ユーザーの項目名の翻訳はない。また `error.<既定のメッセージ>` という翻訳キーもない（`src/i18n/en/global.json` にあるのは `error.NotNull` と `error.Size` だけである）。そのため、画面には既定文言 `Error on field "<項目名>"` が出るとコードから読める。実機での表示は確認していない。
- 行番号 4 について: バックエンドは `/api/**` に認証を要求する（バックエンドの `src/main/java/io/github/jhipster/sample/config/SecurityConfiguration.java`）。画面はルートガードによってログイン済みのときだけ開けるため、開いた後にトークンが無効になった場合に発生する。
- エラー時の共通の動き: 失敗しても画面は遷移せず、Save ボタンは無効にならない（要求中も無効にする指定がない）。フォームの値は変更しない。
