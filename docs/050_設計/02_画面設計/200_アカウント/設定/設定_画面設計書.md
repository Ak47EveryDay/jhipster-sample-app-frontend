## 2. 機能概要

- ログイン中のユーザーが、自分の氏名、メールアドレス、言語を変更する。変更内容は `POST api/account` に送る。
- 画面を開くと `AccountService.identity()` で現在のアカウントを取得し、フォームに設定する。アカウントが取得できるまで、見出しもフォームも表示しない。
- 保存に成功すると「Settings saved!」の成功アラートを表示する。画面は遷移しない。あわせて、アプリが持つアカウント（`AccountService` の `userIdentity`）を送信した値で置き換える。
- 保存に失敗すると `<jhi-alert-error />` にエラーを表示する。画面のコンポーネントには、失敗したときの処理は書かれていない。たとえばメールアドレスがほかのユーザーと重複している場合もこれである。
- First Name、Last Name、Email は必須である。フォームが無効な間は Save ボタンが無効になる。
- Language は選択リストである。選択肢は `LANGUAGES`（このリポジトリでは `en` の 1 つ）である。
- この画面には `<jhi-alert-error />` があるが `<jhi-alert />` はない。

## 3. 画面レイアウト

画面は `Main` の `<router-outlet />` の中、`<div class="card jh-card">` の内側に表示される（`src/app/layouts/main/main.html`）。テンプレートのルートは `<div>` で、その中の中央寄せの `<div class="d-flex justify-content-center">` と `<div class="col-md-8">` の中を、上から順に次の領域が占める。

```
見出し領域（<h2 jhiTranslate="settings.title">）      … settingsForm.value.login があるとき
    User settings for [<username>]
アラート領域
    Settings saved!                                … success()
    <jhi-alert-error />                            … HTTP エラー
入力フォーム領域（<form name="form" novalidate>）     … settingsForm.value.login があるとき
    First Name  … テキストボックス
    Last Name   … テキストボックス
    Email       … メール入力欄
    Language    … 選択リスト（languages.length > 0 のとき）
ボタン領域
    [Save]
```

| 領域 | テンプレート上の要素 | 表示条件 | 4 章の対応 |
| --- | --- | --- | --- |
| 見出し領域 | `<h2 jhiTranslate="settings.title" [translateValues]="{ username: settingsForm.value.login }">` | `settingsForm.value.login` が真のとき | `### 見出し領域` |
| アラート領域 | `<div class="alert alert-success" jhiTranslate="settings.messages.success">`、`<jhi-alert-error />` | 成功アラートは `success()` のとき。`<jhi-alert-error />` は常に置かれ、アラートがあるときだけ内容が表示される | `### アラート領域` |
| 入力フォーム領域 | `<form name="form" (ngSubmit)="save()" [formGroup]="settingsForm" novalidate>` の中の First Name、Last Name、Email の各 `<div class="mb-3">` と、Language の `<div class="mb-3">`（`@if (languages.length > 0)`） | `settingsForm.value.login` が真のとき。Language はさらに `languages.length > 0` のとき | `### 入力フォーム領域` |
| ボタン領域 | Save ボタン | `settingsForm.value.login` が真のとき（フォームの中にある） | `### ボタン領域` |

### 5.2 イベント詳細

#### 5.2.1 画面初期化

- トリガー: `/account/settings` への遷移。画面が表示される前にルートガードが動く。
- 処理手順:
  1. ルートガード `userRouteAccessService` が `AccountService.identity()` でアカウントを確認する。キャッシュ（`accountCache$`）がなければ `GET api/account` を送る。アカウントが `null` なら遷移前の URL を `StateStorageService.storeUrl()` で保存し、`/login` へ遷移してここで終わる。
  2. コンポーネントのフィールド初期化で `settingsForm` ができる。8 つのコントロールの初期値は `{} as Account` のプロパティー、すなわち `undefined` である。`firstName`、`lastName`、`email` は必須のため、この時点のフォームは無効である。
  3. `ngOnInit()` が `this.accountService.identity()` を購読する。ガードがすでにキャッシュを作っているため、要求は追加で送られない。
  4. アカウントを取得できたら（`account` が `null` でなければ）`this.settingsForm.patchValue(account)` でフォームに値を設定する。キーが一致する `activated`、`authorities`、`email`、`firstName`、`langKey`、`lastName`、`login`、`imageUrl` の 8 つが設定される。
  5. `settingsForm.value.login` に値が入ると、見出しとフォームが表示される。
- 表示されない場合: アカウントが `null` のときは `patchValue()` を呼ばないため、`settingsForm.value.login` は `undefined` のまま、見出しもフォームもボタンも表示しない。
- 必須エラーの注意: 取得したアカウントの `firstName`、`lastName` が `null` だと、`Validators.required` によりフォームは無効のままなので、Save ボタンは値を入力し直すまで押せない。
- 状態変化: `settingsForm` の各コントロールの値。
- 遷移: 通常はなし。未ログインのときは `/login`。

#### 5.2.2 入力（First Name、Last Name、Email、Language）

- トリガー: 各入力欄への入力、Language の選択の変更。
- 処理手順: Reactive Forms がコントロールの値を更新し、バリデーターを評価し直す。この画面には入力時のメソッド呼び出しはない。
- 状態変化: `settingsForm` の各コントロールの値と、`invalid`、`dirty`、`touched` の状態。
- 表示の変化: 各入力欄の下に、コントロールが `invalid` で、かつ `dirty` または `touched` のときだけメッセージのブロックを表示する。表示する文言はエラーの種類ごとに次のとおりである。
  - First Name: `firstNameRef.errors?.required` なら翻訳キー `settings.messages.validate.firstname.required`、`minlength` なら `settings.messages.validate.firstname.minlength`、`maxlength` なら `settings.messages.validate.firstname.maxlength`。
  - Last Name: `lastNameRef.errors?.required` なら翻訳キー `settings.messages.validate.lastname.required`、`minlength` なら `settings.messages.validate.lastname.minlength`、`maxlength` なら `settings.messages.validate.lastname.maxlength`。
  - Email: `emailRef.errors?.required` なら翻訳キー `global.messages.validate.email.required`、`email` なら `global.messages.validate.email.invalid`、`minlength` なら `global.messages.validate.email.minlength`、`maxlength` なら `global.messages.validate.email.maxlength`。
  - 1 つの入力欄で複数のエラーが同時に立つときは、メッセージを並べて表示する。
- 遷移: なし。

#### 5.2.3 Save ボタンクリック（設定の保存）

- トリガー: Save ボタン（`type="submit"`）によるフォームの送信（`(ngSubmit)="save()"`）。ボタンは `settingsForm.invalid` の間は無効である。
- 処理手順:
  1. `save()` は最初に `this.success.set(false)` にする。
  2. `const account = this.settingsForm.getRawValue()` で、フォームの 8 つのコントロールの値を取り出す。
  3. `this.accountService.save(account)` を購読する。`AccountService.save()` は `POST api/account` を、取り出した値を本文として送る。
  4. 成功（`next`）: 次の 3 つを行う。遷移はしない。
     - `this.success.set(true)` にする。成功アラートを表示する。
     - `this.accountService.authenticate(account)` で、アプリが持つアカウント（`AccountService` の `userIdentity`）を送信した値で置き換える。ナビゲーションバーの `account` シグナルも同じ値になる。
     - `account.langKey` が `translateService.getCurrentLang()` と異なれば、`this.translateService.use(account.langKey)` で言語を切り替える。
  5. 失敗（`error`）: 何もしない（コメント「Handled by interceptor.」）。`success` は `false` のままで、フォームと入力値はそのまま残る。
- HTTP エラーの表示: `errorHandlerInterceptor` が 401 以外の失敗をイベント `jhipsterSampleApplicationApp.httpError` として配信し、この画面の `<jhi-alert-error />`（`AlertError`）がステータスに応じた文言を危険アラートとして表示する。エラーごとの表示は入力チェック一覧の 4 章に書く。
- トークンとアカウントの状態: この画面はトークンを変えない。保存に成功すると `userIdentity` はフォームの値で置き換わるが、キャッシュ（`accountCache$`）は置き換わらない。キャッシュは次に `identity(true)` が呼ばれるとき（ログインのとき）まで残る。
- 言語について: このリポジトリの `LANGUAGES` は `en` だけであるため、コードからは選択リストで言語を切り替えることはできず、保存時の言語の切り替えも起こらないと読める。ナビゲーションバーの言語メニューも `languages.length > 1` のときだけ表示する。
- 401 のときの共通処理: `authExpiredInterceptor` も `errorHandlerInterceptor` も動かない。URL が `api/account` を含むためである。そのためログアウトも `/login` への遷移もせず、トークンはそのまま残り、アラートも出ない。コードからは、トークンが無効になった状態で Save を押すと、画面には何の変化もないと読める。
- バックエンドの動き（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/AccountResource.java`、`saveAccount()`）:
  - 本文を `@Valid @RequestBody AdminUserDTO` で受け取る。変更対象のユーザーは、トークンから得たログイン ID（`SecurityUtils.getCurrentUserLogin()`）で決める。本文の `login`、`activated`、`authorities` は更新に使わない。
  - 本文のメールアドレスと同じメールアドレスを持つユーザーがいて、そのログイン ID が現在のユーザーと異なれば、`EmailAlreadyUsedException`（400）を投げる。自分自身のメールアドレスはエラーにならない。
  - ログイン ID のユーザーが見つからなければ `AccountResourceException`（400）を投げる。
  - `UserService.updateUser(firstName, lastName, email, langKey, imageUrl)`（バックエンドの `src/main/java/io/github/jhipster/sample/service/UserService.java`）が、名、姓、メールアドレス（小文字に変換する）、言語、画像の URL を設定し、ユーザーのキャッシュを消す。
  - 成功すると 200 を返す。本文もアラートのヘッダーもない。バックエンドのテスト `src/test/java/io/github/jhipster/sample/web/rest/AccountResourceIT.java` は、成功で 200、形式が不正なメールアドレスで 400、ほかのユーザーが使っているメールアドレスで 400 を検証している。
- 状態変化: `success`。成功時は `AccountService` の `userIdentity` と、言語が変わればアプリの言語。
- 遷移: なし。

### 5.3 API呼び出し一覧

| No. | 目的 | メソッド | パス | 要求パラメーター | 応答 | 成功時 | エラー時 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | アカウントの取得（画面初期化。ルートガードと `ngOnInit()` が `identity()` を呼び、キャッシュがなければ送る） | GET | `api/account` | なし | 200: `Account`（`activated`、`authorities`、`email`、`firstName`、`langKey`、`lastName`、`login`、`imageUrl`） | フォームに値を設定する | アカウントが `null` になり、ルートガードが `/login` へ遷移する |

補足:

- 呼び出し元は次のとおりである。
  - No. 1: `userRouteAccessService` と `Settings.ngOnInit()` が呼ぶ `AccountService.identity()`（`src/app/core/auth/account.service.ts`）。キャッシュ（`accountCache$`）があれば要求は送らない。
  - No. 2: `Settings.save()` の `AccountService.save(account)`（`src/app/core/auth/account.service.ts`）。
  - URL の起点は `serverApiUrl` で、中身はビルド時定数 `SERVER_API_URL` である（`src/app/config/endpoint.constants.ts`）。
- No. 2 の本文はフォームの `getRawValue()` の値である。バックエンドはこのうち `firstName`、`lastName`、`email`、`langKey`、`imageUrl` だけを更新に使う。
- 要求ヘッダーは `authInterceptor` が `Authorization: Bearer <トークン>` を付ける。バックエンドは `/api/**` に認証を要求する（バックエンドの `src/main/java/io/github/jhipster/sample/config/SecurityConfiguration.java`）。
- バックエンドの `@Valid` による制約は次のとおりである（バックエンドの `src/main/java/io/github/jhipster/sample/service/dto/AdminUserDTO.java`）。`firstName` と `lastName` は `@Size(max = 50)`、`email` は `@Email` と `@Size(min = 5, max = 254)`、`login` は `@NotBlank`、`@Pattern`、`@Size(min = 1, max = 50)`、`imageUrl` は `@Size(max = 256)`、`langKey` は `@Size(min = 2, max = 10)` である。違反は 400 になる。エラーごとの表示は [設定_入力チェック一覧](./設定_入力チェック一覧.md) の 4 章に書く。
