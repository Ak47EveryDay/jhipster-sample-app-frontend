## 2. 機能概要

- ユーザー名とパスワードを入力してサインインする。入力値は `Login`（`username`、`password`、`rememberMe`）として `POST api/authenticate` に送る。
- 認証に成功すると、応答のトークンを保存し、`GET api/account` でアカウントを取得し直す。`StateStorageService` に保存された URL があればそこへ、なければホーム（`/`）へ遷移する。
- 「Remember me」にチェックするとトークンを `localStorage` に、チェックしなければ `sessionStorage` に保存する。
- 認証に失敗すると画面にとどまり、「Failed to sign in!」の危険アラートを表示する。エラーの種類によらず表示は同じである。
- すでにログインしている状態でこの画面を開くと、ホームへ遷移する。
- 画面を開くと Username 入力欄にフォーカスする。
- 入力項目は Username、Password、Remember me の 3 つである。入力欄ごとのエラーメッセージはなく、Sign in ボタンはフォームが無効でも押せる。
- 「Did you forget your password?」リンクでパスワード再設定依頼画面へ、「Register a new account」リンクで登録画面へ遷移する。
- この画面には `<jhi-alert-error />` と `<jhi-alert />` はない。HTTP エラーは画面独自のアラートだけで表示し、成功通知はない。

## 3. 画面レイアウト

画面は `Main` の `<router-outlet />` の中、`<div class="card jh-card">` の内側に表示される（`src/app/layouts/main/main.html`）。テンプレートのルートは `<div>` で、その中の中央寄せの `<div class="d-flex justify-content-center">` と `<div class="col-lg-6 col-md-8 col-sm-10">` の中を、上から順に次の領域が占める。

```
見出し領域（<h1 data-cy="loginTitle">）
    Sign in
アラート領域（data-cy="loginError"）     … authenticationError() が true のとき
    Failed to sign in! Please check your credentials and try again.
入力フォーム領域（<form class="form">）
    Username     … テキストボックス
    Password     … パスワードボックス
    Remember me  … チェックボックス
ボタン領域
    [Sign in]
リンク領域
    Did you forget your password?
    You don't have an account yet? Register a new account
```

| 領域 | テンプレート上の要素 | 表示条件 | 4 章の対応 |
| --- | --- | --- | --- |
| 見出し領域 | `<h1 data-cy="loginTitle" jhiTranslate="login.title">` | 常に | `### 見出し領域` |
| アラート領域 | `<div>`（`class="alert alert-danger"`、`data-cy="loginError"`、`jhiTranslate="login.messages.error.authentication"`） | `authenticationError()` | `### アラート領域` |

### 5.2 イベント詳細

#### 5.2.1 画面初期化

- トリガー: `/login` への遷移。ルートに `canActivate` も `resolve` もないため、ガードとリゾルバーは動かない。
- 処理手順:
  1. `ngOnInit()` が `this.accountService.identity()` を購読する。`identity()` は、キャッシュ（`accountCache$`）がなければ `GET api/account` を送り、あればキャッシュをそのまま返す。
  2. アカウントを取得できたら `this.accountService.isAuthenticated()`（`userIdentity()` が `null` でないこと）を調べ、真なら `this.router.navigate([''])` でホームへ遷移する。
  3. 取得できなかったときは何もしない。`identity()` は失敗すると `catchError(() => of(null))` で `null` を流す。
  4. `ngAfterViewInit()` が `this.username().nativeElement.focus()` で Username 入力欄にフォーカスする。
- 補足: アプリの骨格 `Main` の `ngOnInit()` も起動時に `accountService.identity()` を購読している（`src/app/layouts/main/main.ts`）。`shareReplay()` により、すでに送った `GET api/account` の結果がこの画面にも共有される。
- 状態変化: 画面の状態は変わらない。キャッシュがなければ、`AccountService` の `userIdentity` と `accountCache$` が変わる。
- 遷移: ログイン済みならホーム（`/`）。それ以外はなし。

#### 5.2.2 入力（Username、Password、Remember me）

- トリガー: 各入力欄への入力、チェックボックスの変更。
- 処理手順: Reactive Forms がコントロールの値を更新し、バリデーターを評価し直す。この画面には入力時のメソッド呼び出しも、コントロールの `errors` を参照する要素もない。
- 状態変化: `loginForm` の各コントロールの値と、`invalid`、`dirty`、`touched` の状態。
- 遷移: なし。

#### 5.2.3 Sign in ボタンクリック（ログイン）

- トリガー: Sign in ボタン（`type="submit"`）によるフォームの送信（`(ngSubmit)="login()"`）。
- 処理手順:
  1. `login()` は `this.loginForm.getRawValue()`（`username`、`password`、`rememberMe`）を取り出し、`this.loginService.login(...)` を購読する。フォームが有効かどうかは確認しない。
  2. `LoginService.login(credentials)` は `AuthServerProvider.login(credentials)` を呼ぶ。`POST api/authenticate` を、本文 `{ username, password, rememberMe }` で送る。
  3. 成功（200）なら `authenticateSuccess(response, credentials.rememberMe)` が、応答本文の `id_token` を `StateStorageService.storeAuthenticationToken(response.id_token, rememberMe)` で保存する。
  4. `mergeMap` で `AccountService.identity(true)` に進む。`force` が `true` なのでキャッシュを使わず、`GET api/account` を送る。この要求には手順 3 で保存したトークンが `Authorization: Bearer <トークン>` として付く。
  5. アカウントを取得できたら `tap` が `authenticate(account)` で `userIdentity`（シグナル）に設定する。ナビゲーションバーの `account` シグナルも同じ値になり、メニューがログイン中の内容に切り替わる。`account.langKey` があり、かつ `StateStorageService.getLocale()` が `null` なら `translateService.use(account.langKey)` で言語を切り替える。
  6. 続けて `navigateToStoredUrl()` が動く。`StateStorageService.getUrl()` で保存された URL（セッションストレージの `previousUrl`）があれば、それを `clearUrl()` で消して `router.navigateByUrl(previousUrl)` で遷移する。なければ何もしない。
  7. `Login.login()` の `next` が `authenticationError` を `false` にする。`this.router.currentNavigation()` が `null` である（手順 6 で遷移が始まっていない）ときは、`this.router.navigate([''])` でホームへ遷移する。
  8. 失敗なら `error` が `authenticationError.set(true)` を実行する。画面にとどまり、アラートを表示する。
- トークンの保存先: `rememberMe` が `true` なら `localStorage`、`false` なら `sessionStorage` である。キーは `jhi-authenticationToken`（`AUTHENTICATION_TOKEN_KEY`）で、値は JSON の文字列にしたトークンである。保存する前に `clearAuthenticationToken()` で両方のストレージから古いトークンを消す。
- 失敗したときの共通部品の動き:
  - 401 のときは `authExpiredInterceptor` が動く。対象は URL に `api/account` を含まない 401 であり、`api/authenticate` は含まないためである。`StateStorageService.storeUrl(router.routerState.snapshot.url)` で現在の URL（`/login`）を保存し、`LoginService.logout()` でトークンを両方のストレージから消して `AccountService.authenticate(null)` でアカウントを `null` にし（キャッシュも消える）、`router.navigate(['/login'])` を実行する。現在の URL と同じ `/login` への遷移は Angular のルーターが無視するため、画面は変わらない（Angular の標準の動きであり、本リポジトリのコードではない）。
  - 401 以外の失敗では、共通部品はトークンもアカウントも変えない。`authExpiredInterceptor` は動かない。
  - すべての失敗で `errorHandlerInterceptor` がイベント `jhipsterSampleApplicationApp.httpError` を配信するが、この画面に `<jhi-alert-error />` はないため表示されない。
- 保存された URL について: 未ログインのまま保護された画面を開くと、ルートガード `userRouteAccessService` がその画面の URL を保存してから `/login` へ遷移する。この画面でログインに失敗すると、上記のとおり `authExpiredInterceptor` が保存された URL を `/login` で上書きする。コードからは、失敗したあとにログインし直しても元の画面には戻らず、ホームへ遷移すると読める（実機では確認していない）。
- バックエンドの動き（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/AuthenticateController.java`、`authorize()`）:
  - 本文を `@Valid @RequestBody LoginVM` で受け取る。ユーザー名とパスワードで認証し、JWT を作って、200 と、本文 `{ id_token }` と、ヘッダー `Authorization: Bearer <トークン>` を返す。
  - トークンの有効期限は、`rememberMe` が `true` なら `token-validity-in-seconds-for-remember-me`、`false` なら `token-validity-in-seconds` である（バックエンドの `src/main/resources/config/application-dev.yml` と `application-prod.yml` では、それぞれ 2592000 秒と 86400 秒である）。
  - ユーザーの探し方はバックエンドの `src/main/java/io/github/jhipster/sample/security/DomainUserDetailsService.java` の `loadUserByUsername()` である。入力されたユーザー名がメールアドレスの形式ならメールアドレスで（大文字と小文字を区別しない）、そうでなければ小文字に変換してログイン ID で探す。
- 状態変化: `authenticationError`。成功時はトークン（`localStorage` または `sessionStorage`）、`AccountService` の `userIdentity` と `accountCache$`、保存された URL（セッションストレージの `previousUrl`）が変わる。失敗時の 401 では、トークンとアカウントが消え、`previousUrl` が `/login` になる。
- 遷移: 成功時は保存された URL、なければホーム（`/`）。失敗時はなし。

#### 5.2.4 リンクによる遷移

- トリガー: Did you forget your password? リンク、Register a new account リンクのクリック。
- 処理手順: `routerLink` 属性に従って遷移する。遷移先のルートに `canActivate` はない。
- 遷移先: `/account/reset/request`、`/account/register`。
- 状態変化: なし（画面が破棄される）。

| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | ログイン（トークンの取得） | POST | `api/authenticate` | 本文: `username`（文字列）、`password`（文字列）、`rememberMe`（真偽値） | 200: `{ id_token }`。ヘッダー `Authorization: Bearer <トークン>` | `id_token` を保存し、No. 2 を呼ぶ | `authenticationError` を `true` にしてアラートを表示する。401 のときは保存された URL を `/login` に上書きし、トークンを消してアカウントを `null` にする |
| 2 | アカウントの取得（ログイン成功後。画面初期化でもキャッシュがなければ送る） | GET | `api/account` | なし | 200: `Account`（`activated`、`authorities`、`email`、`firstName`、`langKey`、`lastName`、`login`、`imageUrl`） | アカウントを設定し、保存された URL またはホームへ遷移する | `null` を流す。ログイン後の失敗では、エラーの内容によらず `authenticationError` は `false` のままホームへ遷移する |

補足:

- 呼び出し元は次のとおりである。
  - No. 1: `Login.login()` の `LoginService.login()`（`src/app/login/login.service.ts`）が呼ぶ `AuthServerProvider.login()`（`src/app/core/auth/auth-jwt.service.ts`）。
  - No. 2: `AccountService.identity()` の `fetch()`（`src/app/core/auth/account.service.ts`）。
  - URL の起点は `serverApiUrl`（`src/app/config/endpoint.constants.ts`）で、中身はビルド時定数 `SERVER_API_URL` である。
- No. 2 のバックエンドは `AccountResource.getAccount()`（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/AccountResource.java`）である。`UserService.getUserWithAuthorities()` で現在のユーザーを探し、見つからなければ `AccountResourceException` を投げる。応答は `AdminUserDTO` の JSON で、フロントエンドの `Account`（`src/app/core/auth/account.model.ts`）はこのうち 8 つのプロパティーを使う。
- 認証の失敗について。存在しないユーザーや誤ったパスワードのときは Spring Security が `BadCredentialsException` を投げ、バックエンドの `ExceptionTranslator` はこれを 401 に変換する（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/errors/ExceptionTranslator.java` の `getMappedStatus()`）。バックエンドのテスト `src/test/java/io/github/jhipster/sample/web/rest/AuthenticateControllerIT.java` の `testAuthorizeFails` も 401 を検証している。
- 要求ヘッダーは `authInterceptor` が `Authorization: Bearer <トークン>` を付ける（トークンがあるとき）。バックエンドは `POST api/authenticate` を `permitAll` とし、`/api/**` には認証を要求する（バックエンドの `src/main/java/io/github/jhipster/sample/config/SecurityConfiguration.java`）。
- エラー時の共通の動きは次のとおりである。
  - No. 1 の 401 は `authExpiredInterceptor` の対象である（5.2.3 参照）。
  - No. 2 の 401 は URL が `api/account` を含むため、`authExpiredInterceptor` も `errorHandlerInterceptor` も何もしない。`identity()` の `catchError` だけが働き、`null` を返す。
  - サーバーに到達できないとき（ステータス 0）も、この画面に `<jhi-alert-error />` がないため `error.server.not.reachable` は表示されない。

### 5.4 画面遷移

| 遷移先 | 条件 | トリガー |
| --- | --- | --- |
| ホーム（`/`） | ログイン済みのままこの画面を開いた | `ngOnInit()`（`this.router.navigate([''])`） |
| ホーム（`/`） | ログインに成功し、保存された URL がない | Sign in ボタン（`login()` の `this.router.navigate([''])`） |
| 保存された URL | ログインに成功し、`StateStorageService` に URL が保存されている | `AccountService.navigateToStoredUrl()` |
| パスワード再設定依頼（`/account/reset/request`） | － | Did you forget your password? リンク |
| 登録（`/account/register`） | － | Register a new account リンク |
| 同じ画面（遷移しない） | ログインに失敗した | Sign in ボタン（401 のとき `authExpiredInterceptor` が `/login` への遷移を指示するが、現在の URL と同じため遷移しない） |
