補足:

- エラーメッセージの表示条件: 各コントロールが `invalid` で、かつ `dirty` または `touched` のときだけメッセージのブロックを表示する（例: `loginRef.invalid && (loginRef.dirty || loginRef.touched)`）。1 つの入力欄で複数のエラーが立ったときは、メッセージを並べて表示する。
- 行番号 4 の正規表現は、`src/app/account/register/register.ts` の `Validators.pattern` の引数で、次のとおりである。

```ts
'^[a-zA-Z0-9!$&*+=?^_`{|}~.-]+@[a-zA-Z0-9-]+(?:\\.[a-zA-Z0-9-]+)*$|^[_.@A-Za-z0-9-]+$'
```

- 送信ボタンとの関係: Register ボタンは `[disabled]="registerForm.invalid"` の間は無効である。上記 14 行のいずれかのエラーがあると押せない。`register()` には、単項目の入力値を確認する処理は書かれていない。
- パスワード強度バー: New password の下に `<jhi-password-strength-bar>` を表示するが、強度はチェックではない。強度が低くてもフォームは有効である。
- ブラウザーの標準の検証: `<form>` に `novalidate` の明示はないが、Angular は `[formGroup]` を持つ `<form>` 要素に `novalidate` を設定するため、ブラウザー自身の検証メッセージは使わない（Angular の標準の動きであり、本リポジトリのコードではない）。
- 初期状態: 4 つのコントロールとも空文字列なので、最初は必須エラーの状態でフォームは無効である。`dirty` も `touched` も立っていないため、メッセージは表示されない。

## 4. サーバ側チェック

`POST api/register` が失敗したとき、`Register.processError()` が HTTP ステータスと応答本文の `type` で表示を切り替える。この画面に `<jhi-alert-error />` はないため、レスポンスヘッダーや本文の内容がそのまま表示されることはない。失敗しても画面は遷移せず、フォームと入力値は残る。

| No. | 発生条件（バックエンド） | HTTP ステータス | バックエンドの応答 | 画面の表示 | この画面から発生するか |
| --- | --- | --- | --- | --- | --- |
| 1 | 小文字にしたログイン ID が、有効化済みの既存ユーザーと同じ（`UserService.registerUser()` が `UsernameAlreadyUsedException` を投げる） | 400 | Problem Details。`type` は `https://www.jhipster.tech/problem/login-already-used`。ヘッダー `x-jhipstersampleapplicationapp-error`（`error.userexists`）、`x-jhipstersampleapplicationapp-params`（`userManagement`） | 「Login name already registered! Please choose another one.」（翻訳キー `register.messages.error.userexists`） | 発生し得る |
| 2 | メールアドレス（大文字と小文字を区別しない）が、有効化済みの既存ユーザーと同じ（`EmailAlreadyUsedException`） | 400 | 同上。`type` は `https://www.jhipster.tech/problem/email-already-used`。ヘッダーは `error.emailexists`、`userManagement` | 「Email is already in use! Please choose another one.」（翻訳キー `register.messages.error.emailexists`） | 発生し得る |
| 3 | パスワードが空、4 文字未満、または 100 文字超（`AccountResource.isPasswordLengthInvalid()`） | 400 | Problem Details。`type` は `https://www.jhipster.tech/problem/invalid-password`。`title` は `Incorrect password` | 「Registration failed! | 4 | `@Valid` による制約違反。`login` の `@NotBlank`、`@Pattern`、`@Size`、`email` の `@Email`、`@Size`、`langKey` の `@Size(min = 2, max = 10)`、`password` の `@Size(min = 4, max = 100)` | 400 | 本文に `fieldErrors`（`objectName`、`field`、`message` の配列）と `message`（`error.validation`）を持つ Problem Details | 「Registration failed! 補足:

- バックエンド側の定義は次のとおりである。
  - `AccountResource.registerAccount()` は、本文を `@Valid @RequestBody ManagedUserVM` で受け取る（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/AccountResource.java`）。
  - `ManagedUserVM` の `password` には `@Size(min = 4, max = 100)` が付く。親クラスの `AdminUserDTO` には、`login` に `@NotBlank`、`@Pattern`、`@Size(min = 1, max = 50)`、`email` に `@Email`、`@Size(min = 5, max = 254)`、`langKey` に `@Size(min = 2, max = 10)` が付く（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/vm/ManagedUserVM.java`、`src/main/java/io/github/jhipster/sample/service/dto/AdminUserDTO.java`）。
  - 重複の判定は `UserService.registerUser()` である（バックエンドの `src/main/java/io/github/jhipster/sample/service/UserService.java`）。ログイン ID を先に調べ、次にメールアドレスを調べる。見つかった既存ユーザーが未有効化なら削除して登録を続け、有効化済みなら例外を投げる。両方が重複しているときは、ログイン ID の重複（行番号 1）だけが返る。
  - 行番号 1、2 の例外は、`ExceptionTranslator` が 400 とヘッダー `x-jhipstersampleapplicationapp-error`、`x-jhipstersampleapplicationapp-params` に変換する（バックエンドの `src/main/java/io/github/jhipster/sample/web/rest/errors/ExceptionTranslator.java` の `getProblemDetailWithCause()` と `buildHeaders()`）。フロントエンドの定数 `LOGIN_ALREADY_USED_TYPE`、`EMAIL_ALREADY_USED_TYPE` は `src/app/shared/jhipster/error.constants.ts` にあり、バックエンドの `ErrorConstants` と同じ値である。ヘッダーは画面では使わない。
- 行番号 3 について: 画面の最大桁は 50 であるのに対し、バックエンドの上限は 100 である。バックエンドの `ManagedUserVM.PASSWORD_MAX_LENGTH` は 100 である。
- 行番号 4 の `fieldErrors` を項目ごとのアラートにするのは `<jhi-alert-error />`（`src/app/shared/alert/alert-error.ts` の `handleFieldsError()`）である。この画面にはそれがないため、項目ごとの内容が画面に出ることはない。
- バックエンドのテスト `src/test/java/io/github/jhipster/sample/web/rest/AccountResourceIT.java` は、有効な登録で 201、不正なログイン ID や不正なパスワードで 400、有効化済みユーザーとのログイン ID 重複とメールアドレス重複で 400 番台を検証している。E2E テスト `cypress/e2e/account/register-page.cy.ts` は、登録の成功で 201 を検証している。
- 未有効化のまま 3 日経過したユーザーは、バックエンドの `UserService.removeNotActivatedUsers()` に削除される（毎日 01:00）。
