# 画面設計・IF 設計（docs/050_設計）

このディレクトリには、リポジトリ `jhipster-sample-app-frontend` の画面設計と IF 設計を日本語でまとめます。
すべての記述は現在のコード（フロントエンドのコミット `570a360`、バックエンドのコミット `423e462`）を根拠にしています。文書とコードが食い違う場合はコードを正としてください。

規約（命名規則、コーディング規約、テスト規約など）は `docs/999_標準化/` にあります。このディレクトリには、このリポジトリの設計だけを書きます。

## 1. 構成

| ディレクトリ | 扱う内容 |
| --- | --- |
| `01_一覧/` | 画面、画面遷移、メッセージ、API 呼び出し、チェックの一覧 |
| `02_画面設計/000_アプリ/` | アプリケーション全体の設計（起動、ルーティング、状態管理、HTTP 共通処理、国際化、ビルドと開発環境の設定） |
| `02_画面設計/100_TOP画面/` | ホーム |
| `02_画面設計/200_アカウント/` | ログイン、登録、アカウント有効化、パスワード変更、パスワード再設定依頼、パスワード再設定完了、設定 |
| `02_画面設計/300_管理画面/` | API ドキュメント、アプリケーション設定、ヘルスチェック、ログ、メトリクス |
| `02_画面設計/400_エンティティ/` | 銀行口座、ラベル、取引、ユーザ管理、権限の一覧・詳細・登録・編集・削除 |
| `02_画面設計/共通/` | ナビゲーションバー、フッター、ページリボン、エラー画面、アラート、アカウント状態と認証、ルートガードと認可、HTTP 共通処理、国際化、画面タイトル |
| `03_IF設計/01_DTO設計書/` | モデル（DTO）ごとの型定義 |
| `03_IF設計/02_電文レイアウト/` | API グループごとの要求・応答の電文 |

画面は 1 画面につき 1 ディレクトリで、`<画面名>_画面設計書.md` と、入力のある画面だけ `<画面名>_入力チェック一覧.md` を置きます。

## 2. 文書一覧

全 94 文書へのリンクです。どの文から始めればよいかは、次を目安にしてください。

- 全体像は [アプリ_画面設計書](02_画面設計/000_アプリ/アプリ/アプリ_画面設計書.md) にあります。
- 画面全体を一望するときは [画面一覧](01_一覧/01_画面一覧.md) と [画面遷移一覧](01_一覧/02_画面遷移一覧.md) を使います。

## 3. 該当なし

参考にしたプロジェクトの文書のうち、このアプリケーションには対応するものがないものです。空のディレクトリや文書は作っていません。

| 文書 | 理由 |
| --- | --- |
| `01_一覧/03_コード一覧` | コードマスター（選択肢の一覧）を持たないため、該当しません。選択肢は `src/i18n/en/*.json` の文言と、権限名などごく少ない固定値だけです。 |
| `01_一覧/06_…タグ実装一覧` | 計測・分析用のタグを実装していないため、該当しません。 |
| `02_画面設計/400_エンティティ/権限/登録・編集` | 権限には編集のルートがありません（`src/app/entities/admin/authority/authority.routes.ts` に `new` はありますが `:name/edit` はありません）。代わりに `権限/登録` を作成しています。 |
| `04_コード` | 参考にしたプロジェクトでは画面ごとのコード値の設計を置いていますが、このアプリケーションはコードマスターを持たないため該当しません（`01_一覧/03_コード一覧` と同じ理由です）。 |
| 画面ごとの `設計書生成用INPUT情報` | 参考プロジェクトで文書を生成するための中間物であり、このリポジトリには対応する内容がないため作成していません。 |
| 画面ごとの `レビュー指摘票` | レビューの記録であり、設計の内容ではないため作成していません。 |

## 4. 記載の約束

- 文書の本文は常体、この README は敬体で書きます。
- コードの識別子（クラス名、ファイル名、ルート、設定キー、翻訳キー）はバッククォートで囲み、コードの表記のままにします。
- ファイルのパスはリポジトリルート基準で書きます。バックエンドのパスには「バックエンドの」と添えます。
- 表のセルの中でコードに縦棒（`|`）が含まれるときは、` \| ` とエスケープして書きます。エスケープした縦棒はコードの一部である `|` を表します。
- コードから確認できないことは「コードからは確認できない」と書きます。コードから読めるが実行して確かめていない動きは「コードからは〜と読める」と書きます。
